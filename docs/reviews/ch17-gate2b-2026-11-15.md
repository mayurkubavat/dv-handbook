## Blocking findings

### B1. `solver-selftest` passes with an unsound `cdcl.py`

`examples/ch17-logic-and-solvers/solver-selftest/selftest.py:40-53`,
chapter `chapters/ch17-logic-and-solvers.qmd:212` ("small enough to be wrong
in ways a reader would not see, so a separate example checks them").

Mutation: delete `cdcl/cdcl.py:77`
(`self.watches[false_lit] += watching[i + 1:]`), the classic watch-list bug
in which a conflict drops the watchers not yet visited. The mutant returns
SATISFIABLE for unsatisfiable formulas and models that violate clauses:

```
$ python3 fuzz_sat.py 3 1500        # reviewer's fuzzer, mutant on the path
BADMODEL (5, 5) RC 69 [...]
MISMATCH (11, 5) RC True False 81 342     # cdcl says SAT, CaDiCaL says UNSAT
MISMATCH (31, 1) RV True False 37 157
...
$ cd solver-selftest && python3 selftest.py          # same mutant
dpll.py, cdcl.py and cdcl_vsids.py agree with z3 on every one
921 satisfiable, each model checked clause by clause; 2079 unsatisfiable
```

Cause: the 3,000 formulas (at most 25 variables, clauses of 1 to 4 literals
drawn with repetition) are almost all settled by propagation. Measured with
the unmodified solver on the selftest's own stream:

```
max conflicts dpll/cdcl/vsids [8, 3, 3]
cdcl conflict histogram [(0, 2663), (1, 334), (2, 2), (3, 1)]
```

2,663 of 3,000 need no conflict at all and three need more than one, so
conflict analysis, learning, backjumping and watch repair after a conflict are
not exercised. The mutant is caught elsewhere only because `cdcl` and `hard`
pin conflict counts; `fifo-unroll` also still passes (different counts, none
pinned, see N1). An example whose stated purpose is to catch a wrong solver
passes with one.

Fix: add a second stream of threshold 3-SAT, 30 to 60 variables, 4.0 to 4.6
clauses per variable (and optionally `gen.pigeonhole(4..6)` and the miters).
Tried: 200 such formulas take 1.3 s for the two learning solvers and catch the
mutant on 121 of them, the first at trial 0. Print the largest conflict count
seen so the output shows the search was exercised.

### B2. "ABC ... writes eight variables and seventeen clauses: the same counts as the hand encoding" is contradicted by the file ABC writes

`chapters/ch17-logic-and-solvers.qmd:91`;
`examples/ch17-logic-and-solvers/tseitin-tools/run_tools.py:47-52,63`;
`tseitin-tools/run.out:5,7`; Makefile comment of the same example.

The example parses ABC's statistics line and never reads the file:

```
$ yosys-abc -c "read_aiger build/fa.aig; strash; print_stats; write_cnf build/x.cnf"
CNF stats: Vars =      8. Clauses =      17. Literals =       45.
$ head -2 build/fa_abc.cnf | tail -1
p cnf 8 18
$ grep -c ' 0$' build/x.cnf
18
```

Decoded by brute force over the 256 assignments:

```
18 clauses in file; 14 non-unit over vars [2, 3, 4, 5, 6, 7]; units [[-8], [2], [4], [-1]]
x3=x5^x6, x2=x7^x3, x4=maj(x5,x6,x7): True
models of whole file: [(0, 1, 0, 1, 1, 1, 1, 0)]
```

So ABC's file is 18 clauses, not 17. Fourteen define three nodes (two XORs of
four clauses, one majority of six) over six variables; the other four are
unit clauses: both outputs asserted (ABC's help says `write_cnf` "generates
CNF for the miter") and two variables that appear nowhere else. The file has
exactly one model, a = b = cin = 1: it is the *question* "can sum and cout
both be 1", not an encoding of the circuit. The prose's "the same counts as
the hand encoding and different clauses" and the output's "17 others from
abc" compare a 17-clause circuit encoding with a statistics line that matches
neither the file nor the same object. The example's Makefile comment
("8 variables, 17 clauses") repeats it.

Fix: read `build/fa_abc.cnf`, print its header, and report the split
(14 gate clauses over 6 variables, 4 units). Rewrite the sentence: ABC covers
the seven ANDs with three nodes and writes 14 clauses for them, fewer than the
hand encoding's 17, plus units for the outputs. The "factor of six" (17 to
100) can stay as hand against Yosys, both of which are stated.

### B3. The output's own closing sentence disagrees with its table and with the prose

`examples/ch17-logic-and-solvers/hard/run_hard.py:88-89` prints, hard-coded,
"the median cost peaks where about half the formulas are satisfiable"
(`hard/run.out:28`, spliced at `chapters/ch17-logic-and-solvers.qmd:258`, and
pinned as `EXPECT_OUTPUT` in `hard/Makefile`). The table above it:

```
   4.2      252      22 / 30                65      172
   4.6      276       6 / 30               109      254     <- the peak
   5.0      300       3 / 30                99      167
```

The peak row has 6 of 30 satisfiable. The prose at line 262 says so ("in the
row where a fifth of them are satisfiable"), three lines after the output
says "about half". One of the two printed sentences is wrong, and it is the
one that is not computed.

Fix: compute the line from the data, for example
`f"the median cost peaks at {ratio}, where {sat} of {RUNS} formulas are
satisfiable, just past the ratio where half are"`, and change `EXPECT_OUTPUT`
to a prefix of it.

## Non-blocking findings

N1. **Printed counts that prose quotes are not pinned.**
`fifo-unroll/run_unroll.py:18,22` asserts the bound, variables and clauses
but not the decisions and conflicts column; "195 conflicts" is quoted at
qmd:224, 266, 468 and in two figure descriptions. With the B1 mutant
`fifo-unroll` passes with other counts. Likewise `dpll/run_dpll.py` and
`cdcl/run_cdcl.py` print variables and clauses without asserting them
(removing the `g or not lit` clauses of `Cnf.or_all` in `common/tseitin.py`
leaves every example passing with different clause columns; "799 clauses
against 296" at qmd:246 would drift), and `hard/run_hard.py:67` pins only the
multiplier half of each row (`got[2:]`). Fix: assert
`(nvars, clauses) == (15 * n - 6, 45 * n - 19)` for the adder miter, pin the
per-bound conflicts of the FIFO, assert the whole row in `run_hard.py`.

N2. **`Cnf.or_all` is never tested as a definition.** `tseitin/encode.py`
checks `and_`, `or_`, `xor_` exhaustively through the full adder; `or_all`
is used only with its output asserted, where one direction suffices. Fix:
one exhaustive check of `or_all` over three inputs in `encode.py`.

N3. **`bitvector` "bits" column passes with a trivial miter.** Replacing
`multiply(cnf, b, a)` by `multiply(cnf, a, b)` in `gen.multiplier_miter`
leaves `bitvector/run.out` byte-identical (same sizes, still unsat). `hard`
catches it through pinned conflicts. Acceptable, worth a comment.

N4. **"five or more for each bit"** (qmd:414): the committed
`production/tbl-word.md` gives 31.07 / 6.25 = 4.97 for the last step, and
this review's run 29.78 / 6.16 = 4.83. Say "about five to eight".

N5. **"at most a hundred and fifty lines of Python each"** (qmd:26; also
"150-line solver" at 266 and the `cdcl` Makefile comment): `cdcl.py` is 169
lines by `wc -l`, 151 non-blank; the class itself is 126 non-blank lines.
Say which is counted, or "under 170".

N6. **`gen.py adderbug 1` is unsatisfiable.** `bug_at = n - 1 = 0` falls in
the half-adder branch of `majority`, which has no gate to break. The
docstring says "(sat)". Not used at N = 1 by any example. Guard or document.

N7. **`cdcl_vsids.py` activity overflows silently.** `bump /= 0.95` reaches
`inf` after about 13,837 conflicts (log(1.8e308)/log(1/0.95)); every bumped
activity is then `inf` and `pick` degenerates to the lowest-numbered such
variable. Still correct, and the largest count any example reaches is 7,786,
but exercise-style runs (8-bit multiplier, 8 holes under the fixed order)
can cross it. Fix: rescale activities and `bump` when `bump > 1e100`.

N8. **Tool-dependent numbers in `run.out` without a version.**
`counter-model` and `fifo-model` print InFormal's sizes (23/19 ANDs, 146
latches, 992 and 102 ANDs, 225 lines of Btor2) and `bitvector` prints z3's
`simplify` result, with no version line; `tseitin-tools` prints
"tool: Yosys 0.68" and is the model to follow. The chapter's promise at
qmd:26 covers "a production solver's numbers" only. The downstream numbers
(1,795 / 5,221 / 195) are safe because `fifo-unroll` reads the committed
`.aag`. Fix: print `informal --version` and `z3.get_version_string()`.

N9. **Implication figure omits lower-level causes without saying so.**
The definition at qmd:167 puts an edge from every other literal of a reason;
`figures/gen_ch17_figures.py` (`fig_implication`) draws level-1 nodes only
for the three literals of the learned clause. Reasons such as `(2 -5 9)`,
`(8 -9 10)` and `(35 36 37 38 -39)` have antecedents (a1, x8, x20, x35, x38,
x39) that are not drawn. Add "causes from earlier levels left of the cut are
not drawn" to the caption.

N10. **`make clean` leaves `common/__pycache__`** (no Makefile in `common/`;
the directory is ignored by git). Cosmetic.

N11. **A hung run, not a failed one, is what several solver mutations give**
(`cdcl.py` without unit assignment or without stored learned clauses:
`fifo-unroll` was still on bound 0 of the FIFO after 110 s). The checker has
no timeout. Not a false pass; noted for CI.

### 2. Correctness attacks (no wrong answer found)

- **SAT solvers.** 11,000 random CNFs (seeds 2026 and 7), 1 to 90 variables,
  six shapes: mixed lengths 1 to 4, threshold 3-SAT, unit/binary heavy,
  lengths 0 to 6 with empty clauses, duplicates, tautologies and unused
  variables, dense 2 to 5, and 40 to 90 variable threshold 3-SAT. `dpll.py`,
  `cdcl.py`, `cdcl_vsids.py` against CaDiCaL (python-sat): verdicts agree,
  every model satisfies every clause and assigns every variable. Structured:
  pigeonhole 1 to 6, adder miters 1 to 6 with and without the bug,
  multiplier miters 1 to 4, parity chains of 2 to 13 variables in two
  association orders (sat and unsat), 30 random XOR systems.
- **Learned clauses.** On every third random formula and all structured
  ones, up to 20 learned clauses per solver were checked: formula plus the
  negated clause is UNSAT under MiniSat in every case.
- **Command line.** `gen.py` + `dpll.py` / `cdcl.py` / `cdcl_vsids.py` on six
  DIMACS files agree with the CaDiCaL binary; `cdcl.py f.cnf 3` prints
  `s UNKNOWN`.
- **Tseitin encoder.** 400 random circuits of `and_`, `or_`, `xor_`,
  `or_all` over 1 to 6 inputs with random inversions: for every input row the
  clauses have exactly one model and it is the evaluated circuit; `cdcl.py`
  agrees on the output and on satisfiability.
- **Pitfall numbers** (qmd:83): re-derived by brute force, extra assignments
  per removed clause are 2 (sixteen times) and 4 (once), none matches a row,
  every input still has a model, and 5 of 17 removals flip the question.
- **ROBDD.** 1,500 managers, random orders of 1 to 7 variables, 28,423
  functions built by random `apply`: truth table correct, one node per
  function (canonical), reduced and ordered, `size` equal to a brute-force
  count of distinct subfunctions, `count` equal to the number of ones.
  The chapter's tables re-derived from truth tables without `robdd.py`:
  carry 3N - 1 and 2^(N+1) - 2 for N = 1 to 10; product bit N - 1 under the
  three orders for N = 2 to 10, all 27 numbers equal (5,246 / 8,012 / 6,002
  at 10).
- **AIG.** 2,000 random graphs: `Aig` parses what was written, `evaluate`
  is right, `strash` preserves every output and leaves no two gates with the
  same input pair.
- **Unroller.** 1,500 random sequential AIGER models (0 to 2 inputs, 1 to 4
  latches with reset 0, 1, uninitialized or absent, 0 or 1 constraint):
  first satisfiable bound from `bmc_aag.bmc` equals the depth found by
  explicit-state search in every case (823 at 0, 92 at 1, 15 at 2, 1 at 3,
  569 never).
