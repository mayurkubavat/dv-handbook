# Chapter 3 gate-2 re-review

Scope: the fourth pass. The new contract in `tools/dvh/clocks.py`
(`shape_recognized` as a fact, `CHECK` rather than `BUG`, nothing
suppressed, an unresolved clock reported as undecided), then every sentence
in @sec-ch03-example that makes a claim about the code, then the residue
listed as non-blocking in `docs/reviews/ch03-gate2-2026-09-09.md`, then the
research note's seven constraints and the house rules.

Method. Every claim about the code was tested by running the code on
designs written for this review. `tools/dvh/tests/rtl/` was read but not
relied on; the two designs from the previous review that are still relevant
(`indep_errs.sv`, `two_src_domains.sv`, `one_gate_only.sv`) were re-run to
settle residue and are marked as such. Every design below is reproduced in
full so it can be re-run. Tools: Yosys 0.68+post, Verilator 5.030, the
`dvbook` conda environment.

Baseline, verified before anything else and again after: `pytest
tools/dvh/tests/test_ch03.py` passes, 22 tests; `scripts/check-examples.sh
ch03` reports `pass=3 fail=0`. Both stay green through every failure below.

One procedural note. `tools/dvh/graph.py`,
`tools/dvh/tests/test_ch03.py` and `tools/dvh/schema/crossings.schema.json`
were edited by other work in progress while this review was running. Every
finding below was re-verified against the tree as of the end of the review;

## 1. Blocking

### 1.1 Crossings are still silenced, and three ordinary designs do it

`tools/dvh/clocks.py:306` gives a register's domain the name
`"+".join(clock_sources)`, and `:315-317` decides whether a path is a
crossing by comparing those **names**:

```python
theirs = dom_of.get(src, "unresolved clock")
if theirs == mine:
    continue
```

Two clock networks that are physically different but resolve to the same
set of source names therefore become one domain, and every crossing between
them is dropped before any of the report-it-loudly machinery below runs.
Nothing in the report says a comparison was made. This is the failure mode
of the rule the fourth pass deleted — identity by name — relocated to the
line that has always been there.

Three designs, none exotic:

```systemverilog
// glitchless.sv -- the ordinary glitch-free clock multiplexer, one per
// block, both drawing on the same two asynchronous sources. Block X runs on
// clk_a while block Y runs on clk_b, and rx -> ry is a real crossing.
module glitchless (input logic clk_a, clk_b, sel, rst_n, d,
                   output logic q);
  logic ck_x, ck_y, rx, ry;
  assign ck_x = (clk_a & sel) | (clk_b & ~sel);
  assign ck_y = (clk_a & ~sel) | (clk_b & sel);
  always_ff @(posedge ck_x or negedge rst_n)
    if (!rst_n) rx <= 1'b0; else rx <= d;
  always_ff @(posedge ck_y or negedge rst_n)
    if (!rst_n) ry <= 1'b0; else ry <= rx;
  assign q = ry;
endmodule
```

```
clock domains: 1
  clk_a+clk_b+sel: 2 registers
registers without reset: 0
crossings: 0, shape not recognized: 0
```

Exit 0. `dvh clock-tree` on the same design reports
`"clock_ambiguous": true` for both registers: the walk knows it could not
tell the clocks apart, and the crossing that would have carried that
sentence to the reader was discarded one line earlier. A `$mux`-shaped
clock mux does the same thing (`ck_x = sel ? clk_a : clk_b`,
`ck_y = sel ? clk_b : clk_a`: `crossings: 0`, exit 0), and so does a
design where one register is clocked straight from `clk_a`, which supplies
the strong evidence that collapses both mux outputs onto the single name
`clk_a` — there the ambiguity marker is not even set.

A gated variant needs no multiplexer at all. Give the walk one register
clocked by a strobe that is also used as a clock-gate enable, and the
strobe becomes the strongest evidence at both gates:

```systemverilog
// en_strong.sv -- a strobe used both as the clock of a small block and as
// the enable of two clock gates on two asynchronous clocks.
module en_strong (input logic clk_a, clk_b, en, rst_n, d,
                  output logic q, output logic q_e);
  logic g_a, g_b, re, ra, rb;
  assign g_a = clk_a & en;
  assign g_b = clk_b & en;
  always_ff @(posedge en or negedge rst_n)
    if (!rst_n) re <= 1'b0; else re <= d;
  always_ff @(posedge g_a or negedge rst_n)
    if (!rst_n) ra <= 1'b0; else ra <= d;
  always_ff @(posedge g_b or negedge rst_n)
    if (!rst_n) rb <= 1'b0; else rb <= ra;
  assign q = rb; assign q_e = re;
endmodule
```

```
clock domains: 1
  en: 3 registers
crossings: 0, shape not recognized: 0
```

Exit 0, on an unsynchronized crossing between two asynchronous clocks.

This falsifies three printed sentences.
`chapters/ch03-digital-design-for-verifiers.qmd:242` — "It reports the
crossing and says the clock could not be told from the enable, rather than
suppressing it" — is false for `glitchless.sv`, where the walk *did* record
that it could not tell and the crossing was suppressed anyway. The listing
at `:244` prints `clocks.py:301` ("Nothing is ever suppressed, and where
the walk cannot resolve a clock it says so") and `clocks.py:323-325`
("Nothing is suppressed here now"), both of which are false on the same
design. And `:63` tells the reader that "a multiplexed clock can hand the
same node the timing of either input, so it may genuinely create a new
domain", in a chapter whose tool quietly decides that two opposite outputs
of two such multiplexers are one domain.

**Fix.** Stop using the domain *name* as the domain's identity. Give each
register a comparison key alongside the printable name: the single resolved
clock source when `len(clock_sources) == 1` and `clock_ambiguous` is false,
and otherwise a key unique to that register's clock net, carrying
`undecided`. Skip a pair only when both keys are of the resolved kind and
equal; report every pair in which either key is undecided, with the
existing "declare the clocks" note. On the book's own two-clock design
every register has a single unambiguous source, so the report typeset at
`:257` does not change; `gated_clock.sv` still gives one domain.

### 1.2 `shape_recognized: true` on two flops that are never on the same clock

Same root cause, worse consequence. `clocks.py:330-332` finds the second
stage by comparing domain *names* as well:

```python
second_stage = [n for n, c in by_name.items()
                if dom_of[n] == mine and n != name
                and _feeds_directly(mod, c, name)]
```

so two flops on provably different clocks satisfy "a second register in
its own domain":

```systemverilog
// falsesync.sv -- "two-flop synchronizer" whose two flops are on opposite
// clocks. Both clock multiplexers draw on clk_a and clk_b, so both
// registers carry the same domain name, and one register clocked straight
// from clk_a gives the walk the strong evidence to name that domain clk_a.
module falsesync (input  logic clk_a, clk_b, clk_c, sel, rst_n, d,
                  output logic q, output logic q_a);
  logic ck_x, ck_y, ra, sc, m1, m2;
  assign ck_x = sel ? clk_a : clk_b;
  assign ck_y = sel ? clk_b : clk_a;
  always_ff @(posedge clk_a or negedge rst_n)
    if (!rst_n) ra <= 1'b0; else ra <= d;
  always_ff @(posedge clk_c or negedge rst_n)
    if (!rst_n) sc <= 1'b0; else sc <= d;
  always_ff @(posedge ck_x or negedge rst_n)
    if (!rst_n) m1 <= 1'b0; else m1 <= sc;
  always_ff @(posedge ck_y or negedge rst_n)
    if (!rst_n) m2 <= 1'b0; else m2 <= m1;
  assign q = m2; assign q_a = ra;
endmodule
```

```
crossings: 1, shape not recognized: 0
  known sc (clk_c) -> m1 (clk_a), 1 bit, two-flop synchronizer
```

Exit 0. `m1` runs on `ck_x` and `m2` on `ck_y`, which are the two opposite
outputs of two clock multiplexers: whatever `sel` is, they are different
clocks. The structure is not a synchronizer in any reading, and the tool
states that it is, as a fact, in the field the redesign created for facts.
This is the direct answer to the question the re-review was asked to
settle: yes, `shape_recognized: true` can be produced for a receiving
structure that is not a two-flop synchronizer.

**Fix.** The same key as §1.1, used here too: require the second stage to
share the sending register's *key*, not its printed domain name, and treat
an undecided key as disqualifying (which `unsure` at `clocks.py:334`
already does for the ambiguous case, and would then also do for the
resolved-by-strong-evidence case that defeats it above).

### 1.3 A multi-bit value on per-bit synchronizers, read together, reported as two recognized shapes

`clocks.py:245` indexes the convergence rule's crossings by second-stage
register name:

```python
stages[n] = c
```

When two crossings name the same second-stage register — which is what
happens when the two second stages are two bits of one declared register —
the dict keeps one of them, `together` counts one, and the rule does not
fire:

```systemverilog
// bus2.sv -- a two-bit value crossing on two one-bit synchronizer chains
// whose second stages are the two bits of one declared register, read
// downstream as one value.
module bus2 (input  logic aclk, arst_n, bclk, brst_n,
             input  logic [1:0] d,
             output logic [1:0] q);
  logic [1:0] src;                 // sender, aclk
  logic       s1a, s1b;            // first stages, bclk
  logic [1:0] s2;                  // both second stages in one register
  logic [1:0] use_q;
  always_ff @(posedge aclk or negedge arst_n)
    if (!arst_n) src <= 2'b00; else src <= d;
  always_ff @(posedge bclk or negedge brst_n)
    if (!brst_n) s1a <= 1'b0; else s1a <= src[0];
  always_ff @(posedge bclk or negedge brst_n)
    if (!brst_n) s1b <= 1'b0; else s1b <= src[1];
  always_ff @(posedge bclk or negedge brst_n)
    if (!brst_n) s2 <= 2'b00; else s2 <= {s1b, s1a};
  always_ff @(posedge bclk or negedge brst_n)
    if (!brst_n) use_q <= 2'b00; else use_q <= s2 + 2'b01;
  assign q = use_q;
endmodule
```

```
crossings: 2, shape not recognized: 0
  known src (aclk) -> s1a (bclk), 1 bit, two-flop synchronizer
  known src (aclk) -> s1b (bclk), 1 bit, two-flop synchronizer
```

Exit 0. The two bits of one value cross on two independently resolving
chains and are read together by `use_q`; the walks see all of it — the
data cone of `use_q` is `{s2}`, of `s2` is `{s1a, s1b}` — and the rule
misses it on a dictionary write. `:253` states the criterion the tool fails
to apply here ("two or more of them that one register downstream reads
*together*"), and `crossings`' own docstring at `clocks.py:296-302` defines
`shape_recognized: true` as "matches a two-flop synchronizer **and is not
one of several such paths carrying one value**", which makes each of these
two lines a false statement of the fact as the tool itself defines it.

This is the previous review's §2.6 first bullet, filed as "harmless today;
a dict of lists would be safer". It is not harmless.

**Fix.** `stages.setdefault(n, []).append(c)`, and count distinct crossing
objects: `together = {id(c) for n in ancestors(name) if n in stages for c in
stages[n]}`. A crossing whose second stage is also another crossing's
second stage is by itself the tell, so the fix could be that direct.

### 1.4 A synchronous reset is reported as no reset at all

`design.py:86-89` builds the Yosys script as `hierarchy; proc; flatten;
opt_clean`. After `proc` alone Yosys does not infer `$sdff`: a synchronous
reset stays a `$mux` in front of a plain `$dff`. `$sdff` appears only once
`opt_dff` has run — checked directly:

```
srst.sv, proc; flatten; opt_clean   ->  1 $dff  + 1 $mux
srst.sv, ... ; opt_dff              ->  1 $sdff + 1 $mux
```

So `SYNC_RESET_TYPES` (`design.py:30`) is unreachable, the synchronous
branch of the reset walk (`clocks.py:194-196`) is dead code, and every
synchronously reset register in any design is reported as having no reset:

```systemverilog
// srst.sv -- synchronous reset, the common style in modern RTL.
module srst (input logic clk, rst, d, output logic q);
  logic r;
  always_ff @(posedge clk)
    if (rst) r <= 1'b0; else r <= d;
  assign q = r;
endmodule
```

```
{ "registers": {}, "no_reset": [ { "name": "q", ... } ] }
```

`:236` — "The register cell types are the ones Yosys emits after `proc` and
before technology mapping, and the split between them is what lets the
reset walk report a kind and a polarity rather than a guess" — is false for
half of the split. The chapter's own report line `registers without reset:
N` is the finding a reader is told to act on (`:262`), and on a
synchronous-reset design it lists every register in the block.

**Fix.** Add `opt_dff;` after `proc;` in `design.py`. One consequence must
be handled in the same pass: `opt_dff` also infers `$adffe`/`$sdffe`, which
puts an enabled flop's data on `D` instead of behind a mux, and the shape
test at `clocks.py:336` would then accept an *enabled* first stage as a
two-flop synchronizer. Today `en_first.sv` (`if (sample) m1 <= sa;` in the
first stage) correctly reports `CHECK`, and it does so only because the
enable is still a mux. So: add `opt_dff`, and require the receiving and
second-stage flops to have no `EN` connection before `shape_recognized` can
be true. Then re-check `en_first.sv` still reports `CHECK`.

### 1.5 The `SYNCASYNCNET` claim contradicts its own evidence and the chapter's own §Lint

`chapters/ch03-digital-design-for-verifiers.qmd:222`:

> ... and additionally turning on `SYNCASYNCNET`, which is off by default
> and is the one warning in the list whose description mentions clock
> domains at all.

The evidence record says otherwise. `research/ch03-digital-design-for-verifiers.md:344`
quotes `MULTIDRIVEN`'s description, which does mention it — "causing clock
domain crossing or timing bugs" — and `:346` quotes `SYNCASYNCNET`'s, which
does not mention clock domains at all: "Warns that the specified net is
used in at least two different always statements with posedge/negedges ...
Mixing sync and async resets is usually a mistake." `CDCRSTLOGIC`'s
description mentions crossings too (note `:408-411`). The chapter's own
`:198` gets this right — "Two warnings, `MULTIDRIVEN` and `SYNCASYNCNET`,
mention crossings as a possible consequence of a local pattern" — so `:222`
also contradicts a paragraph twenty lines above it. The same sentence is
repeated in `examples/ch03-digital-design/sv-lint/Makefile:11-12`.

This is a claim about a tool, which AGENTS.md requires to be sourced, and
the source contradicts it.

**Fix.** Say what is true and what the example actually does: `-Wall` plus
`-Wwarn-SYNCASYNCNET`, the one *off-by-default* warning in the list that
touches reset and clocking style at all, on top of `MULTIDRIVEN`, which is
on by default and is the one whose description names clock domain crossing.
Correct the Makefile comment in the same edit.

## 2. Non-blocking

### 2.1 The convergence rule's false positives remain, and the demotion is a judgement

Re-run of the previous review's §2.1: `indep_errs.sv` (two independent
sticky error flags, each correctly synchronized, OR-ed into one status
flop) and `two_src_domains.sv` (the same shape with the two senders in two
*different* domains) each still report two findings, "2 one-bit
synchronizers are read together by ...", exit 1.

The contract change makes this worse rather than better on one point. The
docstring defines `shape_recognized: true` as a two-flop synchronizer that
"is not one of several such paths carrying one value". In `indep_errs.sv`
the two paths do not carry one value, so `shape_recognized: false` is a
false statement of the fact as defined — and it is false in the direction
that fails a build. The `note` is honest about what was actually observed
("read together by `any_err`"), which is what keeps this non-blocking; the
boolean is not. Requiring a shared `from_domain` before demoting would
remove `two_src_domains` outright and narrow the rest, as the previous
review proposed; that suggestion is unimplemented.

### 2.2 `two_clock_gates.sv` now contradicts its own header and the chapter's list

`tools/dvh/tests/rtl/two_clock_gates.sv:1-6` states the intended
behaviour: "one clock, two gates ... the path between them is the same
clock gated two ways, not a crossing, **and must not be reported as one**."
It is now reported as one:

```
crossings: 1, shape not recognized: 1
  CHECK q1 (clk+en1) -> q2 (clk+en2), 1 bit, clock and enable not
  distinguishable here; declare the clocks
```

Exit 1 on a single-clock design. Under the new contract that report is
defensible — the walk genuinely cannot tell — but two things now say
otherwise: the fixture header, and `:287`, which lists "two gates on one
clock reported as a crossing between them" among the designs "an earlier
version of these tools got wrong", implying it is now right. **Fix.**
Rewrite the fixture header to state what the test asserts, and move that
item out of the `:287` list into the ambiguity paragraph at `:240-242`,
where a non-zero exit on a fully gated single-clock block belongs.

### 2.3 `:287` still refers to the tests by position, and the position is still wrong

"The last several tests are there for a different reason." The last tests
in `test_ch03.py` are `test_a_shared_clock_enable_does_not_hide_a_crossing`
and `test_convergence_is_followed_through_a_third_flop`; the four schema
and source-location tests sit between them and the fixture block. The
sentence then lists seven designs, while nine files exist in
`tests/rtl/` — `shared_enable_clocks.sv` and `three_flop_per_bit.sv` are
the two the list omits, and they are precisely the two at the end.
Residual of the previous review's §4.3. **Fix.** Name the block, not the
position, and add the two designs: "The tests under *Limits the tools were
once wrong about*, and the two that close the file, are there for a
different reason."

### 2.4 A divided clock still produces a finding on a synchronous path

`div2.sv` (divide-by-two, `q_slow <= q_fast`) reports `CHECK fast (clk) ->
q (div), 1 bit, no synchronizer shape`, exit 1. Under the new contract the
sentence is true — the shape genuinely is not recognized — so this is much
smaller than it was. What remains is that `:262` and `:290` propose gating
a build and a commit on the exit code, and any design with a clock divider
fails that gate permanently with nothing to fix. One sentence in the
Future Directions box naming derived clocks (dividers, muxes, black-box
outputs) as a standing source of findings that are not bugs would close it.

### 2.5 `$dffsr` resets are still reported as constants

Unchanged from the previous review's §2.3. `clocks.py:190` picks
`"ARST" if "ARST" in cell.conns else "CLR"` and never looks at `SET`, and
the reset walk skips a multiplexer's select, where a `$dffsr`'s real reset
sources sit:

```systemverilog
module setreset (input logic clk, rst_n, set, d, output logic q);
  logic r;
  always_ff @(posedge clk or negedge rst_n or posedge set)
    if (!rst_n)   r <= 1'b0;
    else if (set) r <= 1'b1;
    else          r <= d;
  assign q = r;
endmodule
```

```
"q": { "kind": "asynchronous", "active": "high",
       "sources": ["const 0", "const 1"], "through": ["$mux", "mux"] }
```

Neither `rst_n` nor `set` appears; the report states that the register is
asynchronously reset by constants, which is false. Kept non-blocking on the
same grounds as before — no chapter sentence asserts otherwise — but it is
a false statement of fact in a report the chapter presents as facts, and
`:236` sits close to it. **Fix.** Detect `$dffsr`/`$dffsre` in
`reset_tree` and record the kind as unclassified with a reason, rather than
a source list the walk did not establish.

### 2.6 A tool crash and a finding still exit the same way

`design.py:90` runs Yosys with `check=True, capture_output=True`. A bad top
name raises `CalledProcessError`, prints a Python traceback, discards
Yosys's own diagnostics, and exits 1 — the same code `read` uses for
"shape not recognized". Verified: `dvh read nosuchtop file.sv` exits 1 with
a traceback. **Fix.** Catch it in `cli.main`, print the captured stderr,
exit 2, which `_emit` already uses for a schema failure.

### 2.7 The ambiguity marker reaches the report only when there is a crossing

Partly fixed. `cli._report` now prints `c["note"]`, so
`shared_enable_clocks.sv` does print "clock and enable not distinguishable
here; declare the clocks" — the previous review's §2.4 case is closed for
any design that has a reported crossing. It is still silent when there is
none: `one_gate_only.sv` prints `clk+en: 2 registers` and nothing else,
and `glitchless.sv` in §1.1 above is the case where that silence is
actively harmful. One line per ambiguous domain in `_report` would cover
both.

### 2.8 The tool does not finish on a small storage array

Yosys expands even a 256-entry array into flip-flops with this script, so
nothing is missed structurally — but the walks re-derive every cone from
scratch (`_data_cone_registers` and `_tier` both call `_walk_to_sources`
with a fresh `seen`), and the cost is roughly quadratic in register count:

| array entries | `dvh crossings` wall time |
|---|---|
| 8 | 3.2 s |
| 16 | 5.2 s |
| 32 | 11.2 s |
| 256 | did not finish in 120 s |

A 256×32 FIFO is a small block. `:290` proposes deriving these artifacts
"on every commit", and the limits paragraph at `:292` says the limits "are
structural rather than temporary" — runtime is a limit it does not name.
Memoizing `_walk_to_sources` per (bit, mode) would fix the cost; a sentence
naming the cost would at least make the claim honest.

### 2.9 Smaller observations

- `test_ch03.py:120`, the pinned report line, was 84 columns against the
  80-column house rule when this review began, and was **fixed by other
  work in progress during the review**. No file spliced into the chapter is
  now over 80 columns.
- Comment rulers are still 76 columns at `test_ch03.py:127`, `:130`,
  `:230`, `:233`, in a file spliced at `:282`; the house rule is 72.
  Residual of the previous review's §4.2, third time raised.
- `test_ch03.py:197` reads "the only safe **behaviour**", in the same
  spliced file, against the American-spelling rule. `graph.py`'s
  "parameterised" is fixed; this one is new to this pass.
- `clocks.py:315` computes `theirs = dom_of.get(src, "unresolved clock")`
  for a source that is not in the domain map, and `:339` then writes
  `"from_domain": dom_of[src]`, which would raise `KeyError` on exactly
  that case. The default is unreachable today (both dicts are built from
  `registers()`), so this is dead code that describes a behaviour the tool
  does not have — and the comment at `:313-314` presents it as the
  mechanism by which an unresolved clock is reported, which it is not. The
  real mechanism is `clock_ambiguous`/`unsure`. Delete the default or make
  both lines use `theirs`.
- A crossing whose destination is a **latch** is never reported. Registers
  are the only destinations, so in `latch_dest.sv` (`always_latch if (hold)
  l = sa;` with `l` leaving through a port) only the path that continues
  into a flop is reported. The previous review noted this; it is unchanged
  and correctly not claimed anywhere in the chapter.
- A two-flop synchronizer whose **first stage also feeds other logic** in
  the destination domain still reports `known` (`meta_fanout.sv`: `m1`
  feeds both `m2` and an unrelated flop, exit 0). The possibly metastable
  node is consumed directly, which is a real and common bug. The receiving
  path does match the shape, so the statement is not false; this is the
  ceiling the chapter describes at `:268`--`:272`, and it is worth one concrete
  sentence there because it is the most likely way a reader's own design
  will get a `known` it should not trust.
- Per-bit synchronizers whose outputs **leave through ports** with no
  downstream register in the module are reported `known` (`perbit_out.sv`,
  exit 0). Consistent with the criterion as stated at `:253`; worth
  knowing that the convergence rule is only as wide as the flattened top.
- `:280` says "The report is included verbatim in this book, so its exact
  text is part of the tool's contract, ordering included. The test suite
  pins it." The test pins the report produced with the working directory at
  the repository root
  (`examples/ch03-digital-design/rtl/datapath.sv:24`), while the `run.out`
  typeset at `:257` is produced in the example directory
  (`../rtl/datapath.sv:24`). The pinned string is not the printed string.
  Either say so, or pin `run.out` itself.
- Register names in the report are net aliases, not always the declared
  register: in `muxdom.sv` the register `ry` is reported as `q` because
  `assign q = ry;` gives the bit two names and the port's wins. Harmless
  for the book's own design; worth a line in the schema's `to`/`from`
  descriptions ("the net the register drives, which may be a port name").
- `crossings.schema.json` still describes `src` only as "Source location";
  it is the *receiving* register's location (`clocks.py:346`). Previous
  review's §2.6, unchanged.

## 5. Verdict

**blocking findings remain**

1. **§1.1** — `clocks.py:316` compares domain *names*, so a glitch-free
   clock multiplexer per block (`glitchless.sv`), a `$mux` clock
   multiplexer (`muxdom.sv`), and a strobe used as both a clock and a gate
   enable (`en_strong.sv`) each report `crossings: 0` and exit 0 on a real
   unsynchronized crossing between asynchronous clocks. `:242`,
   `clocks.py:301` and `clocks.py:323-325` all state the opposite in
   print.
2. **§1.2** — the same comparison at `clocks.py:330-332` reports
   `shape_recognized: true`, "two-flop synchronizer", for two flops that
   are never on the same clock (`falsesync.sv`).
3. **§1.3** — `clocks.py:245` loses one of two crossings that share a
   second-stage register, so a two-bit value on two per-bit synchronizers,
   read together by one register, reports two recognized shapes and exits 0
   (`bus2.sv`). Contradicts `:253` and the docstring's own definition.
4. **§1.4** — `design.py:86-89` never runs `opt_dff`, so `$sdff` never
   appears, `SYNC_RESET_TYPES` is dead, and every synchronously reset
   register is reported as having no reset (`srst.sv`). Contradicts `:236`.
5. **§1.5** — `:222` says `SYNCASYNCNET` is the one warning whose
   description mentions clock domains; the evidence record says
   `MULTIDRIVEN`'s does and `SYNCASYNCNET`'s does not, and `:198` says so
   too.

**The contract was defeated on both of its central claims.** "Nothing is
ever suppressed" is false (§1.1). "`shape_recognized` is a fact, not a
judgement" is false twice: once because the fact is asserted of a structure
that does not have it (§1.2), once because the mechanism that qualifies it
loses half its input (§1.3). Findings 1 and 2 share one root cause, and it
is the root cause the fourth pass thought it had removed: **a clock domain
is identified by the string of its source names.** Deleting the
shared-token rule removed one consequence of that choice and left the
choice in place, which is why the same failure has now appeared for the
third review running in the third different line of code.

STATUS.md's stopping rule for this chapter — "another defect of the same
class in `clocks.py` means the design change failed — escalate rather than
patch a fifth time" — is therefore met. My recommendation is to escalate
the one design question rather than take a fifth patch: *what identifies a
clock domain, and what does the tool do when it cannot identify one?* The
key-plus-undecided scheme in §1.1 is one answer and it fixes §1.1 and §1.2
together, leaves the chapter's printed report unchanged, and is a smaller
change than the fourth pass was. §1.3 and §1.4 are independent and
ordinary bugs with one-line fixes, and §1.5 is a sentence.

The rest of the chapter is in good order and better than it was. The latch
sentence, the shared-enable suppression, the chain-following convergence
rule, the IEEE clause and the `IMPERFECTSCH` claim are all genuinely fixed,
the reframing from verdict to shape is the right design and reads well, the
constraint table is clean, the template and callout rules hold, the
examples run, and the argument at `:268`--`:272` about a structural recognizer
judging shape rather than intent is the strongest passage in the chapter.
It remains truer of the tool than the sentences around it admit.
