## Blocking findings

### B1. Block E of `ag` gives the wrong reason for the circular trap, and the detector it teaches misses the same trap without a reset

`chapters/ch19-formal-techniques.qmd:605` (last four sentences),
`:701` (from "It is sound because" to the end of the paragraph);
`examples/ch19-formal-techniques/ag/ag.tcl:67-83`.

Block E itself is right: with both resets at 1, `x == 0` alone is
refuted at depth 1, each lemma is `proven` with the other assumed, and
`C_run` is unreachable in both. The cover is unreachable for a true
reason: the ring holds 1 in both registers in every cycle, so the
assumption contradicts every reachable state. Probes on the same design
(`informal-kind`, 5 s):

```
assumption (on ag_top, RST1 = 1)                 L_A x==0  covers
y == 0                                           proven    cover 1, rst_n, !rst_n: all unreachable
disable iff (!rst_n) y == 0                      proven    C_run unreachable
rst_n && $past(rst_n) |-> y == 0  (and the       proven    C_run, C_run3 unreachable
  assertion guarded the same way)
RST1 = 0, y == 0                                 proven    C_run covered, depth 2 (true lemma)
```

The chapter explains the trap by the reset: "the tool applies the
assumption in every cycle, the first cycle after reset included, where
it contradicts the reset value" (`:605`), and at `:701` it gives the
same clause as the reason why lemmas about one design differ from the
blocks proved alone. That is not the mechanism. An assumption that is
off during reset and for the cycle after it (rows 2 and 3) leaves both
lemmas just as vacuously proven. The mechanism is that the assumption
names state of the design under proof, so it removes every trace in
the cycle where the other lemma fails, and when both lemmas fail in
the same cycle for a common cause, each removes the other's
counterexample. A reset value of 1 is one common cause; a shared input
is another, and there the witness cover the chapter points at does not
help.

Measured on a ring I built: the `ag` blocks with resets at 0 and a free
input `g` ORed into both registers (`out <= in | g`), so `x` and `y`
both rise one cycle after `g`:

```
g_top, resets 0, shared free g          L_A        C_run       C_run9 (rst_n ##8 1)   C_g (g ##1 1)
x == 0 alone                            cex d2     covered d2
x == 0, assume y == 0                   proven     covered d2  covered d9             unreachable
y == 0, assume x == 0                   proven     covered d2  covered d9             unreachable
gblk alone, assume in == 0 (block A)    cex d2     covered d2
```

Two false lemmas are each `proven` with the other assumed, the cover
block E uses (`C_run`) is reached, as deep as one likes, and only a
cover of the specific cause (`g ##1 1`) is unreachable, which a reader
would write only after suspecting the trap. Proved alone, as block A
does, the block's lemma is refuted. So the chapter's rule (prove each
block alone, keep the proof graph acyclic, `:595`, `:701`) is the real
protection and is stated correctly; but the closing sentences of `:605`
and `:701` ("Only the witness cover, unreachable in both runs, says so";
"only their witness covers, both unreachable, show it") and the reset
clause teach a reader that the trap is a reset artifact that a witness
cover catches. That is the kind of false comfort the round-2 blocking
finding C-B1 was raised to remove.

Fix (text only, no new run needed; the measurements above can be added
as a third E run if wanted):
1. `:605`, replace "the tool applies the assumption in every cycle, the
   first cycle after reset included, where it contradicts the reset
   value, and no trace is left at all. Only the witness cover,
   unreachable in both runs, says so." with: each assumption names a
   register of the design under proof, so it removes every trace in the
   cycle where the other lemma fails; here both fail in every cycle,
   from reset on, so no trace is left and the witness cover is
   unreachable. Then: "When the two fail together for another cause, a
   shared input for instance, traces survive, the witness cover is
   reached, and only the proof graph shows the circle."
2. `:701`, replace "and the tool applies an assumption in every cycle,
   the first cycle after reset included" with "and an assumption on
   that state removes a trace in the very cycle where the other lemma
   fails", and replace the closing "and only their witness covers, both
   unreachable, show it" with "here their witness covers happen to be
   unreachable; a common cause other than reset leaves them reached, so
   the check is the proof graph, not the cover."

### B2. The witness-cover rule fixed in round 2 covers the assumption's window but not the assertion's own: a single-cycle assumption gives `proven` beside a covered antecedent

`chapters/ch19-formal-techniques.qmd:62` (third and fourth sentences),
`:770` ("Under an assumption whose window spans several cycles, a cover
of the antecedent alone is not enough on this tool: the cover must run
to the end of the window"), `:776` and `:793` (assumption sanity: "a
witness cover for each assertion").

Round 2 (D-B1) extended the witness cover through the window of a
multi-cycle *assumption*. The chapter now states the rule as: the
cover is the antecedent, or a scenario through it, and only under a
multi-cycle assumption must it run longer. That leaves the other half
of the same hole open, and it is not specific to this tool: a cover of
the antecedent ends in the antecedent's cycle, so it says nothing about
the cycles where a `|=>` or `##N` consequent is judged. Any assumption,
of one cycle, that removes every trace in the cycle after the
antecedent makes the implication `proven` while the antecedent cover is
`covered`. Measured on the previous chapter's handshake, no cut,
`informal-kind`, 10 s:

```
assumption        a_next {req && !busy |=> gnt}   c_ante {req && !busy}   c_ante1 {req && !busy ##1 1}
none              cex, depth 2                    covered, depth 1
!busy             PROVEN                          covered, depth 1        unreachable
```

`!busy` is a one-cycle assumption, so the chapter's rule as written
requires only `c_ante`, which is reached. No shipped proof is vacuous
for this reason (every `|=>` or `##N` implication proved under an
assumption has a cover in its session whose trace runs past the
consequent, except `a_gnt_once` in `cut-timer` D, whose only cover,
`c_gnt`, ends in the grant's cycle; I ran `cover {gnt ##1 1}` under D's
cut and `m_gap`: covered at depth 5, so D is not vacuous either), so
this is a defect in the rule the chapter teaches, the same defect D-B1
was, found on the other side of the implication.

Fix (text only):
1. `:62`: "The cover is the implication's antecedent, or a scenario
   whose trace passes through it, and under an assumption whose window
   spans several cycles it runs to the end of that window" becomes: the
   cover is a scenario that passes through the antecedent and runs to
   the last cycle the consequent can be judged in, and, under a
   multi-cycle assumption, to the end of that assumption's window as
   well (`antecedent ##N 1`, N the longer of the two); for a `|->` with
   a same-cycle consequent that is the antecedent itself.
2. `:770`: the same clause; the round-2 sentence keeps its reference to
   @sec-ch19-timer for the assumption half.
3. Optional: `cut-timer` session D, `cover -name c_gnt1 {gnt ##1 1}`
   beside `c_gnt` (depth 5 measured), so that the shipped example meets
   the corrected rule literally.

`chapters/ch19-formal-techniques.qmd:776-793`, `sanity/sanity.tcl:11`.
