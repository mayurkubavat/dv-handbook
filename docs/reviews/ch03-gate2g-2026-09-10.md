**Verdict: blocking findings remain.**

Headline, answering questions (1) and (2) at once:

* **A clock blended with a *divided* clock is reported as "one clock gated
  differently" and the build gate passes on an eight-bit unsynchronized
  crossing between two unrelated clocks — exit 0, and exit 0 again when both
  clocks are declared with `--clock`.** §1.1. This is `gate2f` §1.1's
  mechanism surviving its fix. The fix made a demoted *clock candidate* set
  `clock_ambiguous`; a derived clock is not in either candidate tier, so it is
  demoted silently exactly as before.
* **Two one-bit synchronizers carrying one two-bit value across one clock
  boundary are both reported `known ... two-flop synchronizer`, exit 0**, when
  one of the two sending flops sits behind a clock gate whose enable the
  netlist cannot see into. §1.2. This is the fourth distinct route past the
  per-bit check, and the third review in a row to find one.

## 1. Blocking

### 1.1 A clock blended with a divided clock is excused from the gate, declared or not

`clock_candidates` (`tools/dvh/clocks.py:47-86`) builds two tiers of evidence.
**Strong** is a port that drives some register's `CLK` pin with no logic in
between (`:76-81`), or a register whose `Q` bits are *themselves* one of those
`CLK` bits (`:82-84`). **Weak** is any input port (`:85`). `_tier`
(`:89-94`) adds a third strong case, `kind == "unknown"`.

A divided clock that feeds a *gate* rather than a `CLK` pin directly matches
none of them. Its `Q` bit is not in `used_as_clock`, so `:82-84` never adds it;
it is not an input port, so it is not weak; its `Source.kind` is `"register"`,
so `_tier` returns **0**. At the gate, `_walk_to_sources`
(`clocks.py:165-180`) keeps only the best tier, records the rest as
`gated by ...`, and sets `ambiguous` from `any(t >= 1 ...)` (`:178-179`) — which
a tier of 0 does not satisfy. The demotion is therefore silent, and
`same_clock_source` (`clocks.py:559-565`) sees one shared root bit and drops
the crossing out of `unrecognized` (`:586-587`).

The chapter's own definition makes this a clock, not an enable:
`chapters/ch03-digital-design-for-verifiers.qmd:56` — "A **derived clock** is
any signal produced from another clock by the network in between." And
`clocks.py:52-55`, a docstring the book prints at `:246`, claims the code
already handles it: "**Strong**: the net already drives some register's clock
pin directly, **or is a register output used as a clock (a divider)**". The
code only recognizes a divider that drives a `CLK` pin *directly*. A divider
that is blended or gated — the only way a divider can produce a *new* domain —
is invisible to it.

```systemverilog
// divblend.sv -- Plassan's blending, with the second clock a divider.
// clk2div is a divide-by-two of clk2, an independent asynchronous clock.
// It is a *derived clock* by the chapter's own definition.  It drives no
// register's clock pin directly, so it is not in the `strong` set; it is a
// register output, so it is not an input port and not in `weak` either.
module divblend (input logic clk1, clk2, input logic [7:0] d,
                 output logic [7:0] q);
  logic clk2div, gclk;
  logic [7:0] a, b;
  always_ff @(posedge clk2) clk2div <= ~clk2div;
  assign gclk = clk1 & clk2div;            // blend clk1 with clk2/2
  always_ff @(posedge clk1) a <= d;        // clk1 domain
  always_ff @(posedge gclk) b <= a;        // blended domain, 8 bits, no sync
  assign q = b;
endmodule
```

`gclk` rises either when `clk1` rises with `clk2div` high — a `clk1` edge — or
when `clk2div` rises with `clk1` high, which is an edge placed by `clk2` and
bears no timing relationship to `clk1` at all. `b` therefore samples `a` at an
arbitrary point in the `clk1` period. Eight bits, no synchronizer.

```

  CHECK a (clk1#2) -> b (clk1#21), 8 bits, no synchronizer shape  [divblend.sv:13]
instances: 0, connections: 0
$ echo $?

```

**Declaring the clocks does not help, which is the worse half.** The chapter
(`:242`) says a declaration means "nothing is left undecided", and
`clocks.py:70-71` says "a declared name is the only strong evidence, everything
else is control, and nothing is left to a guess". With `declared` non-empty,
`clock_candidates` returns `(set(declared), set())` (`:73-74`) — the weak tier
is *empty*, so `_tier` can only return 2 or 0, and `ambiguous` at `:178-179`
can never fire from a demotion. Declaring both real clocks makes the answer no
better, and declaring a name that does not exist makes it *correct*:

```
$ ... read divblend divblend.sv --clock clk1 --clock clk2
crossings: 1, shape not recognized: 1, 1 of them one clock gated differently
  CHECK a (clk1#2) -> b (clk1#21), 8 bits, no synchronizer shape  [divblend.sv:13]
$ echo $?
0

$ ... read divblend divblend.sv --clock clk1
  ... identical, exit 0

$ ... read divblend divblend.sv --clock nosuchclock
clock domains: 3
  clk1: 1 registers
  clk1+clk2div: 1 registers
  clk2: 1 registers
crossings: 1, shape not recognized: 1
  CHECK a (clk1) -> b (clk1+clk2div), 8 bits, no synchronizer shape  [divblend.sv:13]
$ echo $?
1
```

A misspelled declaration gives the right answer and a correct one gives the
wrong answer. That inversion is worth stating on its own: the declaration
feature, as built, can only ever *remove* findings, and it removes this one.

`crossings --validate` names the mechanism:

```json
{"to": "b", "to_domain": "clk1#21", "from": "a", "from_domain": "clk1#2",
 "width": 8, "direct": true, "second_stage": [], "shape_recognized": false,
 "same_clock_source": true, "note": "no synchronizer shape"}
```

with `"unrecognized": []`. `clock-tree` shows the demotion and shows that it
was never flagged:

```json
"b": {"clock_sources": ["clk1"], "gated_or_muxed": true,
      "through": ["$and", "gated by clk2div"],
      "clock_ambiguous": false, "root_bits": ["2"], "domain": "clk1#21"}
```

**This falsifies printed sentences.** `:238` — "Strong evidence is that the net
already drives some register's clock pin, **or is a divided clock**, or is
something the netlist cannot see into" — is false of the code for any divider
that does not drive a `CLK` pin directly, which is every divider that matters
to this analysis. `:296` — "Where they do not, as with a divider or a
multiplexer between two clocks, it does fail" — is false of `divblend.sv`, in
which there is a divider between two clocks and it does not fail. `:242`'s
"nothing is left undecided" is true but for the wrong reason: nothing is
undecided because the weak tier is empty, so a wrong decision is made in
silence.

**Fix.** Two, complementary.

1. Extend the strong tier from "a register whose `Q` is a `CLK` bit" to "a
   register whose `Q` reaches a `CLK` bit through the clock-tree pass-through
   set" — the walk that answers that question is already written
   (`_walk_to_sources` with `any_comb=False`). Then `clk2div` is strong,
   both inputs of the gate are carried, the register has two root bits, and
   `same_clock_source` is false. This also makes `clocks.py:52-55` true.
2. Independently, `same_clock_source` must not be satisfied by a cone that
   demoted anything: require `not tree["registers"][name]["gated_or_muxed"]`
   on *both* ends, or compare the `through` lists. Two nets that reach one
   root only because a walk discarded a different root have not been shown to
   be one net. That is a two-line change and closes the exit-0 hole on its own.

Fixture: `divblend.sv`.

### 1.2 `shape_recognized: true` on two one-bit chains carrying one value — the fourth route

`_flag_parallel_synchronizers` (`clocks.py:368-459`) has two rules. `gate2f`
§1.3 moved the second from the domain key to the clock *roots*
(`boundary`, `clocks.py:439-442`), keyed on
`(frozenset(from root_bits), frozenset(to root_bits))`. A frozenset is still a
derived key, and it still splits: a sending flop whose clock gate carries an
input the walk cannot see into gets **two** root bits, not one, so its chain
lands in a group of its own and neither rule fires.

The opaque input is not exotic. `_tier` (`clocks.py:92`) treats
`kind == "unknown"` as strong evidence of a clock, and `_walk_to_sources`
returns `"unknown"` for any net driven by a cell outside `PASS_THROUGH`
(`clocks.py:198`) — an adder, a multiplier, a shifter, a memory read port, a
black box. A clock gate enabled by a bit of an arithmetic result is ordinary
RTL. Both inputs are then tier 2, both are carried (`:169-171` never demotes
when the tiers tie), `ambiguous` stays false, and the register's `root_bits`
has two entries.

```systemverilog
// mixroot.sv -- a two-bit value crossing on two one-bit synchronizers.
// Both sending flops are on aclk; one of them sits behind a clock gate whose
// enable the netlist cannot see into (an $add output).  Each chain is a
// correct two-flop synchronizer; together they are the loss of data
// @sec-ch03-cdc describes.  The value leaves through the ports, so no
// register inside reads the two chains together.
module mixroot (input logic aclk, bclk,
                input logic [3:0] x, y,
                input logic d0, d1,
                output logic o0, o1);
  logic [4:0] sum;
  logic g1, a0, a1, p0, p1, r0, r1;
  assign sum = x + y;
  assign g1  = aclk & sum[0];
  always_ff @(posedge aclk) a0 <= d0;
  always_ff @(posedge g1)   a1 <= d1;
  always_ff @(posedge bclk) begin p0 <= a0; p1 <= a1; end
  always_ff @(posedge bclk) begin r0 <= p0; r1 <= p1; end
  assign o0 = r0;
  assign o1 = r1;
endmodule
```

```
$ PYTHONPATH=tools conda run -n dvbook python -m dvh.cli read mixroot mixroot.sv
clock domains: 3
  aclk: 1 registers
  aclk+sum (driven by $add): 1 registers
  bclk: 4 registers
registers without reset: 6
  ...
crossings: 2, shape not recognized: 0
  known a0 (aclk) -> p0 (bclk), 1 bit, two-flop synchronizer  [mixroot.sv:17]
  known a1 (aclk+sum (driven by $add)) -> p1 (bclk), 1 bit, two-flop synchronizer  [mixroot.sv:17]
instances: 0, connections: 0
$ echo $?
0
```

Identical output, and exit 0, with `--clock aclk --clock bclk`. The JSON:

```json
{"to": "p1", "from": "a1", "from_domain": "aclk+sum (driven by $add)#21",
 "width": 1, "direct": true, "second_stage": ["o1"],
 "shape_recognized": true, "same_clock_source": false, "note": ""}
{"to": "p0", "from": "a0", "from_domain": "aclk#2",
 "width": 1, "direct": true, "second_stage": ["o0"],
 "shape_recognized": true, "same_clock_source": false, "note": ""}
```

`"unrecognized": []`. Two bits of one value, synchronized bit by bit across one
physical clock boundary, reported as two recognized two-flop synchronizers.

**This falsifies printed sentences.** Exercise 6 at `:329` — "The tool rejects
parallel one-bit synchronizers across a clock boundary, because someone
anticipated that anti-pattern — three times, after three designs walked past
the first three versions of the check" — is false of `mixroot.sv`, which is
parallel one-bit synchronizers across a clock boundary and is accepted. `:291`'s
taxonomy is one round behind for the same reason: "parallel one-bit chains
carrying one value — three times, by three routes, the last of them two clock
gates off one clock" is now four routes.

**Fix.** The four versions of this check have keyed on a declared name, on a
downstream reader, on the domain pair, and now on the root-bit set. Each is a
*derived* key and each has split. The thing that does not split is the question
the rule is actually asking: do these two chains cross between the same two
physical clock networks? Key rule 2 on a canonical clock identity — the set of
strong roots reachable from each end's `CLK` pin, with demoted and
opaque-driven inputs excluded rather than added — or, more simply, on the
*intersection* of the two ends' root-bit sets being non-empty, which is a
grouping relation rather than an equality and does not split when one end
picks up an extra root. Fixture: `mixroot.sv`.

### 1.3 A crossing whose destination is a latch is not reported at all: `crossings: 0`, exit 0

`crossings` (`tools/dvh/clocks.py:521-523`) builds `by_name` from
`registers(mod)` and iterates it, and `registers` (`tools/dvh/design.py:310-311`)
yields only cells whose type is in `DFF_TYPES` (`design.py:25-28`). A latch is
not in that set. `clocks.py:29-34` states the design intention for latches — "a
path through one is never direct, so it can never be a synchronizer; but
stopping at a latch would hide the crossing behind it, so the data walk passes
through and records the latch" — and that is true of a latch *in the middle* of
a path. A latch at the *end* of one is never asked about, because the loop that
asks the question only visits flip-flops.

```systemverilog
// latchend.sv -- the receiving element is a latch, not a flip-flop.
module latchend (input logic aclk, bclk, input logic [7:0] d,
                 output logic [7:0] q, output logic ben);
  logic [7:0] a;
  logic en;
  always_ff @(posedge aclk) a <= d;      // aclk domain
  always_ff @(posedge bclk) en <= ^d;    // bclk domain
  always_latch if (en) q <= a;           // a (aclk) captured on a bclk enable
  assign ben = en;
endmodule
```

Eight bits leave the `aclk` domain and are captured by a transparent latch
whose enable is a `bclk`-domain register. The latch opens and closes on `bclk`
timing over data that moves on `aclk`: the enable edge can land anywhere in
`a`'s transition, which is the setup/hold violation of @sec-ch03-metastability
with no synchronizer anywhere. The tool reports the design as clean:

```
$ PYTHONPATH=tools conda run -n dvbook python -m dvh.cli read latchend latchend.sv
clock domains: 2
  aclk: 1 registers
  bclk: 1 registers
registers without reset: 2
  a  [latchend.sv:6]
  ben  [latchend.sv:7]
crossings: 0, shape not recognized: 0
instances: 0, connections: 0
$ echo $?
0
```

Identical, exit 0, with `--clock aclk --clock bclk`. And the JSON is empty, not
merely unflagged:

```
$ ... crossings latchend latchend.sv --validate
{
  "crossings": [],
  "unrecognized": []
}
```

The netlist has the latch; only the tool does not look at it:

```
$ yosys -p "read_verilog -sv latchend.sv; hierarchy -check -top latchend; \
    proc; opt_dff; memory_collect; memory_map; flatten; opt_clean; stat"
=== latchend ===
        4 cells
        2   $dff
        1   $dlatch
        1   $reduce_xor
```

The escape route is the one the chapter already worries about for per-bit
chains: the latched value leaves the block through a port, so no flip-flop
inside this netlist ever reads it. Put a `bclk` flop on `q` instead and the
crossing *is* found, through the latch, exactly as `clocks.py:29-34` promises —
which is what makes this a gap in the destination set rather than in the walk.

Latch-terminated paths are not exotic: retention and isolation latches on a
power domain boundary, level-sensitive legacy interfaces, and the enable latch
of a clock gate are all of this shape, and the last of those is a structure the
chapter names in its own text (`:63`, "A clock gate is normally built with a
latch").

**This falsifies printed sentences.** `:268` — "Notice what the report does not
say... It says one matches a shape it recognizes and two do not, which is a
fact about structure" — and `clocks.py:515-517`, printed at `:246`: "**Nothing
is ever suppressed**, and where the walk cannot resolve a clock it says so."
Here a crossing is not suppressed by a rule; it is never constructed, and the
report contains no trace that a state element it does not model exists in the
design at all. `:291`'s taxonomy lists "because a walk stopped at a latch, or
passed through one by its data input only" — a *third* latch route is now open
and the sentence does not cover it.

**Fix.** Two parts, and the first is cheap.

1. Treat a latch as a crossing destination. `LATCH_TYPES` is already defined
   (`clocks.py:33-34`); a latch's domain is not a clock domain, but the
   question "does this latch's data come from a register whose clock differs
   from the domain of whatever drives its enable" is answerable with the walks
   already written, and the answer belongs in `crossings` with
   `shape_recognized: false` and a note saying the destination is a latch.
2. Failing that, make the silence impossible: count the latch cells in the
   flattened netlist and print them, so `crossings: 0` on a design holding
   eight bits in a `$dlatch` is not the whole of what the reader is told. A
   tool whose contract is "a fact about structure" must not omit a state
   element from the structure.

Fixture: `latchend.sv`.
