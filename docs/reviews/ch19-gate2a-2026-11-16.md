## Blocking findings

**B1. Lines 161 and 556: the 199-cycle gap is not "the same mechanism" as the
prophecy, and the trace does not end before the assumption could check it.**
Line 161: "The assumption is an implication whose consequent lasts 199 cycles,
and the trace ends three cycles after its antecedent. On this tool, a trace
counts as satisfying the assumption if it ends before the window closes ...
The same mechanism defeats the prophecy variable of @sec-ch19-history, and the
rule there applies here: an assumption checks nothing in cycles the trace does
not reach." Line 556: "The same mechanism let the timer's depth-3 trace survive
a 199-cycle assumption".

The assumption is `req && !busy |=> !u_timer.expired [*199]`
(`cut-timer/cut.tcl` line 94). The trace (`cut-timer/run.out` lines 60-64) has
the antecedent in cycle 1 and `expired = 1` in cycle 2, the first cycle of the
consequent. The violation is in a cycle the trace *does* reach. Under IEEE
1800 semantics the consequent `!expired [*199]` is a weak sequence that fails
as soon as no match is possible, so a trace with `expired` high in cycle 2 is
a bad prefix of the assumption and is excluded whatever its length; a tool that
follows the standard would remove this trace. InFormal does not: it judges a
multi-cycle consequent only when its whole window has elapsed. I confirmed
that with a design of my own on the pinned build (two free inputs `req`, `x`;
`assume {req |=> !x [*N]}`, `assert {req |=> !x}`, `informal-bmc`): with
`N = 1` there is no counterexample, with `N = 3` the assertion is refuted at
depth 2 although the assumption forbids exactly that trace. So this is a tool
behavior that deviates from the language, not a property of safety checking.
The prophecy case is different in kind: there the checking cycle (`pop_k`)
genuinely lies beyond the end of the trace, and every tool behaves the same.
Teaching them as one mechanism tells the reader that a long-window assumption
never constrains a short trace on any tool, which is false, and hides that
this is an InFormal gap a reader should expect to differ elsewhere. Also
"three cycles after its antecedent" is two (antecedent in cycle 1, trace ends
in cycle 3).

Fix (line 161, from "The assumption is an implication"): "The trace raises
`expired` in cycle 2, the first cycle of the assumption's window, so it breaks
the assumption inside the trace. The language says such a trace is excluded;
InFormal judges a multi-cycle consequent only once its whole window has
elapsed, so on this tool a multi-cycle assumption constrains only traces long
enough to contain its whole window [@informal-tool]. The one-cycle gap of
block D binds at once. Write gap assumptions one cycle at a time, or expect a
spurious trace shorter than the window." Delete "The same mechanism defeats
... trace does not reach." In the Pitfall at line 556, replace the sentence
"The same mechanism let the timer's ..." with "On this tool a multi-cycle
assumption behaves the same way even when the trace breaks it, because the
tool judges it only at the end of its window (@sec-ch19-timer)." The
outline's finding (i) and the comment at `cut.tcl` lines 88-91 carry the same
conflation and should be corrected with it (the comment's "binds too late" is
right; "constrains only traces that contain the whole window" is right as a
statement about the tool).

**B2. Line 691: the decomposition Pitfall forbids what the entry does, and the
real circularity rule is missing from the helper and decomposition entries.**
Line 691: "a chain that assumes its own conclusion, directly or through a
lemma that restates it, proves nothing; check that no lemma, alone or with the
others, already implies the end-to-end property before the design is
involved." In `decomp/decomp.tcl` lines 12-13, `L1` (`wcnt0 + wr_left[0] ==
len0`) and `L2` (`$rose(done[0]) && !err[0] |-> wr_left[0] == 0`) together
imply `E2E_A` by pure logic, with no design involved; that is the entry's own
Idea at line 662 ("check that the end-to-end property follows from the
lemmas") and the reason `E2E_A` is proven at once (run.out line 22). Lemmas
that imply the conclusion are the goal of a decomposition, not a defect. What
makes a chain circular is the proof graph: a lemma proved under an assumption
whose own proof assumed that lemma (or the conclusion) in the same cycle. Two
invariants each proved with the other assumed in every cycle prove nothing
(both `x == 0` and `x == 1` can be "proved" that way on a design where `x` is a
free register with no reset). The helper entry (line 573, "Proofs, provided the
helper is itself proved in the same flow") omits the same side condition.
Fix: line 691, replace from "And a chain that assumes" with "And a chain is
circular when a lemma's proof assumes the end-to-end property, or another
lemma whose proof assumed it: draw which proof assumed which property and
check that the graph has no cycle, or that every cycle passes through a
register in the sense of @sec-ch19-ag." Line 573: "Proofs, provided the helper
is itself proved in the same flow, and its proof does not assume the property
it helps, directly or through other helpers."

## Non-blocking findings

### Technical precision

**N1. Lines 239, 251, 975 and the glossary "Initial-value abstraction": the
inductiveness side condition is not needed for a proof to transfer.** Line
251: "Proofs, with two side conditions: `INV` holds in the reset state, and
`INV` is inductive." If a property is proved (unboundedly) for every trace
from every `INV` state, and the reset state (the first state after reset) is
an `INV` state, every trace from reset is one of those traces; that is the
whole argument. Inductiveness makes `INV` contain every reachable state, which
matters when the start set is used for a *bounded* search or as the claim
"every deep state is a shallow state here", not for the proof. Exercise 3
("Which two facts make a proof from those states a proof from reset") then
has a wrong determinate answer. Fix: "Proofs, with one side condition: the
reset state satisfies `INV`. If `INV` is also inductive, the start set
contains every reachable state, so a bounded search from it reaches every
reachable state's next N cycles." Adjust exercise 3 to "Which fact makes ...,
and what does the second `INV_A` row add?" Also say at line 263 that the
helper assumed at 256 (`M_H`) is a conjunct of `INV`, discharged by the first
`INV_A` row.

**N2. Line 342 and line 803: the one-word argument assumes `ahead` counts the
words ahead independently; `track.sv` takes it from the FIFO's own `count`.**
`track.sv` line 25: `ahead <= AW'(u.count) - AW'(u.do_read)`. The argument
("count the words ahead of it ... when nothing is ahead, the word at the
output is `sd`") holds only if the design's count is right, and the wrapper
reads design internals, against the chapter's own advice at line 468 ("a
wrapper that touches the design only through its ports"). This is plausibly
why `a_integrity` does not kill the count mutant (line 803); "whose first
failure is sixteen cycles deep" describes the other properties, not this one.
Fix: either compute `ahead` from a port-level occupancy ghost (as `fifo_ctr`
does), or add one sentence: "The wrapper takes the count of words ahead from
the FIFO's own `count`; the argument then assumes that count, which the
occupancy checker proves separately, and a count bug is that checker's to
catch." Reword line 803 to "and, within two seconds, not the count mutant".

**N3. Line 185: the refutation at 32 is the constant `5'(32)` truncating to 0,
not the count overflowing.** `width.tcl` lines 42-43 assert `occ <= 5'(32)`
and `full == (occ == 5'(32))`; both constants are 0, which is why the
counterexamples are at depths 2 and 1 (`param-width/run.out` 17-18), long
before 32 pushes. The lesson survives, but the explanation should match the
trace. Fix: "refuted at 32 within two cycles: five bits cannot even hold the
constant 32, which truncates to 0, and the count would wrap after 31 pushes."

**N4. Line 361: "the tracked word leaving with nine words behind it".**
`c_out` is `in_q && ahead == '0 && u.do_read && u.count == 9`
(`track.tcl` line 77): the count includes the tracked word at the head, so
eight words are behind it; depth 10 fits nine pushes in cycles 1-9. Fix:
"with eight words behind it" (and the script comment).

**N5. Line 544: the mutant's cover is not "a grant whose request came more
than three cycles earlier".** `c_late` is `gnt && !$past(req) && !$past(req,2)
&& !$past(req,3)` (`hist.tcl` lines 80-81); on the mutant it is covered at
depth 3 (run.out line 15), too early for any request three cycles back: the
mutant grants with no request at all. Fix: "on the correct unit with a cover
of a grant whose request came more than three cycles earlier; on the mutant
the same cover is reached at depth 3 by a grant with no request." Also
`history/run.out` line 17 says "the ninth pop"; `pop_k` with `k == 9` is the
tenth pop, counting from 0 (`hp.sv` line 47). The prose's "the pop numbered
k = 9" is right; fix the script's string.

**N6. Line 389 and the `ch19-track` figure: "no slot of the memory holds `d1`
any more" is false as an invariant.** A popped slot keeps `d1` until it is
overwritten. The needed fact is about the occupied slots, between the read
and the write pointer. Fix: "no occupied slot holds `d1` any more"; figure:
"no other occupied slot holds d1".

**N7. Line 380: "Loss of a word is not covered".** True of the flag form; the
position form's `p_head1`/`p_head2` catch a tracked word that is overwritten
or displaced, as the one-word check does (line 366 says it catches "loss of
identity"). What neither covers is a FIFO that stops delivering. Fix: "The
flag form does not cover loss ...; the position form catches a word that is
overwritten, but neither catches a FIFO that never delivers it, which needs a
liveness or bounded-response property."

**N8. Line 525: refinement mappings do not "always" exist.** Abadi and
Lamport's completeness result holds under hypotheses (machine closure, finite
invisible nondeterminism, internal continuity in the paper's terms). Fix: "so
that, under conditions the paper states, a refinement mapping between two
specifications exists".

**N9. Line 809: "uses the logic a bounded refutation needed".** In this book
"refuted" means a counterexample was found (it is used that way some forty
times). McMillan and Amla use the logic in the *proof of unsatisfiability* of
a bounded check, i.e. a proof that no counterexample exists to the bound.
Fix: "uses the logic that a bounded proof, the solver's proof that no
counterexample exists to some depth, needed" (line 279 already says it
correctly).

**N10. Line 849: "pessimistic with respect to silicon".** Self-composition
with each unknown source free and independent in each copy is exact for the
question asked: a difference means the output's value depends on the value
the unknown takes. That is a real dependence in silicon too; whether it is a
bug depends on whether the output is qualified (by a valid, say) at that time.
"Pessimistic" is the word usually applied to X in simulation, and here it
misleads. Fix: "A difference is an output whose value depends on the value an
unknown takes, which is real in silicon as well; whether it is a bug depends
on whether the output is used in that cycle."

**N11. Lines 237 and 961: "256 pushes from reset".** The mutant wraps on the
push from 254 (`init.tcl` line 12, `count == DEPTH-2`), so the bug is the
255th push; line 258 itself says the start state is "254 pushes from reset".
Fix: "255 pushes" (or "more than 250").

**N12. Line 625: "a case list that forgot case 3 passes all three of its
cases".** With the bug planted, cases 0-2 were not run (`case-split/run.out`
lines 30-38 show only case 3 and `A_cover3`; `split.tcl` line 43 runs only

**N13. Line 191: "there are more such states than any k walks past".** The
reason induction fails is not the number of states: an unreachable state with
the array word at `sa` different from `sv` can persist unchanged for any

**N14. Line 425: "the rotation check shows why it could not be one".** Block

**N15. Lines 241 and 275: `reset -none` does not free every register.**
`iv.sv` relies on `initial first = 1'b1` surviving `reset -none`; if `first`
were free, block C would fail at depth 0 like block D, and it does not. Fix:

**N16. Line 509 and exercise 7: two rows of part D show the wrong role.**

## Teaching

A DV engineer who has read the property and formal chapters can use every
full entry: each says what goes wrong without the technique, shows the tool
spelling from a real file, names the side condition and shows a run that
fails without it. The chapter does not repeat its predecessors; it points to
`@sec-ch18-helper`, `@sec-ch18-assume`, `@sec-ch09-where` and others and
adds only what is new (typing a helper once in a Tcl variable, role
parameters, the circularity rule). The compact entries are honest about what
the tool lacks. The worked example's eight steps are a usable procedure. The
weak spots are B3 (an objective nothing teaches) and the B1 explanation,
which would send a reader using another tool looking for a behavior that is
InFormal's own.
