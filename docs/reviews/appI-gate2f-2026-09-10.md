## S-1 (`:209`) — the claim about the tests is still wider than the tests

**The text.**

> Further tests live in the tool layer's own suite rather than in the file
> below. One walks the schemas and fails if a field is ever added without a
> description. **Others run every command on every design the repository ships
> and fail if a reported source location is blank, absolute, or does not name
> the construct it points at.**

The first clause is true: `tools/dvh/tests/test_ch03.py:272`
`test_every_field_carries_a_description` walks every schema and asserts a
`description` on every field. The bolded sentence asserts a conjunction that no
test performs. Broken into its parts:

| asserted | the test that does it | actual scope |
|---|---|---|
| every command × every shipped design | `test_every_fixture_validates_and_is_located` (`:305`) | 4 commands × `FIXTURE/*.sv` only — **not** the ch03 example design, **not** the ch01 FIFO; and it asserts schema conformance, nothing about the location beyond the schema's `"pattern": "^[^:]+:\\d+"` |
| location is not blank, not absolute | `test_every_finding_carries_a_real_source_location` (`:330`) | `TWO_CLOCK` **only** — `:339` loads `design.load_flat(TWO_CLOCK, "top")` and nothing else |
| location names the construct | `test_the_source_location_points_at_the_right_line` (`:357`) | every fixture, but **clock-tree registers only** (`:373-379`); instances are checked on `TWO_CLOCK` alone (`:370`), and neither `crossings`' `src` nor `reset-tree`'s `no_reset` entries are checked for correctness on any fixture |

So: the blank/absolute check runs on one design, not every design; the
correctness check runs on one command's output, not every command; and neither
runs on the two example designs whose output the book actually prints.

This matters beyond pedantry. The same gap — "the appendix states a property of
the tool's *output* while the tests check a property of its *shape*" — is what
the last five rounds kept finding. The residual defect in S-2 below is exactly
one of the uncovered combinations.

I ran the sweep the sentence describes, because the tests do not: over all 22
fixtures plus the ch03 example design plus the ch01 FIFO, every register
location and every crossing location names its construct (§2). The claim is
**substantively true today and procedurally unguarded.**

**Fix, two options.**

1. Make the sentence match the tests: "Others run every command on every design
   the tool's own suite ships and fail if a reported source location is blank or
   ill-formed, and one checks, for every register of every such design, that the
   line it names really is the line the register came from."
2. Or make the tests match the sentence — the better choice, and about fifteen
   lines. Widen `test_every_finding_carries_a_real_source_location` to the same
   `FIXTURE.glob("*.sv")` loop the correctness test already uses, add `FIFO` and
   `TWO_CLOCK` to both loops, and extend the correctness loop to the `src` of
   `crossings(...)["crossings"]` and `reset_tree(...)["no_reset"]`. All of these
   pass today, verified by `scratchpad/sweep.py`, so the change is a guard
   rather than a fix.

**Also note a dead assertion inside the helper.** `test_ch03.py:404`:

```python
hit = [w for w in words if w in block]
assert hit, (src, words, block[:80])
base = name.split(".")[-1].split("[")[0]
if base and base in "".join(text):
    assert base in block or hit, (src, name)
```

`hit` is non-empty by the assertion two lines above, so `base in block or hit`
is always true and the name half of the check never runs. Either drop it or make
it `assert base in block`.

## S-2 (`:47`, `tools/dvh/design.py:135-224`) — the one shape where a register still reports a location that did not produce it

`_memory_src` deliberately refuses to guess when two modules declare arrays of
the same name. Its docstring (`design.py:141-143`) says so:

> a name that is claimed by two different lines is dropped rather than guessed
> at. Pointing a reader at the wrong array is worse than pointing nowhere.

But dropping it does not produce "nowhere". `_fill_missing_src` falls through to
its third source, `mod.src` (`design.py:209`), documented as "The module's own
declaration, which is coarse but true" — and after flattening, `mod` is the
**top** module, not the one the array was in. Constructed design
(`scratchpad/rtl/two_arrays_same_name.sv`): `a_blk` declares
`logic [7:0] mem [16];` on line 3, `b_blk` declares the same on line 9, and the
top module spans lines 13-17.

```
$ PYTHONPATH=tools conda run -n dvbook python -m dvh.cli reset-tree \
      two_arrays_same_name two_arrays_same_name.sv --validate
q1          two_arrays_same_name.sv:5.3-5.40      <- correct
q2          two_arrays_same_name.sv:11.3-11.40    <- correct
u_a.mem[0]  two_arrays_same_name.sv:13.1-17.10    <- the top module's own span
```

The payload validates. The location is non-blank, relative, digit-led and names
an existing file, so every check in the suite passes it. A reader following it
lands on the top module's port list, five lines above the instantiation, in a
different module from the one that declares the array. `:47`'s "names the file
and line of the RTL that produced it" is false for these sixteen registers.

Two modules each declaring `mem` is ordinary RTL, not a contrived shape; this is
one fixture away from being the seventh round's blocker. It is graded serious
rather than blocking only because it is false of nothing the repository ships
(§2).

**Fix.** Either (a) key the memory map by module as well as name so the
collision does not arise — the pre-`memory_map` JSON has the owning module, it is
simply discarded at `design.py:146-152`; or (b) make the guard mean what its
docstring says and emit no location, which requires relaxing the schemas'
`"pattern": "^[^:]+:\\d+"` to allow an empty string and stating the gap at
`:42`/`:47`; or (c) restrict the `mod.src` fallback to cells that belong to the
top module's own source. Whichever is chosen, add
`two_arrays_same_name.sv` as a fixture, since S-1's point is that the guard has
to be a test.
