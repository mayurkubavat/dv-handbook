## E1 detail — the timescale rewrite is false under the other simulator

`chapters/ch04-simulation-fundamentals.qmd:174`:

> Delays are scaled to the smallest precision used anywhere in the design
> [@sutherland2007gotchas], which sets the resolution of the shared time wheel;
> **a module's own delays are still rounded to its own declared precision, so a
> finer module elsewhere does not change what a coarser one does.**

The first clause is the source's, verbatim in substance (`g2007.txt:1807–1808`,
§8.1: "Within simulation, all delays are scaled to the smallest precision used
by the design"). The bolded clause is the chapter's own inference. It is what
IEEE 1800 requires, and **Verilator 5.030 does not do it.**

Written for this review, not adapted from the chapter's examples. A module that
declares `1ns/1ns` and delays by `#1.4`, alongside a module that declares
`1ns/1ps`. If the coarse module's delay is rounded to its own 1 ns precision it
fires at 1.0 ns, *before* the fine module's 1.2 ns event; if it is not, it fires
at 1.4 ns, *after* it:

```systemverilog
// o_coarse.sv
`timescale 1ns/1ns
module ocoarse;
  initial #1.4 $display("  ocoarse (1ns/1ns): my #1.4 fired");
endmodule

// o_fine.sv
`timescale 1ns/1ps
module ofine;
  initial #1.2 $display("  ofine   (1ns/1ps): my #1.2 fired");
endmodule
```

```
$ iverilog -g2012 -o O.vvp o_coarse.sv o_fine.sv o_top.sv && vvp O.vvp
  ocoarse (1ns/1ns): my #1.4 fired
  ofine   (1ns/1ps): my #1.2 fired

$ verilator --binary --timing -Wno-DECLFILENAME -Wno-TIMESCALEMOD \
      --top-module otop -Mdir vO o_coarse.sv o_fine.sv o_top.sv && ./vO/Votop
  ofine   (1ns/1ps): my #1.2 fired
  ocoarse (1ns/1ns): my #1.4 fired
```

**Opposite orderings, same source.** Isolated further — one `1ns/1ns` module,
nothing else in the design with a delay, and only the top declaring `1ns/1ps`:

```
$ vvp P.vvp                       # iverilog
  pcoarse #1.4 -> $realtime=1.000000 (1ns units)
  pcoarse #0.4 -> $realtime=1.000000 (rounds to 0 if honored)
$ ./vP/Vptop                      # verilator
  pcoarse #1.4 -> $realtime=1.400000 (1ns units)
  pcoarse #0.4 -> $realtime=1.800000 (rounds to 0 if honored)
```

Icarus rounds `#1.4` to 1 ns and `#0.4` to 0 — the module's own declared
precision. Verilator rounds neither; it uses the design-wide precision. The
sentence the chapter prints is a statement about the model, correct as such,
printed as a statement about what happens.

This matters more than an ordinary inaccuracy for three reasons:

1. It is round D's **D4 with the sign reversed.** D4 blocked "Delays are scaled
   to the smallest precision used anywhere in the design, *so one module's
   declaration changes another module's behavior*" on an experiment run under
   Icarus alone. That sentence is false under Icarus and **true under
   Verilator**. Its replacement is true under Icarus and **false under
   Verilator**. Two rounds have now each verified a cross-module timescale claim
   on one of the two simulators the book ships, and each time the tool that was
   not run is the one that contradicts the claim.
2. The very next paragraph (`:176`) tells the reader that the chapter's own
   examples get two different answers from the two tools about what time it is.
   A reader primed by that sentence is exactly the reader who will test this one.
3. The paragraph's own hedge does not cover it. `:174` declines to state a
   rounding rule "because no openly readable source states one" and says
   "measure it on the tool you use" — but that hedge is about *which way* a
   sub-precision delay rounds, not about *whether rounding to the module's own
   precision happens at all*, which is the thing that differs.

*Fix.* Keep the model statement and mark it as one, and let the disagreement do
the work the section wants:

> Delays are scaled to the smallest precision used anywhere in the design
> [@sutherland2007gotchas], which sets the resolution of the shared time wheel.
> In the model, a module's delays are then rounded to that module's own declared
> precision, so a finer module elsewhere should not change what a coarser one
> does — and this is a place worth measuring rather than assuming, because this
> book's two simulators answer it differently.

Everything else in the paragraph is correct. The compile-order half was
independently reproduced for this review: the same file, with no `` `timescale ``
of its own, containing `#100`:

```
$ iverilog -g2012 -o c1.vvp co_ns.sv co_bare.sv co_ps.sv co_top.sv && vvp c1.vvp
  bare_mod: its #100 elapsed, now $realtime=100000      # 100 ns
$ iverilog -g2012 -o c2.vvp co_ps.sv co_bare.sv co_ns.sv co_top.sv && vvp c2.vvp
  bare_mod: its #100 elapsed, now $realtime=100         # 100 ps
```

A factor of a thousand, from the order of the files on the command line. Exactly
what `:174` says, and exactly `g2007.txt:1823–1826`.

`refs.bib`, `sutherland2007gotchas`:

```bibtex
  title     = {More Standard Gotchas: Subtleties in the {Verilog} and
               {SystemVerilog} Standards That Every Engineer Should Know},

               publisher's index title. Accessed 2026-09-08}
```

**What the paper says.** Fetched from the entry's own URL,

> Gotcha Again

> Gotchas: Subtleties in Verilog and SystemVerilog That Every Engineer Should
> Know** by Stuart Sutherland and Don Mills (Awarded Best Paper)

## E3 detail — the listing font prints `<=` as `≤`

`_quarto.yml:45–47`:

```yaml
    monofont: "JetBrains Mono"
    monofontoptions:
      - Scale=0.82
```

JetBrains Mono ships programming ligatures in its `calt` feature, which fontspec
enables by default. Nothing turns them off. `pdffonts` confirms the face is
embedded and in use for listings (`QUWHWJ+JetBrainsMono-Regular`).

**What reaches the reader.** `_book/Design-Verification.pdf` p. 120, rendered at
150 dpi and read as an image rather than through `pdftotext` — which is why four
previous rounds did not see this:

> `if (!rst_n) count ≤ 8'h00;`
> `else        count ≤ count + 8'd1;`

directly under, on the same page:

> Change the four assignment operators to non-blocking — **four `<` characters**,
> and nothing else — and the race is gone…

There is no `<` character on the page. The reader is told to look for four of
them and shown four `≤` glyphs. This is round D's **D2** — a count refuted by the
listing beneath it — arriving again by a different route, one round after D2 was
fixed.

It is worse than a count error, because `<=` and `≤` are not interchangeable in
this book's subject matter:

- In an expression, `<=` **is** the less-than-or-equal operator in Verilog. A
  chapter whose entire thesis is the difference between `=` and `<=` prints the
  non-blocking assignment operator as the relational operator it must be
  distinguished from.
- A reader who copies the visible characters does not get compiling SystemVerilog.

**It also corrupts verbatim simulator output**, which the constitution says is
included from `run.out` "so it cannot drift from what the code prints". PDF
p. 112, the regions block:

> `[active]    just assigned b ≤ 1, b is still x`

`examples/ch04-simulation/regions/run.out:2` says:

```
  [active]    just assigned b<=1, b is still x
```

The page is not showing what the simulator printed.

**Scope.** `===` renders as `≡` (PDF p. 116, `≡ four-state, event-driven`, where
`run.out:1` is `=== four-state, event-driven`). `pdftotext` reports 233
occurrences of the `<=` ligature and 9 of the `===` ligature across the whole
book, so this is not a Chapter 4 defect — but Chapter 4 is where a sentence in the
prose counts the characters and is refuted.

*Fix (one line, and it is a whole-book change, so it is an escalation as well as
a finding).* Turn the contextual alternates off in `_quarto.yml:46–47`:

```yaml
    monofontoptions:
      - Scale=0.82
      - RawFeature={-calt,-liga}
```

Re-render and re-read **p. 120 as an image**, not as extracted text: the check
that failed for four rounds is the one that trusts `pdftotext`.

### 2.1 What control flow does with an unknown (`:145–147`) — all five claims hold

```systemverilog
// e1_x.sv (excerpt) -- xc = 1'bx, xsel = 2'bxx, all targets pre-set to 7
if (xc) bare = 8'd1;                                         // bare if
if (xc) els  = 8'd1; else els = 8'd2;                        // if/else
case (xsel) 2'b00: csn = 8'd1; 2'b01: csn = 8'd2; endcase    // no default
case (xsel) 2'b00: csd = 8'd1; default: csd = 8'd9; endcase  // default
```

```
$ iverilog -g2012 -o e1.vvp e1_x.sv && vvp e1.vvp
bare_if_keeps_old=7 if_else_takes_else=2 case_nodefault=7 case_default=9
x&1=x x&0=0 x|1=1 x|0=x x+1=x x^0=x x==1=x ~x=x
```

| Chapter, `:145–147` | Result |
|---|---|
| "An `if` whose condition is unknown does not take the true branch" | Neither `bare` nor `els` took it |
| "With one, the `else` branch runs, exactly as though the condition had been false" | `if_else_takes_else=2` |
| "Without one, neither branch runs and the target keeps whatever it held before" | `bare_if_keeps_old=7` |
| "A `case` on an unknown selector takes its `default`, or, where it has none, does nothing and leaves its target holding the value it already had" | `case_default=9`, `case_nodefault=7` |
| "Arithmetic and bitwise operators **generally** propagate it" | `x&1=x`, `x+1=x`, `x^0=x`, `x==1=x` propagate; `x&0=0` and `x\|1=1` do not. The hedge earns its place |

### 2.2 Active, Inactive, NBA and Postponed in one timestep (`:52–58`, `:91`, `:107`) — hold

```systemverilog
// e2_nba.sv (excerpt) -- v starts at 5
always @(posedge clk) v <= 8'd99;                              // NBA writer
always @(posedge clk) begin r_active = v; $display(...); end   // Active reader
always @(posedge clk) $strobe("  [strobe]   v=%0d", v);        // Postponed
always @(posedge clk) #0 $display("  [inactive] ... v=%0d", v);// Inactive
```

```
$ vvp e2.vvp                          # event-driven
  [active]   read v=5 immediately at the edge
  [inactive] a #0 statement ran, v=5
  [strobe]   v=99
  [nextstep] v=99

$ ./ve2/Ve2                           # statically scheduled
  [inactive] a #0 statement ran, v=5
  [active]   read v=5 immediately at the edge
  [strobe]   v=99
  [nextstep] v=99
```

`:91` ("the update is in NBA and every reader in Active sees the old value") and
the `$display`-versus-`$strobe` row of the guideline table at `:101` are exact on
both tools. And the run is an unplanned confirmation of `:107`: **the two tools
put the `#0` print on opposite sides of the Active print**, which is precisely
"it does not remove the race; it renames it".
