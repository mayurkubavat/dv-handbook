## Blocking findings

### D-B1. The ch09 support matrix prints a backslash inside two code spans (malformed generated table)

`examples/ch09-temporal-properties/support-matrix/matrix.py:371`,
`cell()`: `why = why.replace("$", "\\$")` escapes every dollar sign in a
note, including those inside code spans, where Markdown does not treat
the backslash as an escape. The committed
`examples/ch09-temporal-properties/support-matrix/matrix.md` row
"obligation pending at `$finish`, once per operator" (line 174, both
Verilator columns) holds `` `##[1:\$]` `` and `` `\$finish` ``.

```
$ pandoc -f markdown -t html examples/ch09-temporal-properties/support-matrix/matrix.md \
    | grep -o '<code>[^<]*\\[^<]*</code>' | sort | uniq -c
      2 <code>##[1:\$]</code>
      2 <code>\$finish</code>
$ pandoc -f markdown -t latex ... | grep textbackslash
\texttt{\#\#{[}1:\textbackslash{}\${]}}, ... \texttt{\textbackslash{}\$finish}
```

The table is included by `chapters/ch09-temporal-properties.qmd:303`, so
the book prints `##[1:\$]` and `\$finish` as code, in HTML and PDF. The
defect predates round 1 (the old pipe-table writer had the same escape)
but the round-1 fix rewrote this function and its log (section 8, "Final
checks") states that the pandoc LaTeX pass over ch09 found no
`\textbackslash{}` except shell continuations, which this run
contradicts. The chapter's own `common/tables.py:cell` already does
this right (escapes only outside code spans). Fix: in `matrix.py`
escape `$` only in the parts outside backticks (the same split as
`tables.cell`), apply it to the label column too (`lab` is written
unescaped today; no current label has a bare `$`, but a future one
would open math), regenerate, and grep the HTML for `\` inside
`<code>`.

### E5. The teaching engines against my own fuzzer (task 5)

My fuzzer shares no code with `ic3-fuzz/fuzz.py`: own netlist builder
(with constant folding), each system written as `.aag` and read with
the book's `Aig` (two- and three-field latch rows, self-literal
resets), own evaluator and oracle. AIGER 1.9 semantics: a transition or
a bad state counts only under an input that satisfies every
constraint. Families: random logic (0-3 inputs, 1-5 latches, 0-2
constraints, constants), counters (wrap, saturate, reset-at-limit, any
target), one-hot rings with and without a planted bug, twin counters
with and without a bug, shift registers with a "no two ones" input
constraint; and a third run of larger random logic (4-6 latches).

Checks on every system: IC3 verdict; counterexample starts initial,
follows allowed transitions, ends bad (and was shortest in every case);
invariant contains every initial state, is closed and excludes bad
states by enumeration, `certify` accepts it, and `certify` on the
invariant with one lemma dropped returns the three answers enumeration
gives. Plain k-induction (bound 10): the pair (verdict, k) equals the
solver-free prediction (base at k satisfiable iff a bad state is
reachable in exactly k steps; step at k satisfiable iff a walk of k
good allowed edges ends in a bad state), counterexamples real and of
length k, every returned CTI a real model of the step case.
Unique-states induction (bound `2^n`): (verdict, k) equals the
prediction from the longest simple good path into a bad state, never
undetermined at `2^n`, counterexamples real and shortest; plus a run
stopped one short of its proof whose CTI must be a pairwise-distinct
model of the step case.

## N. Non-blocking findings

**N1. Grid width is `len()`, not display width.** `common/tables.py:141`
and `ch09 .../matrix.py:384`. Wide (CJK, emoji) or zero-width
(combining) characters misalign the borders; cells merge and text is
lost (E2). No probe produces them today. Fix: assert every cell has
`unicodedata.east_asian_width` not in `W`/`F` and no combining marks,
or measure with a width function.

**N2. `BLOCK` misses some block openers, and cells are otherwise raw
Markdown.** `tables.py:121`, `matrix.py:382`: `a. `, `i. `, `(1) `
(pandoc fancy lists), `| ` (line block) and `[x]: url` (reference
definition) are not refused. Beyond `$`, nothing is escaped, so a
tool message with `<word>`, a pair of `*` or a `\` would render as
HTML, emphasis or an escape; this is not specific to grid tables.
Fix: extend the pattern to
`([-+*] |([0-9]+|[A-Za-z]|[ivxlcdmIVXLCDM]+|#)[.)] |\(([0-9]+|[A-Za-z])\) |#|>|: |\| |\[)`
and, for the probe notes that come from tool output, put them in code
spans or escape `\*_<[` as well.

**N3. The C-N3 fix is not guarded.** Moving `set_engine_mode {Ht}`
back before `prove -all` in `shell-commands/commands.list` (M3b)
passes; only the row order changes. If the example's point is a
single-engine session, assert it (for instance that no report row of
the four `prove` lines names `ric3-ic3`, or count engines from the
session).

**N4. Nothing checks a generated table.** M8a, M8b and M10 write a
malformed or wrongly escaped table and `make run` passes; D-B1 is the
committed instance. Fix: let `tables.write` and `matrix.grid` re-read
what they wrote with `tables.read` and assert the cells equal the
input, and assert that no code span in a cell contains `\$`. (A pandoc
round trip would be stronger but adds a dependency to the examples.)

**N5. `ic3-fuzz` does not predict the simple-path k.** M2b (one
pairwise constraint dropped) leaves `ic3-fuzz` passing with the same
tallies; the `kind` example catches it. A `simple_k` beside `plain_k`
(longest simple path of good edges into a bad state, plus one) would
make the fuzz self-sufficient.

**N6. `ran` and `depth` locate a property by text search.**
`engine-guide/guide.tcl:15-21`, `common/proof.tcl` `depth`: if
`"name": "<full>",` is absent, `string first` returns -1 and the next
search starts at 0, so the first property's engine list is read; a
design signal with the same name as a property (the hierarchy lists
signals as `"name": "x",` before the properties) would also match
first. Neither happens in the book's scripts, which pass full names of
existing properties. Fix: search from the `"props": [` offset and fail
on -1.
