## Blocking findings

### B1. The 199-cycle gap is explained by the wrong mechanism, and equated with the prophecy trap (text contradicted by a run)

`chapters/ch19-formal-techniques.qmd:161`: "On this tool, a trace counts as
satisfying the assumption if it ends before the window closes ... The same
mechanism defeats the prophecy variable of @sec-ch19-history, and the rule
there applies here: an assumption checks nothing in cycles the trace does
not reach." Repeated at `:556` (Pitfall): "The same mechanism let the
timer's depth-3 trace survive a 199-cycle assumption (@sec-ch19-timer)."
Also `:161` "the trace ends three cycles after its antecedent".

The depth-3 trace printed in `cut-timer/run.out:60-64` has the antecedent
`req && !busy` in cycle 1 and `expired = 1` in cycle 2. The assumption
`req && !busy |=> !u_timer.expired [*199]` is therefore already violated
in cycle 2, a cycle the trace *does* reach. The trace survives because
the tool evaluates a multi-cycle implication only once its whole window
lies inside the trace, not because the violating cycle is missing.
Measured on scratch copies of `cut.tcl` block F (same design, same cut,
`informal-kind`, 10 s), varying only the repetition count:

```
assume  req && !busy |=> !u_timer.expired [*1]    a_no_early proven
assume  ... [*2]                                  a_no_early proven
assume  ... [*3]                                  a_no_early cex, depth 3
assume  ... [*5]                                  a_no_early cex, depth 3
assume  ... [*199]                                a_no_early cex, depth 3
```

With `[*3]` the same depth-3 trace, violating the assumption in cycle 2,
is accepted; with `[*2]`, whose window ends inside the trace, it is not.
The same holds for assertions, which matters for reading depths elsewhere
in the chapter: `assert req && !busy |=> !u_timer.expired [*N]` under the
cut (where `expired` may rise in cycle 2) is refuted at depth 3, 11 and
200 for N = 2, 10 and 199, by both `informal-bmc` and `informal-kind`,
always at the end of the window and never at cycle 2.

The prophecy case of `history/` is a different thing and is general: its
assumption `pop_k |-> rd_data == pv` has its *antecedent* in a cycle past
the end of the trace, so no tool's semantics constrains the trace. Block
F's violation is inside the trace, and SVA's finite-prefix reading of a
safety property (a prefix that cannot be extended to a satisfying trace
is a violation) would remove it; whether other tools prune it is a
measurement this book has not made. Telling the reader that the two are
one mechanism, and that "an assumption checks nothing in cycles the trace
does not reach" explains block F, teaches a rule that is false of the
trace on the page.

Fix: in `:161`, say what was measured: "On this tool, a multi-cycle
implication is evaluated only when its whole window lies inside the
trace: the trace above violates the assumption in cycle 2, one cycle
after its antecedent, and survives because it ends before the 199-cycle
window closes. With a window of two cycles, which fits, the same trace is
removed and `a_no_early` is proven." Replace "trace ends three cycles
after its antecedent" by "two cycles". Drop "The same mechanism defeats
the prophecy variable" and the "rule there applies here" clause, or
rewrite as a contrast: the prophecy is a trace that ends before the
assumption's antecedent, which no tool can help; block F is a trace that
violates the assumption's consequent inside the trace, which this tool
does not prune. In `:556`, delete the sentence that equates them or
change it to "A related effect, specific to this tool, let ...". Consider
a short note (block F or @sec-ch19-boundedlive) that a bounded engine
reports a multi-cycle assertion at the end of its window, so a depth
printed for such an assertion is the window's end, not the cycle of the
first wrong value. If the example should show it, add the `[*2]` run to
block F; it costs a fraction of a second.

### B2. "Every assertion has a witness cover" is false of about a third of the examples (text contradicted by the code)

`chapters/ch19-formal-techniques.qmd:63`: "Three things accompany every
entry in this chapter, and the chapter does not restate them each time.
Every assertion has a witness cover, run under the same assumptions as
the proof". `:760`: "Every entry of this chapter has used one ... The
witness covers of this chapter's examples are the evidence that each
proof had something to say".

Scanning every session of every `run.out` for a proven implication with
no cover in the same session finds (implications
only; invariants such as `H_A` and miter equalities are left out):

| Example | Session | Proven, no cover in the session |
|---|---|---|
| `symmetry/` | A, B, C | `a_wait0` .. `a_wait3` (under `m_hold`) |
| `ag/` | A, C | `G_out` (under `M_in`) |
| `init-value/` | C | `P_A` (under `M_start`, and `M_H` at 256) |
| `mem-abs/` | D | `a_store` (under `m_sa`, `m_mem`) |
| `symconst/` | B | `Slot_A` (under `m_sa`) |
| `history-ric3/` | A, B | `a_hist`, `a_proph_late` (under `m_k`, `m_pv`, `m_check`) |
| `cut-timer/` | E, G | `a_gap`, `a_201` (no assumptions) |
| `hier-ric3/` | both | `P1_A`, `P2_A` (under the contracts) |
| `two-word-ric3/` | B | `p_head1`, `p_head2` |

None of these proofs turned out to be vacuous: I added the missing
witness covers in scratch copies, under each session's own assumptions,
and every one was reached (`c_emptyafter` depth 1 for init-value C at
256 under `M_start` and `M_H`; `mchk_q` depth 3 for mem-abs D under
the helper; `pop_k && k == 9` depth 11 under `m_k`, `m_pv` and
`m_check`; a four-cycle wait of port 0 depth 5 under `m_hold0` on the
free-start arbiter; `Slot_A`'s antecedent with `sa == 9` depth 10 under
`m_sa`). So this is a claim about the shipped code, not a hidden bug, but
a reader who checks the claim against the listings finds it false in the
very chapter that tells them to read an unreachable cover as a failure.

Fix: either (a) add one cover per listed session (each is one line, and
the five above are measured to cost under a second each with
`informal-bmc`), or (b) soften `:63` to "Every assertion should have a
witness cover ... The examples show one wherever an assumption could
make the assertion vacuous" and `:760` to "Most entries of this chapter
use one", and list the exceptions. (a) is better: the chapter's own
In Practice box at `:816` asks for exactly this.

## Non-blocking findings (section N)

### N1. Expectations with less than a factor of two of headroom

Several `expect` lines encode a race between a limit and an engine, so a
machine about twice as fast (for `undetermined`) or twice as slow (for
`proven`) fails the example. Measured here:

- `mutants/mutants.tcl:45` expects `a_integrity` undetermined on the
  `wrap` mutant within 2 s. With a longer limit `informal-bmc` refutes it
  at depth 17 in 4.3 s. Chapter `:803` ("not the count mutant, whose
  first failure is sixteen cycles deep") is also slightly off for this
  property: 16 is the depth of the other kills, 17 of `a_integrity`.
  Fix: either put `a_integrity` in `kill(wrap)` with a limit that reaches
  it, or keep the 2 s run and say "within two seconds; it falls at depth
  17 with a longer limit".
- `mem-abs/mem.tcl:65`: `a_store` needs 11.4 s of its 20 s limit
  (`tbl-seconds.md`), `h_mem` 6.4 s. `case-split/split.tcl:29`: the whole
  miter needs 18.3 s of 40 s.
- Robust ones, for the record: `two-word-ric3` `p_ahead` and `a_order`
  still have no verdict from rIC3 at 150 s (the example uses 10 s and
  5 s), so the claim at `:398` is not a short-limit artifact. The DMA
  lemmas `L1`, `L2` and `E2E_A` have no verdict from rIC3 at 120 s and
  no counterexample from `informal-bmc` at 60 s.

Suggest a sentence in Appendix F or the chapter's opening that an
example's `undetermined` and `proven` rows are tied to the limits on the
machine that wrote `run.out`, and raise the two tightest limits (20 s to
40 s for `a_store`).

### N2. The DMA lemmas are called true without evidence, and one pitfall contradicts the example

`:683` and `:691` ("Lemmas that are true and not inductive ... as
above"), and `:688`. Neither lemma is proved, and neither is refuted
(N1). Reading `dma_v2.sv:104-143` I believe `L1` holds (configuration
writes, START included, are refused with `PSLVERR` while the channel is
busy, so the start assignment to `wr_left` never meets a same-cycle
`wr_good`), but the chapter should say "believed true" or "not refuted
by a bounded search of 60 s", not "true". Separately, `:691`: "check
that no lemma, alone or with the others, already implies the
end-to-end property before the design is involved". `L1` and `L2`
together imply `E2E_A` with no design at all (wcnt0 + 0 == len0); that is
what makes the chain close, and it is what block B proves in 0.02 s. The
intended pitfall is a lemma that restates the conclusion. Fix: "check
that no single lemma restates the end-to-end property, and that each
lemma is a fact about the design rather than a rewording of the goal".

### N3. "Nine words behind it" is eight

`track-word/track.tcl:46` and chapter `:361`: the cover is
`in_q && ahead == '0 && u.do_read && u.count == 9`. `count` is the
occupancy and includes the tracked word at the head, so eight words are
behind it (I covered the same with `!u.do_write` added, depth 10).
Fix: "with eight words behind it" or "leaving a FIFO of nine".

### N4. The "refused" name inside a box is an internal error

`:105` says a name inside the box "is accepted by `assert` and refused
when the property is run". The row it splices
(`cut-timer/run.out:18-22`) reads `not supported yet: internal: missing
signal slot for symbol SymbolId(13)`. That is a tool limitation reported
as an internal error, not a designed refusal, and it may change at the
next commit of the tool. Suggest "fails when the property is run, with
an internal not-supported error" so the text does not present the
message as the tool's intended behavior.

### N5. The figure generator draws depths but does not check them

`figures/gen_ch19_figures.py` reads every verdict from `run.out`, exits
non-zero when a status changes (tested: `G_out` proven to cex, an
`L1_A` undetermined to proven, a two-word proven to cex, the prophecy
trace changed: all exit 1), and is byte-reproducible (two runs equal the
committed SVGs). A changed depth (mem-abs C 3 to 4, ag D 3 to 4, decomp
`Done3_C` 15 to 16, pipe `U1Full_C` 258 to 259, mutant 256 to 255)
exits 0 and redraws the SVG with the new number. That is consistent
with "draws what run.out says", but the `fig-alt` texts in the chapter
(`:231`, `:597`, `:685`, `:939`) hard-code the same depths, and nothing
fails when they drift. Suggest asserting the depths the alt texts state,
or having `check-structure.sh` compare each committed SVG with a fresh
run of the generator.

### N6. A tool defect worth knowing: `assume -disable` does not disable an RTL assumption

Not used by any chapter-19 script, found while testing `protocol/`.
On `vr_top` with `ENV = 1`, `assume -disable *Answer_M` shows the row as
`disabled`, yet `o_ready |-> o_valid` is then proven and
`i_ready && !i_valid` is unreachable: the assumption still applies. With
the same checker built with `ANSWER = 0` the cover is reached at depth 1
and `Answer_A` fails, as it should. `assume -disable` on a Tcl
assumption and `assert -disable` on an RTL assertion both behave. Worth a
line in the tool notes of @sec-ch18-reference (or an upstream report),
since a reader who disables an RTL assumption to test its effect is told
it is off when it is not.

### E3. Soundness probes (task 3)

All on scratch copies; no tracked file edited.

- **Symbolic constant** (`symconst`): under `$stable(sa)`, `sa == 0` is
  refuted at depth 1 and `sa == 9` covered at depth 1, so `sa` is free and
  not pinned by an initial `$past`. Without the assumption, `C0_A`
  (`first |-> sa0 == sa`) is refuted and `C0_C` covered at depth 1, so
  block C's proof is a real consequence of the assumption, i.e. the
  value is held from the reset cycle. Same check on `mem-abs`
  (`sa == 0` refuted, `sa == 200 && chk_q` covered).
- **Black box / cut** (`cut-timer`): the box note and the depth-3 trace
  are as described; probes on multi-cycle windows are B1.
- **Memory contract** (`mem-abs`): the contract
  (`mchk_q |-> m_rdata == mexp_q`, `mexp_q <= sv`) is the read-old
  behavior of `mem_store`, and is proven on the real storage under the
  proven helper (block D). The contract's antecedent `mchk_q` is reached
  under the helper (depth 3).
- **Assume-guarantee** (`ag`): block C without `M_in` is refuted (depth
  3); with `M_in` on a stuck-at-0 mutant of `blk` refuted (depth 4). The
  liveness ring is refuted for `G_y` too and by `informal-bmc`, so the
  lasso is not an artifact of IC3. The example shows what it says.
- **Symmetry** (`symmetry`): an asymmetric mutant of the arbiter (port 1
  skipped when `last == 0` and port 2 requests) refutes `a_rot` at depth
  2; so does the rotation assumed in the wrong direction. Port 0's
  four-cycle wait is covered under `m_hold0` (depth 5).
- **Oracle guard** (`track-word`): the oracle can pick a push into a
  FIFO of 15 (covered, depth 16), so the `!in_q` guard does not exclude
  the boundary the chapter warns about.
- **Protocol roles**: with the output checker's `Answer` rule removed
  (`ANSWER = 0`), `Answer_A` on the input is refuted at depth 1, which
  confirms `:501`'s "which the stage obeys because its output neighbor's
  `Answer_M` is assumed".
- **History / prophecy**: the trace of `a_proph` is two cycles and ends
  before `pop_k`; `pop_k && k == 9` is reached under `m_k`, `m_pv` and
  `m_check` (depth 11), so `a_proph_late` in `history-ric3` is not
  vacuous.
- **Initial-value abstraction**: under `M_start` and `M_H` at 256 a
  FIFO that becomes empty after not being empty is covered at depth 1,
  so the 256-entry proof of `P_A` is not vacuous.
- **Witness covers missing**: B2.
