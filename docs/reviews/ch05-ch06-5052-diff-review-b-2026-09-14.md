### M4. Cache key and the runner image -- NOT CLOSED (the expression is empty on a hosted runner)
Now (`.github/workflows/book.yml:34-36`):
```
# The image name is in the key so that binaries built on one Ubuntu
# are not restored on the next when ubuntu-latest moves.
key: dvtools-verilator-v5.052-iverilog-v13_0-yosys-v0.68-${{ runner.os }}-${{ env.ImageOS }}
```
`ImageOS` is real: the runner-images build script
`images/ubuntu/scripts/build/configure-environment.sh` (lines 11-13) writes
`ImageVersion` and `ImageOS` into `/etc/environment`, so every process on a
hosted runner sees them, and `${{ env.ImageOS }}` is syntactically allowed in
a step's `with:` (GitHub's contexts reference lists `env` among the contexts
available to `jobs.<job_id>.steps.with`). But the `env` *expression context*
does not contain them. GitHub's contexts reference, "env context": "The env
context contains variables that have been set in a workflow, job, or step.
It does not contain variables inherited by the runner process." The runner
source agrees: `src/Runner.Worker/ExecutionContext.cs:950` creates
`Global.EnvironmentVariables` as an empty dictionary, and
`JobExtension.cs:776-784` builds `ExpressionValues["env"]` from that
dictionary alone, which is filled only from workflow/job/step `env:` and
`$GITHUB_ENV`. A third-party workflow found on GitHub code search
(`getopenscreen/openscreen`, `.github/workflows/build-whisper-stt.yml:159`)
records the same thing empirically: "`${{ env.ImageOS }}` DOES NOT WORK, and
it fails silently ... both halves expanded to the empty string". Several
other repositories use the pattern, which is presumably where it came from;
they get the same empty string.

So the key evaluates to `dvtools-...-yosys-v0.68-Linux-` (trailing dash),
which is a valid key and the cache still works, but the image name is not in
it and the comment above it is false. Not blocking under the previous
review's definition (no book claim, no spliced output, the workflow still
runs), and not verified by running the workflow. Fix, either of:
- a step before the cache step: `run: echo "IMAGE_OS=$ImageOS" >>
  "$GITHUB_ENV"`, then `${{ env.IMAGE_OS }}` in the key; or
- `runs-on: ubuntu-24.04` and the literal `ubuntu-24.04` in the key, which
  also pins the image the book's toolchain was verified on.
