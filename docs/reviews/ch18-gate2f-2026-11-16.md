### E2. `common/tables.py`: `wrap` and `widths`

Code read: `tables.py:55-104`. `wrap` is `textwrap.wrap(text, width,
break_long_words=False, break_on_hyphens=False) or [""]`: it breaks at
whitespace only and never inside a word or at a hyphen; a word longer than
`width` gets its own line. The column width is `max(requested, longest
wrapped line)`, and each row is then re-wrapped at that computed width, so
every line fits its column (a word longer than the request widens the
column instead of overflowing it). Each logical row is emitted as
`max(len(cells))` physical lines, short cells padded with blanks, then the
rule. The header row wraps the same way and the alignment row keeps its
length `w + 2` per column, with `:` at the ends the `align` strings ask for.

Checks run (scratch scripts, not in the repository):

1. **The committed table, losslessly.** Reconstructed the 49 logical body
   rows and the header of `shell-commands/tbl-shell.md` by joining each
   row's physical lines with a space, then wrote them again with
   `tables.write(..., grid=True, widths=[30, 24, 40])`: byte-identical to
   the committed file. Wrote the same rows with no `widths` (one line to a
   cell) and parsed both with pandoc to JSON: after mapping `SoftBreak` to
   `Space`, every header and body cell is identical (49 rows, 3 columns).
   No content lost, reordered or reinterpreted. HTML: no math, no list,
   heading, definition list or quotation, no backslash in code. Code spans

   `` `assert -name a_step {!en |=> `` / `` $stable(cnt)}` ``) come back

2. **Alignment.** A three-column table with `align=[":---", ":---:",
   "---:"]` and widths that force wrapping in the header and the body:
   pandoc reads `AlignLeft`, `AlignCenter`, `AlignRight`, and the header
   is one row.
3. **`tables.read`.** Still correct on the one table it reads,

   `sva-forms` passes its cross-check). On a wrapped table it returns one

## N. Non-blocking findings

**N1. Wrapping can change a cell's meaning in four ways, and nothing
checks it.** `common/tables.py:55-60` and `:95` (the lines a wrapped cell
is cut into). A continuation line is Markdown in its own right, so:

- a line that begins with `: ` turns the line above into a definition-list
  term (`wordwordw : i` at width 9 gives a `DefinitionList`);
- a line made only of `-` or `=` (a lone `-`, `--`, `---`, `=` that lands at
  a break, e.g. `aaaa - bbbbbbbbb` at width 4) turns the line above into a
  setext heading;
- a line that ends with `\` (a backslash word before a break) becomes a hard
  line break;
- a run of two or more spaces at a break is dropped, so `` `a  b` `` cut
  there renders as `a b`: the docstring's "joined again with a space, which
  is what it held" is true only of single spaces. (A lone `*` at a break
  can also open emphasis.)

The committed `tbl-shell.md` has none of these (E2.1), so no printed table
is wrong today. But the third column is tool output, and a message like
`expected 1 - got 0` or `name : value` at a different InFormal commit
would silently give a heading or a definition list in the book, and
`make run` would pass. Fix: in `write`, after wrapping, assert that no
continuation line starts with `: ` or matches `^[-=]+$`, that no line ends
with `\`, and that `" ".join(lines) == cell` (which also catches lost
double spaces); or wrap with a splitter that never breaks before such a
token. This is round 2's N4 (nothing checks a generated table) for the new
code path.

**N2. One command token is still wider than its column, by estimate.**
`shell-commands/commands.py:132`, `widths=[30, 24, 40]` gives the command
column `0.3173` of the width in LaTeX (was `0.1765` in round 2): about 109
pt, about 22 monospace characters at the book's `Scale=0.82`. The other long
tokens gate 2c listed fit, `informal::set_engines` (21) narrowly; `over-constraint/handshake.sv`
(28 characters, inside a code span, which cannot break) does not and would
run about 30 pt into the next column, as it did with the original equal
widths. Arithmetic, not a render (no TeX here). Fix if a build shows it:
widen the first column (`widths=[34, 22, 38]`) or shorten that path in
`commands.list`.

**N3. `tables.read` splits a wrapped row into fragments.**
`common/tables.py:107-122`: one list per physical `|` line, so on
`tbl-shell.md` it returns 91 lists for 49 rows, with fragments such as
`` `code `` that hold half a code span. No caller reads a wrapped table
today (`sva-forms` reads the ch09 matrix, one line to a cell). Fix: join
the physical lines of a row (append each cut's text to the current row
until the next `+` rule), or state in the docstring that it reads
one-line-per-cell tables only.

**N4. `widths` is silently ignored for a pipe table.**
`common/tables.py:72-77`: `write(..., widths=[...])` without `grid=True`
writes one line to a cell with no warning. Fix: `assert grid or not
widths`.
