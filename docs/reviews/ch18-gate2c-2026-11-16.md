## Blocking findings

**B1. Chapter 9, `examples/ch09-temporal-properties/support-matrix/matrix.md`
line 174 (`tbl-ch09-support-x`, row "obligation pending at `$finish`"): a
backslash still prints inside two code spans, in both columns of the
simulators.** The cells are `` `##[1:\$]` `` and `` `\$finish` ``. pandoc

`\texttt{\textbackslash{}\$finish}`, `\texttt{\#\#{[}1:\textbackslash{}\${]}}`

`matrix.py` `cell()` (line 372) runs `why.replace("$", "\\$")` over the whole
cell, code spans included; the cell text comes from line 197

rewrote; the draft log (section 8, "Final checks") states that the only
`\textbackslash{}` left in ch18 and ch09 are shell line continuations, which
is not so for this included file. Pre-existing (the old pipe table has the
same two cells), so the content is otherwise unchanged by the conversion.
Fix: escape `$` only outside backtick spans in `cell()` (split on
`` ` ``, escape even-numbered pieces), regenerate, and convert once more.
Chapter 9 is an earlier chapter: record it for the author as the escalation
rule asks, together with B10's ch09 changes.

**B2. Line 403, the lasso Definition: "`b` holds in no later cycle of the
stem" excludes the cycle in which `a` holds.** In `a |-> s_eventually b`
the consequent starts in the cycle where the antecedent matches, so a lasso
with `a` and `b` in the same stem cycle, and `b` nowhere after, satisfies the
property; the Definition, which says "false exactly when", calls it a
violation. (The chapter's own property cannot show this, since `gnt` and
`n == 0` never coincide, but the Definition is stated for the general form.)
Fix: "`b` holds neither in that cycle nor in any later cycle of the stem, and
in no cycle of the loop".

**B3. `examples/ch18-formal-property-verification/shell-commands/tbl-shell.md`
(`tbl-ch18-shell`): the grid conversion narrowed the command column in LaTeX
from 33% to 17.65%, and its code no longer fits.** A grid table's LaTeX
widths follow its source widths: pandoc writes `p{(\columnwidth -
4\tabcolsep) * \real{0.1765}}`, `0.2096`, `0.6103`, because one cell of the
third column is 165 characters long. On the book's page (7 in wide, inner

`informal::set_engines` (21), `informal::session`, `get_design_info`,
`set_engine_mode`, `bmc-depth/deep.sv`, `over-constraint/handshake.sv` (28),
and others. A `p` column does not clip, so each overprints the "What it is
for" text beside it. With the old equal widths only the 28-character path
overflowed. The estimate is arithmetic, not a render (no TeX here): confirm
on `scripts/build-book.sh` output, and if no overprint appears, downgrade.
Fix: have `common/tables.py` wrap long cells over several lines of the grid
row (grid cells may span lines) to a target width, or emit Quarto's
