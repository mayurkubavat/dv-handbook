**Verdict: blocking findings remain.**

Headline, answering question (1):

* **A register's asynchronous *load value* is not a clock dependency.**
  `clock_deps` now follows a register's `CLK` and every pin in
  `RESET_PINS` marked asynchronous (`tools/dvh/clocks.py:174-177`), and
  `ALOAD` is among them -- but the value loaded, `AD`, is not. A `$aldff`
  whose `AD` is clk2 follows clk2 transparently while its load is high, so
  its output is clk2 for as long as the load lasts; the tool reads it as
  depending on clk1 alone, calls it control at `clk1 & flag`, and exits 0
  with both clocks declared. §1.1. One design.
* **A multiply-driven net keeps one driver.** `Module.finish`
  (`tools/dvh/design.py:71-76`) fills `drivers[bit]` in a loop, so the last
  cell written wins and every other driver of that net is invisible to
  every walk. A clock built from two tri-state drivers -- `sel ? clk2 :
  'z` and `sel ? 'z : clk1` on one wire, which Yosys leaves as two `$mux`
  cells driving one bit -- is walked through whichever `$mux` the JSON
  listed last. With clk1's last, the multiplexer is "clk1 gated by sel" and
  the eight-bit crossing onto it exits 0, declared. With the assignments
  swapped it is "clk2" and exits 1 for the wrong reason (§1.2): the answer
  depends on the order of two `assign` statements. Undeclared it is
  undecided and exits 1 either way. One design, two orderings.

Both are pins or nets the definition does not enumerate, which is the
pattern of every round since `gate2g`. Neither escapes undeclared.

Every design quoted in `gate2i` was re-created and re-run (§2). Its two
blocking findings and the serious findings on recursion and the
hidden-clock defense are fixed; details there.

## 1. Blocking

### 1.1 A register's asynchronous load value is not a clock dependency

`clock_deps` at a register (`tools/dvh/clocks.py:168-178`):

```python
if cell.type in DFF_TYPES:
    if through_registers:
        stack += cell.conns.get("CLK", [])
        for pin, _, kind in RESET_PINS:
            if kind.startswith("asynchronous"):
                stack += cell.conns.get(pin, [])
        continue
```

`RESET_PINS` (`:454-458`) lists `CLR`, `ARST`, `SET`, `ALOAD`, `SRST`. For
`$aldff`/`$aldffe` the pin that carries the *value* is `AD`, and while
`ALOAD` is asserted `Q` follows `AD` combinationally (the Yosys cell is a
flip-flop with an asynchronous load, i.e. a latch on `AD` while loading).
`AD` is on no list, so a clock on it is never seen.

```systemverilog
// aldffad.sv -- a register clocked by clk1 whose asynchronous *load value*
// is clk2: while ld is high, flag follows clk2 transparently. Its output
// gates clk1. Both clocks are ports, drive clock pins, and are declared.
module aldffad (input logic clk1, clk2, ld, input logic [7:0] d,
                output logic [7:0] q, output logic t);
  logic flag, gclk, tog;
  logic [7:0] a, b;
  always_ff @(posedge clk1 or posedge ld)
    if (ld) flag <= clk2; else flag <= 1'b0;
  assign gclk = clk1 & flag;
  always_ff @(posedge clk1) a <= d;
  always_ff @(posedge gclk) b <= a;
  always_ff @(posedge clk2) tog <= ~tog;
  assign q = b;
  assign t = tog;
endmodule
```

Yosys makes `flag` a `$aldff {'AD': [3], 'ALOAD': [4], 'CLK': [2], 'D':
['0']}` -- bit 3 is `clk2`, bit 4 is `ld`, bit 2 is `clk1` (confirmed by
dumping the JSON the tool reads).

```
$ dvh read aldffad aldffad.sv --clock clk1 --clock clk2
clock domains: 3
  clk1#2: 2 registers
  clk1#23: 1 registers
  clk2: 1 registers
ports treated as gating control: clk1, ld
registers without reset: 4
crossings: 1, shape not recognized: 1, 1 of them one clock gated differently
  CHECK a (clk1#2) -> b (clk1#23), 8 bits, no synchronizer shape
         [aldffad.sv:12]
instances: 0, connections: 0
exit 0
```

From the `--validate`d clock tree:

```
"flag": {"clock_sources": ["clk1"], "gated_or_muxed": false, "through": [],
         "clock_ambiguous": false, "root_bits": ["2"], "domain": "clk1#2"}
"b":    {"clock_sources": ["clk1"], "gated_or_muxed": true,
         "through": ["$and", "gated by flag"], "clock_ambiguous": false,
         "root_bits": ["2"], "domain": "clk1#23"}
"ports_treated_as_control": ["clk1", "ld"]
```

With `ld` high, `gclk = clk1 & clk2`, the blend of `gate2h` §1.1 and
`gate2i` §1.2 by one more pin. Undeclared: `undecided clock of b`, exit 1.

Two things in that report are worth noting beyond the exit code. The
"ports treated as gating control" line names `clk1`, a *declared* clock,
because a demoted register is reported by the ports that clock it
(`clocks.py:429-439`) and `flag` is clocked by clk1; the chapter at `:242`
says "a reader who finds a clock in that list has found the declaration's
mistake", and here a reader finds a clock in that list and the declaration
is complete. That is §4.1. And the list does *not* name `clk2`, the port
on the pin that matters, because `AD` is not among the pins walked at
`:434-435` either.

**Fix.** In `clock_deps`, a `$aldff`/`$aldffe` depends on `AD` as well as
`ALOAD` -- the load is transparent, so the value pin is as much an edge
source as the enable. The same pins should be walked in `clock_tree`'s
demoted-register report. `$dffsr`'s `SET`/`CLR` carry constants and need
no change (§5: `dffsr.sv` fails correctly). Fixture: `aldffad.sv`.

### 1.2 A multiply-driven net keeps one driver, so a tri-state clock multiplexer is read as one of its two drivers

`Module.finish` (`tools/dvh/design.py:71-76`):

```python
for cname, cell in self.cells.items():
    for port, bits in cell.conns.items():
        if cell.dirs.get(port) == "output":
            for b in bits:
                if isinstance(b, int):
                    self.drivers[b] = (cname, port)
```

`drivers` is `bit -> (cell, port)`; a second driver overwrites the first.
Yosys does not merge two continuous assignments with `'z` into one cell
(there is no `tribuf` pass in `design.py:120-138`'s script), so a
tri-state clock select arrives as two `$mux` cells driving one bit, and
the walks see whichever one the JSON listed last.

```systemverilog
// tribuf.sv -- a clock chosen by two tri-state drivers on one net.
module tribuf (input logic clk1, clk2, sel, input logic [7:0] d,
               output logic [7:0] q, output logic t);
  wire mclk;
  logic tog;
  logic [7:0] a, b;
  assign mclk = sel ? clk2 : 1'bz;
  assign mclk = sel ? 1'bz : clk1;
  always_ff @(posedge clk1) a <= d;
  always_ff @(posedge mclk) b <= a;
  always_ff @(posedge clk2) tog <= ~tog;
  assign q = b;
  assign t = tog;
endmodule
```

The cells Yosys emits for `mclk` (bit 23), from the JSON the tool reads:

```
$mux {'A': ['z'], 'B': [3], 'S': [4], 'Y': [23]}     # sel ? clk2 : z
$mux {'A': [2], 'B': ['z'], 'S': [4], 'Y': [23]}     # sel ? z : clk1
```

```
$ dvh read tribuf tribuf.sv --clock clk1 --clock clk2
clock domains: 3
  clk1#2: 1 registers
  clk1#23: 1 registers
  clk2: 1 registers
ports treated as gating control: sel
registers without reset: 3
crossings: 1, shape not recognized: 1, 1 of them one clock gated differently
  CHECK a (clk1#2) -> b (clk1#23), 8 bits, no synchronizer shape
         [tribuf.sv:10]
instances: 0, connections: 0
exit 0
```

```
"b": {"clock_sources": ["clk1"], "gated_or_muxed": true,
      "through": ["$mux", "gated by const z", "gated by sel", "mux"],
      "clock_ambiguous": false, "root_bits": ["2"], "domain": "clk1#23"}
```

`through` records one `$mux`, `sel` and the constant `z`; clk2 left no
trace because the cell carrying it was never a driver. Swap the two
`assign` lines (`tribuf2.sv`, identical otherwise) and the same design
reports `CHECK a (clk1) -> b (clk2#23)`, exit 1 -- a finding, but with
`b` in clk2's domain and clk1 nowhere, so the report is wrong in both
orderings and right in neither. Undeclared, both orderings are
`undecided clock of b`, exit 1, because `const z` and the clock differ.

A wired-OR (`wor mclk; assign mclk = clk1; assign mclk = clk2;`) is *not*
affected: Yosys resolves it to one `$reduce_or` and the tool reports
`b (clk1+clk2)`, exit 1 (`wor.sv`, §5). The defect is specific to nets
Yosys leaves with several drivers, of which tri-state is the ordinary case.

**Fix.** Make `drivers` one-to-many, or detect the collision in `finish`
and raise `DesignError` ("net `mclk` has 2 drivers") -- the three-way exit
contract already has the code for "could not answer", and a multiply-driven
clock is exactly a design the tool should refuse to pass in silence.
Alternatively add `tribuf` to the Yosys script so tri-state pairs become
one `$tribuf` cell, then treat `$tribuf` as a multiplexer whose `EN` is a
select. Either way the walk has to see both drivers. Fixture: `tribuf.sv`
and `tribuf2.sv` (both orderings, so the order dependence stays caught).

## 3. Serious (not blocking, but they belong in the next patch)

### 3.1 The control-port list names declared clocks, so a clock in it no longer means a mistake

`clock_tree` (`clocks.py:428-439`) reports a demoted *register* by every
port that clocks it, so that a hidden clock reaching a gate through a
register is named (that is what fixed `gate2i` §3.1, and `hidreg.sv` now
lists `hclk`). But it lists every such port, declared or not:

```
$ dvh read gatedreg gatedreg.sv --clock clk        # clk & en, en a clk register
clock domains: 2
ports treated as gating control: clk
...
crossings: 1, shape not recognized: 1, 1 of them one clock gated differently
exit 0
```

That is the textbook clock gate with a registered enable, the declaration
is complete and correct, the run passes -- and the list names the one
clock the design has. The chapter's sentence at `:242` ("a reader who finds
a clock in that list has found the declaration's mistake") is now false in
the direction that matters: a reader following it would go looking for a
mistake that is not there, and after a few such runs would stop reading the
list. The same appears on `dffe.sv` and `aldffad.sv` (`clk1` listed with a
complete declaration) and, undeclared, on `asyncset.sv` (`clk1, clk2`).

**Fix.** Filter the ports collected from a demoted register's clock walk
against the declaration: a port that *is* declared is not a candidate
hidden clock and should not be listed. Keep the direct case (a demoted
*port*) as it is, since a declared port can only be demoted through the
dependency rule and that is a finding a reader wants. Then add `AD` to the
pins walked at `:434-435` (§1.1) so the list names `clk2` on `aldffad.sv`.

### 3.2 `Module.drivers` silently keeps one driver per net

The cause of §1.2, restated as a tool defect rather than an escape: no
walk in `clocks.py` can see a second driver, because `design.py:71-76`
stores one. That affects the data walks as much as the clock walk (a
tri-state *data* bus driven from two domains is read as driven from one),
though this round did not find a data-side escape that the clock-side one
does not already cover. A `DesignError` on collision is the smallest fix
and is what the three-way exit contract exists for.

## 4. Minor

### 4.1 `$dffe` with a clock on its enable is excused, and that is right, but silently

`dffe.sv` (§5): a `$dffe` clocked by clk1 whose enable is clk2, gating
clk1. Its output changes only on clk1's edge, so "control" is the right
answer and exit 0 is correct. But the register *samples* clk2 as data, and
that port-to-register crossing is reported nowhere, because ports have no
domain. That is the tool's stated scope (the chapter's own design takes its
inputs from ports), and it is worth one sentence at `:251` so a reader does
not expect it.

### 4.2 Three statements of the weak-evidence rule (carried from `gate2i` §4.1)

`clock_candidates` (`clocks.py:60-61`): "an input port". `_tier` (`:204`):
port, register or latch. Chapter `:238`: "an input port or a register's
output". The code's is the right one.

### 4.3 A constant is recorded as gating control (carried from `gate2i` §3.3)

`tribuf.sv`: `"through": [..., "gated by const z", ...]`. A constant is not
control. It no longer saves or sinks any design this round (the select is
classified now), so this is cosmetic.

### 4.4 Trailing whitespace in four fixtures

`tools/dvh/tests/rtl/clock_mux_select_register.sv:6`,
`hidden_clock_via_register.sv:7`, `latch_async_clear.sv:5`,
`clock_mux_select_blackbox.sv:8` each end in a space. None is spliced into
the book.
