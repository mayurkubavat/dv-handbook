## Blocking findings

### D1. A strong obligation still open at `$finish` IS reported by the simulator: "the distinction is moot" is false for `s_until`

`chapters/ch09-temporal-properties.qmd:82` names `s_eventually`, `s_until`
and `strong(...)` as the strong forms, then says: "On the book's simulator
the distinction is moot at the end of a run. An obligation still pending at
`$finish` was reported by neither the weak form nor the strong one ...
nothing is printed. A property that waits for something that never comes is
silent in simulation." Line 297 repeats it: "A concurrent check that has
matched its antecedent and is still waiting for its consequent when the test
ends is dropped without a report." The probes behind those sentences
(`p14_delay_unb.sv`, `p39_s_eventually.sv`) measure `##[1:$]` and
`s_eventually` only, and they count failures in the action block *before*
`$finish`, so a report printed after it would not be seen by them anyway.

Own probe (`su.sv`, in the scratch directory): `a` at tick 12 of 14,
`Su_A: assert property (@(posedge clk) a |-> (1'b1 s_until b))`, `b` never
(or, with `-DGOOD`, at tick 13); `-DWEAK` swaps in `until`. Book flags plus
`--assert -Wno-fatal`, on 5.052 and 5.054 alike:

```
[]            before $finish: s_until action ran 0, until 0
              [136] %Error: su.sv:17: Assertion failed in top
              %Error: su.sv:17: Verilog $stop
              rc=1
[-DGOOD]      rc=0, no message
[-DWEAK]      rc=0, no message        (weak until: silent, as the text says)
```

So Verilator *does* tell strong from weak at the end of a run for `s_until`:
the pending strong obligation is reported after `$finish` (without its label
and without running the action block) and the exit status becomes 1. A
pending `s_eventually` and a pending bounded `##[1:3]` stay silent (also
re-measured, same file family `end.sv`), which agrees with the table. The
sentences generalize from two operators to all strong forms and to every
pending check, and one of the three forms the paragraph itself names
contradicts them.

Fix: restrict the claim to what was measured ("a pending `s_eventually` and
a pending `##[1:$]` were reported by neither ..."), state the `s_until` case
(reported after `$finish`, unlabeled, exit status 1, action block not run),
and add an `s_until`-pending row to `probes.txt` whose runner also reads the
output after `$finish` and the exit status. Line 297's "dropped without a
report" needs the same restriction.

## Non-blocking findings

### M1. Two run scripts do not check the cover counts the prose reads from them

`bounded-response/run_response.sh` checks only the failure counts; the
chapter (line 180) draws a conclusion from `Waited_C` reading 0 on the slow
responder and 2 on the correct one. `handshake/run_handshake.sh` checks the
total of five failures but not `Waited_C=5`, which line 148 explains.
Mutation: `Waited_C ... disable iff (1'b1)` (cover never counts):
`bounded-response -> pass` (`response-formal` does fail: "Waited_C is
unreachable, expected covered"). The changed counts would show as a diff of
the tracked `run.out`, so the mistake is visible, which is why this is not
blocking. Fix: `need` lines for `Waited_C=0` / `Waited_C=[1-9]` and for
`Waited_C=5`, and for the handshake, the failing label at each tick (the
verdict "only the rule with no reset term failed at the reset" is not
itself tested).

### M2. `expect` treats the name it is given as a glob pattern

`examples/mk/informal.tcl:19` `[string match "*.$want" $full]`. A suffix
with a generate index is a bracket expression to `string match`. Own design
(`three`, `for ... begin : g`, instance `g[1].u` bad):

```
expect cex g\[1\].u.Same_A  ->  unexpected: g[1].u.Same_A is missing, rc 1
expect proven three.g\[0\].u.Same_A three.g\[2\].u.Same_A   ->  rc 0
expect proven Same_A        ->  unexpected: three.g[1].u.Same_A is cex, rc 1
expect proven ame_A         ->  missing, rc 1  (no partial-label match)
```

It fails closed today (a full name works; a bracketed suffix is "missing"),
but a pattern such as `g[01].u.X_A` would select a different set from the one
written. Fix: compare literally, e.g. `[string equal -length ... ]` on the
tail, or `[string range $full end-[string length $want] end] eq ".$want"`.
