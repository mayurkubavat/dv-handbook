**Verdict: blocking findings remain.**

Headline, answering question (1):

* **Under a complete and correct declaration, a clock the netlist cannot
  follow is control.** `clock_deps` (`tools/dvh/clocks.py:105-157`) answers
  "which declared clocks does this net depend on", and its docstring says in
  terms what happens to everything else: "an undeclared port, a black box, a
  constant -- depends on nothing" (`:116-118`). A black-box output, a clock
  that has passed through a black-box buffer, and a clock that has passed
  through any combinational cell outside `PASS_THROUGH` all depend on
  nothing, so at a gate each is "synchronous control", the gated register
  lands on the other clock's net, `same_clock_source` is true, and the build
  passes on an eight-bit unsynchronized crossing. Exit 0 with every
  declarable clock declared; the black-box clock *cannot* be declared,
  because `--clock` is checked against the top module's ports. §1.1. Four
  designs, each ordinary RTL: a PLL output, a clock buffer cell, a
  polarity-select XNOR, and a divider gated by a PLL clock.
* **The vector-port lesson the chapter tells at `:300` reappears inside
  `clock_deps`.** Dependencies are sets of port *names* (`clocks.py:141-142`),
  so two lane clocks on `input logic [1:0] lane_clk` are one clock to the
  definition, and a divider of lane 1 gating lane 0 is "a divider of the
  same clock". Exit 0 with `--clock lane_clk`, the only declaration the
  tool accepts for that port. §1.2.
* **A latch whose asynchronous clear comes from another domain is not a
  crossing at all: `"crossings": []`, exit 0, declared or not.**
  `_latch_crossings` hand-writes the pins it reads (`D`, `AD`, `EN`;
  `clocks.py:642-647`), which is the practice `_data_inputs` (`:443-455`)
  exists to forbid. The same clear on a flip-flop is reported. §1.3.
* **Two one-bit chains carrying one value are both `known`** when one
  sender is clocked through a black-box buffer, because the buffer output
  has no identity and the boundary rule splits on it. §1.1, second
  consequence.

Sentences the chapter prints about the tool that are false of the code are
collected in §1.4, with line numbers.

The previous round's five blocking and six serious findings were all
re-created and re-run (§2). All five blocking findings are fixed. Five of
the six serious ones are fixed; the deep clock cone (`gate2g` §3.1) still
ends in `RecursionError`, and the new declared walk adds a second recursion
path of its own (§3.1).

## 1. Blocking

### 1.1 A clock the netlist cannot follow depends on nothing, so it is control

`_walk_to_sources`, declared branch (`tools/dvh/clocks.py:244-265`):

```python
direct = {(p, b): clock_deps(mod, b, declared, {}, False) for (p, b) in ins}
have = frozenset().union(*direct.values())
if have:
    carrying = [(p, b) for (p, b) in ins
                if direct[(p, b)]
                or not clock_deps(mod, b, declared) <= have]
```

An input whose full dependency set is a subset of `have` is control. The
empty set is a subset of everything, and `clock_deps` returns the empty set
for any net whose driver is not a declared port, a `DFF_TYPES` cell, a
`PASS_THROUGH` cell or a latch (`clocks.py:141-155`). That is: a black-box
output, and the output of any combinational cell the pass-through set does
not list.

The chapter defines a primary clock as "a primary input of the design or the
output of an analog block such as a phase-locked loop treated as a black
box" (`chapters/ch03-digital-design-for-verifiers.qmd:56`). The declared
definition makes the second kind of primary clock an enable.

**(a) A PLL output blended with a port clock.**

```systemverilog
// bbblend.sv -- Plassan's blending, with the second clock the output of a
// black box: a PLL the netlist cannot see into. pclk is a primary clock by
// the chapter's own definition (@sec-ch03-clocks: "the output of an analog
// block such as a phase-locked loop treated as a black box"). It is not a
// port, so it cannot be declared with --clock, and `clock_deps` says it
// depends on no declared clock.
(* blackbox *)
module pll (input logic ref_clk, output logic clk_out);
endmodule

module bbblend (input logic clk1, ref_clk, input logic [7:0] d,
                output logic [7:0] q, output logic t);
  logic pclk, gclk, tog;
  logic [7:0] a, b;
  pll u_pll (.ref_clk(ref_clk), .clk_out(pclk));
  always_ff @(posedge clk1) a <= d;        // clk1 domain
  assign gclk = clk1 & pclk;               // blend clk1 with the PLL clock
  always_ff @(posedge gclk) b <= a;        // 8 bits, no synchronizer
  always_ff @(posedge pclk) tog <= ~tog;   // pclk is a clock elsewhere too
  assign q = b;
  assign t = tog;
endmodule
```

`pclk` clocks a register of its own, so the report itself lists it as a
domain. Undeclared, the tool is right:

```

        distinguishable here; declare the clocks
         [bbblend.sv:18]

```

It says to declare the clocks. The only clock port is `clk1`, and
`clock_ports` (`clocks.py:93-102`) agrees, so `--clock clk1` is a complete
declaration by the tool's own check:

```

  clk1#2: 1 registers
  clk1#22: 1 registers
  pclk (driven by pll): 1 registers
...
```

```
{"to": "b", "from": "a", "width": 8, "direct": true, "second_stage": [],
```

There is no declaration under which this design fails. Following the
report's own advice turns a correct answer into a wrong one.

**(b) Both clocks are ports, both are declared, and one passes through a
clock buffer.** This is the stronger form, because the declaration is
complete and correct by any reading, and a black-box clock buffer is how a
clock is distributed in every technology library.

```systemverilog
// bufblend.sv -- both clocks are ports and both are declared. clk2 reaches
// the blend through a black-box clock buffer, the ordinary way a clock is
// distributed in a technology library. The buffer's output depends on no
// declared clock, so the blend is one clock gated.
(* blackbox *)
module CLKBUF (input logic I, output logic O);
endmodule

module bufblend (input logic clk1, clk2, input logic [7:0] d,
                 output logic [7:0] q, output logic t);
  logic clk2_buf, gclk, tog;
  logic [7:0] a, b;
  CLKBUF u_buf (.I(clk2), .O(clk2_buf));
  always_ff @(posedge clk1) a <= d;          // clk1 domain
  assign gclk = clk1 & clk2_buf;             // blend clk1 with clk2
  always_ff @(posedge gclk) b <= a;          // 8 bits, no synchronizer
  always_ff @(posedge clk2_buf) tog <= ~tog; // clk2_buf clocks registers
  assign q = b;
  assign t = tog;
endmodule
```

```
  clk1#22: 1 registers
```

`b`'s entry: `"through": ["$and", "gated by clk2_buf"]`,
`"clock_ambiguous": false`, `"root_bits": ["2"]`; the crossing has

**(c) A clock through a combinational cell outside `PASS_THROUGH`.** The
set at `clocks.py:25-27` lists nineteen types. Yosys emits `$xnor` for `~^`,
which is not among them:

```systemverilog
// xnorclk.sv -- clk2 reaches the blend through a cell that is not in the
// pass-through set (an XNOR, written `~^`). Both clocks are ports, both
// declared.
module xnorclk (input logic clk1, clk2, pol, input logic [7:0] d,
                output logic [7:0] q, output logic t);
  logic clk2p, gclk, tog;
  logic [7:0] a, b;
  assign clk2p = clk2 ~^ pol;             // polarity-selectable clk2
  assign gclk  = clk1 & clk2p;            // blend
  always_ff @(posedge clk1) a <= d;
  always_ff @(posedge gclk) b <= a;
  always_ff @(posedge clk2p) tog <= ~tog; // clk2p clocks registers
  assign q = b;
  assign t = tog;
endmodule
```

```
$ dvh read xnorclk xnorclk.sv --clock clk1 --clock clk2

  clk1#2: 1 registers
  clk1#23: 1 registers
  clk2p (driven by $xnor): 1 registers
```

Undeclared: `undecided clock of b`, exit 1. The same design with `^`
instead of `~^` is a `$xor`, which is in the set, and fails correctly. A
gate's answer depends on which spelling of the same function the designer
chose.

**(d) The other branch.** Where no input reaches a clock through logic
alone (`clocks.py:255-261`), an input with no dependencies is dropped
without the `ambiguous` mark, so a divider gated by a black-box clock is
"one clock gated differently" too:

```systemverilog
// divbb.sv -- a divider of clk1 gated by a black-box clock. No input of the
// gate reaches a declared clock through logic alone.
(* blackbox *)
module pll (input logic ref_clk, output logic clk_out);
endmodule
module divbb (input logic clk1, ref_clk, input logic [7:0] d,
              output logic [7:0] q);
  logic div, pclk, gclk;
  logic [7:0] c, b;
  pll u_pll (.ref_clk(ref_clk), .clk_out(pclk));
  always_ff @(posedge clk1) div <= ~div;
  assign gclk = div & pclk;
  always_ff @(posedge div)  c <= d;     // divider domain
  always_ff @(posedge gclk) b <= c;     // divider blended with the PLL clock
  assign q = b;
endmodule
```

```
$ dvh read divbb divbb.sv --clock clk1
crossings: 1, shape not recognized: 1, 1 of them one clock gated differently
  CHECK c (div#20) -> b (div#22), 8 bits, no synchronizer shape
exit 0
```

**(e) Second consequence: the per-bit rule splits on the same identity
loss.** `boundary` (`clocks.py:563-566`) groups chains by the pair of
root-bit sets. A sender clocked through a buffer has a root of its own:

```systemverilog
// bufchain.sv -- two one-bit chains carrying one two-bit value. One sender
// is clocked by aclk and the other by aclk through a black-box clock buffer.
(* blackbox *)
module CLKBUF (input logic I, output logic O);
endmodule

module bufchain (input logic aclk, bclk, input logic d0, d1,
                 output logic o0, o1);
  logic aclk_b, a0, a1, p0, p1, r0, r1;
  CLKBUF u_buf (.I(aclk), .O(aclk_b));
  always_ff @(posedge aclk)   a0 <= d0;
  always_ff @(posedge aclk_b) a1 <= d1;
  always_ff @(posedge bclk) begin p0 <= a0; p1 <= a1; end
  always_ff @(posedge bclk) begin r0 <= p0; r1 <= p1; end
  assign o0 = r0;
  assign o1 = r1;
endmodule
```

```
$ dvh read bufchain bufchain.sv --clock aclk --clock bclk
crossings: 2, shape not recognized: 0
  known a0 (aclk) -> p0 (bclk), 1 bit, two-flop synchronizer
  known a1 (aclk_b (driven by CLKBUF)) -> p1 (bclk), 1 bit, two-flop
        synchronizer
exit 0
```

Identical, exit 0, undeclared. The rule as the chapter states it at `:257`
("the same pair of clock *nets*") is honored: the netlist has two sending
nets. The finding is that the tool does not know whether `aclk_b` is
`aclk`, and reports `known` rather than saying so; `:244` says a tool a
build gate trusts "must fail loudly when it does not know". It is graded
with §1.1 because it has the same cause and the same fix.

**This falsifies printed sentences.** `:242`: "the crossing onto a blended
or multiplexed clock still fails, because it is still a crossing" — four
designs above are blends and exit 0. `:298`: "Where they do not, as with a
divider or a multiplexer between two clocks, it does fail" — `divbb.sv` is
a divider between two clocks, exit 0. `:56`'s definition of a primary clock
includes the black-box output that `clock_deps` calls control. The schema's
`same_clock_source` description, "Both clocks resolved to one net,
declaration given" (`tools/dvh/schema/crossings.schema.json`), is false of
every design above: one of the two clocks was discarded, not resolved.

**Fix.** Two parts.

1. In `clock_deps`, a net whose driver the walk cannot follow — a cell
   outside `PASS_THROUGH`, `DFF_TYPES` and `LATCH_TYPES`, which includes
   every black box — must not depend on *nothing*. Give it an identity of
   its own (the net, or the cell output it comes from) and return that as
   a dependency. Then `clk1 & pclk` has two inputs with disjoint
   dependencies, both are carried, and the register has two roots. The
   `_tier` walk already does exactly this for the undeclared case
   (`kind == "unknown"` scores as strong, `clocks.py:167`); the declared
   definition regressed it.
2. Let `--clock` name a net that is not a port — a black-box output, or a
   buffered copy — and let a declaration say two names are one clock
   (`--clock aclk=aclk_b`, or a `--same-clock` pair). Without that, a
   design whose clocks come from a PLL has no declaration that is both
   accepted and correct, and `bufchain.sv` has no fix at all. The
   completeness check (`cli.py:166-172`) should then also refuse a
   declaration that leaves out an opaque net driving a clock pin.

Fixtures: `bbblend.sv`, `bufblend.sv`, `xnorclk.sv`, `divbb.sv`,
`bufchain.sv`.

### 1.2 `clock_deps` compares port names, so a vector clock port is one clock

`clock_deps` adds `mod.port_of_bit[b]` — a port *name* — to the dependency
set (`clocks.py:141-142`). Every bit of a vector port has that name. The
chapter's Future Directions box tells this exact story about an earlier
version (`:300`: "A check written against names found one clock in each of
those, called the crossing between the lanes a gated clock, and passed the
build on an eight-bit unsynchronized path between two unrelated clocks")
and says "That the test is the net and not the source *name* is the whole
of it".

```systemverilog
// vecdiv.sv -- two lanes, one clock each, on one vector port. A divider of
// lane 1's clock gates lane 0's clock. `--clock lane_clk` is the only
// declaration the tool accepts for this port, and `clock_deps` answers by
// port *name*, so a divider of lane_clk[1] is "a divider of the same clock"
// as lane_clk[0].
module vecdiv (input logic [1:0] lane_clk, input logic [7:0] d,
               output logic [7:0] q);
  logic div1, gclk;
  logic [7:0] a, b;
  always_ff @(posedge lane_clk[1]) div1 <= ~div1;   // lane 1 divider
  assign gclk = lane_clk[0] & div1;                 // blend lane 0 with it
  always_ff @(posedge lane_clk[0]) a <= d;          // lane 0 domain
  always_ff @(posedge gclk) b <= a;                 // 8 bits, no sync
  assign q = b;
endmodule
```

```
$ dvh read vecdiv vecdiv.sv
  CHECK a (lane_clk#2) -> b (undecided clock of b), 8 bits, clock and enable
        not distinguishable here; declare the clocks
exit 1

$ dvh read vecdiv vecdiv.sv --clock lane_clk
clock domains: 3
  lane_clk#2: 1 registers
  lane_clk#21: 1 registers
  lane_clk#3: 1 registers
...
crossings: 1, shape not recognized: 1, 1 of them one clock gated differently
  CHECK a (lane_clk#2) -> b (lane_clk#21), 8 bits, no synchronizer shape
         [vecdiv.sv:13]
exit 0
```

`b`: `"through": ["$and", "gated by div1"]`, `"clock_ambiguous": false`,
`"root_bits": ["2"]`. At the gate, `direct[lane_clk[0]] = {"lane_clk"}`,
and `div1`'s full dependency is `{"lane_clk"}` through the register on
`lane_clk[1]`, which is a subset of `have`, so `div1` is control.

**Fix.** `clock_deps` must return port *bits*, not names, exactly as
`root_bits` and `_domain_key` already do (`clocks.py:324-327`, `:354`).
`declared` then has to be resolved from names to the set of bits those
ports carry, once, in `clock_candidates`. Fixture: `vecdiv.sv`.

### 1.3 A latch with an asynchronous clear from another domain is not a crossing

`_latch_crossings` (`clocks.py:625-662`) reads the enable from `EN`
(`:642`) and the data from `D` and `AD` (`:646`). Yosys builds
`always_latch if (clr) q <= '0; else if (en) q <= da;` as an `$adlatch`,
whose clear arrives on `ARST`. Nothing reads `ARST`, `SET` or `CLR` on a
latch. `_data_inputs` (`clocks.py:443-455`) was written so that no list of
pins is hand-written — "a hand-written list is wrong the first time the
netlist produces a cell the list did not anticipate. Two separate crossings
went unreported that way" — and `_latch_crossings` hand-writes one.

```systemverilog
// latchar.sv -- a latch with an asynchronous clear from another domain.
module latchar (input logic aclk, bclk, input logic [7:0] d, input logic e,
                output logic [7:0] q);
  logic [7:0] da;
  logic en, clr;
  always_ff @(posedge aclk) begin da <= d; en <= e; end
  always_ff @(posedge bclk) clr <= ~e;
  always_latch if (clr) q <= '0; else if (en) q <= da;
  // q is captured under aclk timing, cleared under bclk timing
endmodule
```

The netlist, from the tool's own Yosys script:

```
$adlatch {'ARST': ['clr'], 'D': ['da' x8], 'EN': ['en'], 'Q': ['q' x8]}
$dff     {'CLK': ['bclk'], 'D': [...], 'Q': ['clr']}
$dff     {'CLK': ['aclk'], 'D': ['d' x8], 'Q': ['da' x8]}
$dff     {'CLK': ['aclk'], 'D': ['e'], 'Q': ['en']}
```

```
$ dvh read latchar latchar.sv
clock domains: 2
  aclk: 2 registers
  bclk: 1 registers
registers without reset: 3
crossings: 0, shape not recognized: 0
exit 0
$ dvh crossings latchar latchar.sv --clock aclk --clock bclk --validate
{ "crossings": [], "unrecognized": [] }
```

Exit 0 declared as well. The same clear on a flip-flop is reported, because
for a flip-flop every input but `CLK` is a data input:

```systemverilog
// flopar.sv -- latchar.sv with the latch replaced by a flip-flop: the same
// asynchronous clear from a bclk register, on an aclk-domain element.
module flopar (input logic aclk, bclk, input logic [7:0] d, input logic e,
               output logic [7:0] q);
  logic [7:0] da;
  logic clr;
  always_ff @(posedge aclk) da <= d;
  always_ff @(posedge bclk) clr <= ~e;
  always_ff @(posedge aclk or posedge clr) if (clr) q <= '0; else q <= da;
endmodule
```

```
$ dvh read flopar flopar.sv
crossings: 1, shape not recognized: 1
  CHECK clr (bclk) -> q (aclk), 8 bits, no synchronizer shape
exit 1
```

The tool reports the flip-flop's clear as an eight-bit crossing and the
latch's as nothing. This is narrower than `gate2g` §1.3 — the *data* into
the latch is synchronous here, and the crossing is the control — but it is
a crossing between two asynchronous clocks that produces `"crossings": []`,
and `clocks.py:685`, printed at `:246`, says "Nothing is ever suppressed".
`:291`'s taxonomy names the previous latch route ("a crossing whose
destination was a latch rather than a flip-flop was never constructed")
and does not cover this one.

**Fix.** In `_latch_crossings`, take the data pins from `_data_inputs(cell)`
minus `EN`, so that `ARST`, `AD`, `SET` and `CLR` are all examined, and
report a source on any of them that is in a domain other than the enable's.
Fixture: `latchar.sv`.
