## Non-blocking findings

N1. **Two printed results that prose quotes are still not pinned.**
`dpll/run_dpll.py:56-66` and `cdcl/run_cdcl.py:136-143` assert only that the
buggy miter is satisfiable. Mutation: `dpll.py:78-79` decides false first
(the docstring, the comment and the chapter say true first). `make run`
passes in `dpll`, `cdcl`, `hard` and `solver-selftest`, and prints

```
   N = 4: SATISFIABLE after 8 decisions; the adders differ at a = 0, b = 8
   N = 8: SATISFIABLE after 16 decisions; the adders differ at a = 0, b = 128
   N =  8: dpll.py 16 decisions and 1 conflicts; cdcl.py 23 and 15
```

against the committed `dpll/run.out:24-25`, `cdcl/run.out:48-49` and the
sentence "at eight bits that takes 263 decisions" (qmd:149). The mutant is a
correct solver and the checker would rewrite `run.out`, so this is drift, not
a false pass; it is the remainder of round 1's N1. (Pigeonhole is symmetric
under the flip: 51, 374, 3,245 either way, which is why `hard` passes.)
Fix: in `run_dpll.py` assert
`(s.decisions, a, b) == {4: (19, 15, 0), 8: (263, 255, 0)}[n]`; in
`run_cdcl.py` assert the four counts of each row.

N2. **No example gives the solvers an empty clause.** `cdcl/cdcl.py:45-46`
(`if not c: return False`) changed to `return True` passes `cdcl`, `hard`,
`fifo-unroll` and `solver-selftest`. The unmodified solvers are right
(`p cnf 2 2 / 1 2 0 / 0`: all three print `s UNSATISFIABLE`, as CaDiCaL
does; my fuzzer's stream with empty clauses finds the mutant at once). Fix:
one formula with an empty clause in stream 1 of `selftest.py`, or a
two-line check.

N3. **The self-test's limit does not stop every loop.**
`solver-selftest/selftest.py:39` says "a solver that loops fails here; it
does not hang". `LIMIT` counts conflicts; mutant V1 (a `pick` that returns
an assigned variable) decides for ever without a conflict and the example
ran past 400 s. Not a false pass. Fix: reword the comment ("a solver that
keeps meeting conflicts"), or bound decisions as well.

N4. **`bitvector`'s "bits" column is still unpinned** (round 1's N3; a
comment was added, `word_vs_bits.py:50-52`). `Cnf.or_all` without its
`g or not lit` clauses now fails `tseitin`, `dpll`, `cdcl` and `hard`
(round 1's N2 is fixed), but `bitvector` passes with other clause counts.
Fix: assert `len(cnf.clauses)` against 226, 377, 568, 799, 1070 at
`word_vs_bits.py:67`.

N5. **"by a power of two so that no order changes"** (qmd:204) is exact for
the first two rescales only. Each rescale multiplies by 2^-512; an activity
not bumped since before the first rescale is near 2^-1024 after the second,
below the smallest normal double, where low bits are dropped, and would be 0
after the third. Measured with the shipped class on the 8-bit multiplier
miter: 28,766 conflicts, 4 rescales, smallest positive activity 1.17e-308
(subnormal). Only variables the search has not touched for some 14,000
conflicts are affected and no example reaches a second rescale (the largest
count is 7,786, one rescale; the count is the same as before the fix, and
without the bump's rescale it is 7,795). Verdicts and learned clauses stay
right (550 lemmas checked on each of four long runs). Fix: "so that the
order of the variables still in play does not change", or leave it.

N6. **`make clean` still leaves `common/__pycache__`** (round 1's N10).
Ignored by git; cosmetic.
