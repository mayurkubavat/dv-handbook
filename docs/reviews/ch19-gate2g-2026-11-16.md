## Blocking findings

### G-B1. Line 62 (and line 770) says every proved implication in the examples has a cover that runs to the cycle where the consequent is judged; five shipped proofs do not

Line 62, introduced by `5c79eeb`: "First, every implication proved in
an example has a witness cover run under the same assumptions as the
proof ... The cover is the implication's antecedent, or a scenario
whose trace passes through it, and it runs to the last cycle in which
the consequent is judged and to the end of any multi-cycle assumption's
window". Line 770 says the examples' covers are "the antecedent itself,
or a scenario whose trace passes through the antecedent", and then that
"A cover of the antecedent alone is not always enough: the cover must
run to the last cycle in which the assertion's consequent is judged".

Those two sentences together tell the reader that the shipped covers
follow the rule. The following proofs, read from the scripts and the
committed `run.out`, have no cover in their session that runs past the
antecedent's cycle, or (for `a_gnt_once`) past the antecedent itself:

### G-B2. The new assumption-sanity Pitfall (line 793) gives "running to the last cycle the consequent is judged in" as the recipe, and on its own example a cover that meets it is reached while the proof is vacuous

Line 793, edited by `5c79eeb`: "Only the assertion's own witness cover,
under the final assumptions, shows the problem. Write witness covers
per assertion, running to the last cycle the consequent is judged in
(@sec-ch19-witness), and read an unreachable one as a failure of the
proof". Line 62 states the same rule as the definition of the
chapter's witness covers.

The assertion of the `sanity` example is `A_mode {mode && chosen |->
cnt != 4'd9}` (`sanity.tcl:9`), an implication whose consequent is
judged in its antecedent's cycle. By the rule as written, its witness is
the antecedent, `mode && chosen`. Measured under part C's assumption
`M_dead1`, in scratch, `informal-kind`, 5 s:

```
A_mode      assert  proven
Ante_C      cover   covered      depth 2      {mode && chosen}
Witness_C   cover   unreachable                {mode && chosen && cnt == 4'd8}
```

A reader who follows the Pitfall literally writes `Ante_C`, sees it
reached, and accepts the proof that line 790 and the Pitfall itself
call vacuous. `Witness_C` works because it was chosen to reach the case
the assertion exists to check (mode 1 with the counter one step from
9), which is the previous chapter's definition of a witness, "together
with enough of the consequent to show the interesting case occurring"
(@sec-ch18-cover, `ch18-formal-property-verification.qmd:375`), and not
what the new wording says. The cycle rule is necessary, not
sufficient; stated as the recipe, beside this example, it teaches the
mistake the entry exists to prevent. (Round 3's F-N3 noted the
neighboring problem with `Witness_C` itself: an assumption that ends
mode-1 traces at `cnt == 9`, not before, would leave `Witness_C`
reached. That remains non-blocking, N9 below.)

Fix (text only):
- Line 793: "Write a witness cover for each assertion that reaches the
  case the assertion exists to check, here mode 1 with the counter
  about to reach 9, and at least runs to the last cycle the consequent
  is judged in (@sec-ch19-witness); read an unreachable one as a
  failure of the proof, not as a curiosity."
- Line 62 and line 770: make the rule a minimum in the same words: "a
  scenario that passes through the antecedent, reaches the case the
  assertion is about, and runs at least to the last cycle in which the
  consequent is judged and to the end of any multi-cycle assumption's
  window". The sentence at the end of line 770 ("the next entry shows
  that the choice of cover matters") then points at the demonstration.

## Non-blocking findings

**N1. Line 701, "so an assumed lemma removes exactly the traces on
which the other would fail".** Too strong. An assumed lemma removes the
traces on which *it* fails. Those include every failing trace of the
asserted lemma only when the assumed one fails no later on each of
them, as in block E, where both fail on every trace. If the assumed
lemma is true, it removes nothing and a false asserted lemma is
refuted. Fix: "so an assumed lemma can remove the very traces on which
the lemma it helps would fail".

**N2. Line 605, "The assumption names state of the design under proof,
not an input from outside it, so it removes every trace in the cycle
where the other lemma would fail".** The "so" does not follow: block
A's input assumption also removes every trace in the cycle where it
fails. The difference is that an assumption on a free input only
narrows the inputs the engine may choose, while an assumption on state
can contradict a state the design is forced into, and then nothing is
left to choose. "The other lemma" is also ambiguous, since there are
two lemmas and two runs. Suggested: "The assumption names state of the
design under proof. An assumption on an input only narrows what the
engine may choose; one on state can contradict a state the design is
forced into, and it then removes the trace in that cycle. Here the
assumed lemma fails in the same cycle as the asserted one, so every
counterexample is removed with it." The paragraph is now sixteen
sentences long; start a new paragraph at "Block E is the warning".

**N3. Line 605, two claims that no `run.out` shows; both are true.** (a)
"Here that leaves no trace at all": block E's `C_run` (`rst_n &&
$past(rst_n)`) shows only that no trace reaches the second cycle out of
reset. (b) "on a design whose other traces survive the assumption the
cover can still be reached" (and line 701, "a cover is not a reliable
guard"): this follows from the semantics, but the chapter measures
everything else it says about this trap. Measured in scratch on
InFormal `5114330`, `informal-kind`, 5 s:

```

ring of ag blocks, resets 0, out <= in | g
  (g a free input shared by both)
  assert x == 0 alone                           cex depth 2
  assume y == 0, assert x == 0                  proven; C_run covered depth 2; cover {g ##1 1} unreachable
```

the shared-input ring as a third E run (under a second each). Neither
