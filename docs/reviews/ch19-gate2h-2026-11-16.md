## Blocking findings

### B1. The witness-cover rule at `:62` is stated as met by every example, and six examples do not meet it

`chapters/ch19-formal-techniques.qmd:62` (the third sentence: "The
cover is the implication's antecedent, or a scenario whose trace passes
through it, and it runs to the last cycle in which the consequent is
judged and to the end of any multi-cycle assumption's window"), read
with the first sentence ("every implication proved in an example has a
witness cover"). The same rule is restated at `:770` and `:793`.

Every proved implication in the 24 scripts was listed, together with the
covers of its session. These do not meet the rule:

| example, block | proved implication | consequent judged up to | multi-cycle assumption | cover in the session | file:line |
|---|---|---|---|---|---|
| `symmetry` A, B, C | `a_wait0` (A, C), `a_wait0..3` (B): `req[i] && !gnt[i] \|-> ##[1:4] gnt[i]` | +4 | `m_hold$i`, `\|=>`, 2 cycles | `c_wait$i` = the antecedent, ends at +0 | `symmetry/sym.tcl:16-20` |
| `symconst` B | `Slot_A`: `... \|=> u.mem[sa] == $past(wr_data)` | +1 | none (`$stable`) | `c_slot` = the antecedent | `symconst/sc.tcl:22`, `sc_free.sv:21-22` |
| `cut-timer` D | `a_gnt_once`: `gnt \|=> !gnt` | +1 | none (`m_gap` is one cycle) | `c_gnt` = the antecedent | `cut-timer/cut.tcl:33,35` |
| `cut-timer` A, B, C | `a_gnt_once` | +1 | no assumption | `c_gnt` | same |
| `cut-timer` F, real timer | `a_gap2`, `a_gap199`: `req && !busy \|=> !expired [*N]` | +2, +199 | no assumption | `c_req` = the antecedent | `cut-timer/cut.tcl:101-103` |
| `cut-timer` G, real timer | `a_201`: `req && !busy \|-> ##[1:201] gnt` | +201 | no assumption | `c_req` | `cut-timer/cut.tcl:145-147` |
| `two-word` C | `p_ahead`: `in1 && !out1 && in2 && !out2 \|-> a1 < a2` | +0 | none | `c_both` only, whose trace never has both words inside at once (see below) | `two-word/two.tcl:67-77` |

`two-word` C: the trace of `c_both` (depth 3) is push `d1`; push `d2`
and pop `d1` in the same cycle; pop `d2`. Its flags never show `in1 &&
!out1 && in2 && !out2` together, so no cover of the session passes
through `p_ahead`'s antecedent. (It does pass through the antecedents of
`p_head1`, at cycle 2, and `p_head2`, at cycle 3.)

**None of these proofs is vacuous.** Each was checked with the covers
the rule asks for, in scratch copies, under the session's own
assumptions:

```
symmetry A/B/C   req[i] && !gnt[i] ##4 1        covered, depth 5 (all 9)
symconst B       u.do_write && u.wr_ptr == sa ##1 1   covered, depth 2
cut-timer A..D   gnt ##1 1                      covered, 203 / 4 / 4 / 5
cut-timer F      req && !busy ##2 1 / ##199 1   covered, 3 / 200 (bmc)
cut-timer G      req && !busy ##201 1           covered, 202 (bmc)
two-word C       in1 && !out1 && in2 && !out2   covered, depth 3
```

`protocol-dma` was checked as well, although its shipped `Wait_C`
covers already reach the consequent's cycle: one cycle further still is
covered (depths 6, 9, 9, and `RWait_C ##1 1` at 6), so no open window of
the slave's assumptions hides anything there.

**Why it matters anyway.** The point of the 5c79eeb sentence is that a
cover of the antecedent alone does not detect an assumption that ends
traces between the antecedent and the consequent. Two of the shipped
covers are exactly that kind of cover, and a mutation shows they would
pass a vacuous proof:

```
symmetry B session + assume m_dead {req[0] && !gnt[0] |=> 1'b1 ##1 1'b0}
  a_wait0 proven; a_false {req[0] && !gnt[0] |-> ##[1:4] 1'b0} proven
  c_wait0 (shipped) covered depth 1; ##1 1 covered depth 2; ##4 1 unreachable
symconst B session + assume m_dead {u.do_write && u.wr_ptr == sa |=> 1'b0}
  Slot_A proven; c_slot (shipped) covered depth 1; ##1 1 unreachable
```

So the chapter tells the reader that its examples carry the full check,
and some carry the weaker check that the chapter says is not enough. In
the `symmetry` blocks the assumption is multi-cycle, the case the
round-2 and round-3 fixes were about. Round 3 (gate 2f, B2) named only
`cut-timer` D as an exception and offered the extra cover as optional;
`symmetry`, `symconst` and `two-word` were missed then.

**Fix (choose one).**
1. Preferred: make the examples meet the rule. In `sym.tcl:19` the
   cover becomes `"req\[$i\] && !gnt\[$i\] ##4 1"` (depth 5 measured
   for every port in A, B and C); in `sc.tcl:22` add `cover -name
   c_slot1 {u.do_write && u.wr_ptr == sa ##1 1}` (depth 2); in
   `cut.tcl:35` add `cover -name c_gnt1 {gnt ##1 1}` (depths 203, 4,
   4, 5); in `two.tcl` session C add `cover -name c_inside {in1 &&
   !out1 && in2 && !out2}` (depth 3). For `cut-timer` F and G, either
   add `req && !busy ##199 1` and `##201 1` (bmc reaches them at 200
   and 202, so they need the bmc engine and a separate `one`, or a
   longer limit), or use the exemption in fix 2 for sessions with no
   assumption. Then rerun, commit the new `run.out` files and recheck
   the line ranges of every splice of `symmetry/run.out` (`:427`,
   `:432`, `:437`, `:442`), `symconst/run.out` (`:318`, `:323`),
   `cut-timer/run.out` (`:51`, `:93`, `:106`, `:126`, `:150`, `:157`,
   `:164`, `:747`) and `cut-timer/cut.tcl` (`:86`, `:119`, `:143`),
   and the text that reads depths from them (the symmetry paragraph
   says nothing about cover depths; `:51` quotes row 11 of
   `cut-timer/run.out`).
2. Text only: at `:62`, keep the rule as advice and stop presenting it
   as met. For example: "...and, under assumptions, it should run to
   the last cycle ... window. The examples' witness covers were run that
   far for this review; where a script shows only the antecedent's
   cover, the longer one was reached as well." A session with no
   assumption cannot end a trace, so there the antecedent's cover is
   enough; saying so would exempt `cut-timer` A-C, F and G honestly.
   Fix 2 still leaves `two-word` C's `p_ahead` without a cover in its
   session, so it needs the one-line `c_inside` either way.

## Block E of `ag`: does the 5c79eeb explanation match the run?

`:605`, as edited: the assumption names state of the design under proof,
so it removes every trace in the cycle where the other lemma would fail,
and the two lemmas fail together; here no trace is left at all, because
both registers hold 1 from reset, so the cover is unreachable in both
runs; on another design the cover can be reached, and the proof graph is
the check that always works.

Measured on scratch copies (`informal-kind`, 5 s, block E's own design
and assumptions, with covers added):

```
ring, both resets 1                      L_A      C_any {1}   C_run
  y == 0 alone                           cex d1   covered d1  covered d2
  x == 0, assume y == 0                  proven   unreachable unreachable
  y == 0, assume x == 0                  proven   unreachable unreachable
ring, resets 0, shared free g (x<=y|g, y<=x|g)
  x == 0 alone                           cex d2   covered d1  covered d2
  x == 0, assume y == 0                  proven   covered d1  covered d2   (C_g {g ##1 1} unreachable)
  y == 0, assume x == 0                  proven   covered d1  covered d2   (C_g unreachable)
ring, x resets 1, y resets 0
  x == 0 alone                           cex d1
  y == 0 alone                           cex d2
  x == 0, assume y == 0                  cex d1   covered d1  unreachable
  y == 0, assume x == 0                  proven   unreachable unreachable
```

So, for block E, `:605` is right on every point: both lemmas fail at
depth 1 alone, the assumption leaves no trace at all (even `cover {1}`
is unreachable), and with a shared input as the common cause the same
trap leaves the shipped kind of cover (`C_run`) reached. The pointer to
the proof graph is the correct protection. The third ring bears on the
general sentence at `:701`; see N1.

## Non-blocking findings

### N1. `:701` says an assumed lemma removes "exactly" the traces on which the other would fail; it removes the traces on which it itself fails

`chapters/ch19-formal-techniques.qmd:701`: "lemmas about one design are
proved on the same state, so an assumed lemma removes exactly the traces
on which the other would fail."

An assumption removes each trace from the cycle where the assumed
property fails. That removes the other lemma's counterexamples only when
the assumed lemma fails no later than the other one does, and it can
remove much more. The third ring above shows both: with `x` reset to 1
and `y` to 0, `x == 0` fails at depth 1 and `y == 0` at depth 2.
Assuming `x == 0` removes every trace, including the cycle-1 states in
which `y == 0` holds, and `y == 0` is proven although the lemmas do not
fail together. In the other direction `x == 0` assuming `y == 0` is
refuted. "Exactly" is true of block E only because there the two fail
in the same cycle.

The practical advice in the paragraph (draw the proof graph and check
it is acyclic) is correct and does not depend on this word, so this is
not blocking. Fix: "...so an assumed lemma removes every trace from the
cycle where it fails, and with it every counterexample of the other
lemma that fails no earlier." `:605` may say "fail no later than the
other" in place of "fail together", but for block E as it stands the
sentence is accurate.

### N2. Block E's `run.out` does not itself show "no trace at all" (round-3 N1, still open)

`examples/ch19-formal-techniques/ag/ag.tcl:53`. The text at `:605` says
that no trace is left at all. The shipped cover `C_run` (`rst_n &&
$past(rst_n)`, depth 2) shows only that no trace reaches the second
cycle. `cover -name C_any {1'b1}` is unreachable under either

claim. That changes `ag/run.out` lines, spliced whole at `:602`, and
`figures/gen_ch19_figures.py` reads verdicts from that file, so rerun
the generator.

### N3. `hier` block C's only cover passes through `P1_A`'s antecedent in the reset cycle

`examples/ch19-formal-techniques/hier/hier.tcl:50-58`. `P1_A` is `G ==
