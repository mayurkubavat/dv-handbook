## Blocking findings

### E1. The new skip rule lets a run that `main` records as a failure be recorded as a skip, exit 0

`scripts/check-examples.sh:92-96`. The rule is `rc == 0` and any line of
`run.log` beginning `skipped`; it is tested *before* the `EXPECT_OUTPUT`
check for a passing example, and it reads the design's own output, not only
a tool's. So a run that exits 0 without its pinned line, which is exactly
the case `EXPECT_OUTPUT` exists for (appendix F, "the script recorded a pass
on every commit until someone read the output"), is recorded as `skipped`
if any line it prints starts with that word, and the script exits 0.

Own test, a copy of `examples/appF-counter/sv` (pins `PASS: counter reached
15`), its testbench given one extra `$display("skipped %0d idle cycles
before the count", 2)` and its verdict inverted so that it prints `FAIL: 0
mismatches` and exits 0; `scripts/check-examples.sh appF-counter/sv` with
the branch's script and with `git show main:scripts/check-examples.sh`:

```
branch  rc=0  lint=pass run=skipped ( idle cycles before the count)
              (pass=1 fail=0 skipped_run=1)
main    rc=1  lint=pass run=fail (passed, but without 'PASS: counter reached 15')
              (pass=0 fail=1 skipped_run=0)
```

With the verdict left right (prints the `skipped ...` line and `PASS`), the
branch records `run=skipped (...)` where `main` records `run=pass`, and
leaves a stale `run.out` in place (a marker line appended to it survived the
run), so an example whose design prints such a line is misrecorded and its
printed output stops being regenerated. No example in the tree prints a
line beginning `skipped` today (`grep -l '^skipped' examples/*/*/run.out`:
none), so the defect is latent; it is a weakening of the script all the
same, and appendix F (line 255) now documents the exception as if only a
missing tool could trigger it. A failing run (`rc != 0`) cannot become a
skip, and an `EXPECT := fail` example cannot either (that branch is tested
first; a "skipped" exit 0 there is "expected to fail, but passed").

Fix (either): (a) signal a skip by exit status, not by text: `matrix.py`
and `informal.sh` exit 77 (the automake convention) and the script maps
`rc == 77` to skipped, so nothing a design prints can forge it; or (b) keep
the text but require it to be the whole story: the *first* line of
`run.log` matches `^skipped: ` and `EXPECT_OUTPUT`, when set, is tested
first (a run that printed its pinned line is a pass, not a skip). Reword
appendix F's sentence to match.

### E2. "silent ... unless it is written with `s_until`" is false for an `s_until` that is not the consequent of an implication

`chapters/ch09-temporal-properties.qmd:82`, last sentence: "So a property
that waits for something that never comes is silent in simulation unless it
is written with `s_until`, and even then the report does not name it." The
row behind it (`x18_pending_end.sv`) measures one shape, `a |-> (1'b1
s_until b)`. Round 2's D1 was a sentence generalized past what was measured;
this is the same sentence, generalized one step less far. Own probe
(`own/d1/su3.sv`: `a` high throughout, `b` never, 11 ticks, book flags plus
`--assert -Wno-fatal`), 5.052 and 5.054 alike:

```
assert property (@(posedge clk) a s_until b)                      rc=0, silent
assert property (@(posedge clk) disable iff (!en) a s_until b)    rc=0, silent
assert property (@(posedge clk) 1'b1 |-> (a s_until b))           rc=1, "[110] %Error: su3.sv:18: Assertion failed in top"
assert property (@(posedge clk) en |=> (a s_until b))             rc=1, same report
assert property (@(posedge clk) $rose(en) |-> (a s_until b))      rc=1, same report
```

(Each form does check: with `a` dropped at tick 5 every one of them counts
failures in its action block.) So the plainest property "written with
`s_until`" that waits for something that never comes is silent and exits 0.
Line 297 is correctly restricted ("has matched its antecedent and is still
waiting for its consequent") and the table row says what it measured; only
the closing sentence of line 82 claims more.

Fix: one clause. "... is silent in simulation unless the wait is an
`s_until` in the consequent of an implication (as a whole property, a
pending `s_until` was silent as well), and even then the report does not
name it." Optionally add the bare form as a sixth build of x18.
