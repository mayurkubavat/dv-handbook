## Blocking findings

### C1. The liveness row of @tbl-ch09-ltl is false of every correct FIFO (L68)
- The row reads "A FIFO that is read often enough drains | **G** (**G** **F** rd → **F** empty)".
  The formula never mentions writes. Consider a correct FIFO that holds one
  entry and is written and read on every tick from then on. Its occupancy
  stays at one, so rd holds infinitely often and empty never holds. That
  trace violates the formula, so no correct FIFO satisfies this
  "requirement".
- The classification (liveness) and the argument at L74 are right. The
  example requirement is wrong, and L74 reasons about it as if a correct
  FIFO should meet it.
- Fix (one cell plus the wording): "A FIFO that stops being written and
  keeps being read drains | **G** (**G** (rd ∧ ¬wr) → **F** empty) |
  liveness". Every finite prefix still extends to a satisfying trace, and
  the L74 sentence still holds ("it may drain on the next read").

### C2. "every rule ... fails exactly once" disagrees with the output (L148)
- `handshake/run.out` shows `HeldRaw_A` failing twice, at tick 11 and at
  tick 14. The script's own verdict line says "three rules failed once
  each".
- Fix: "so that every rule with a reset term holds at least once and fails
  exactly once at a tick known in advance", or name `HeldRaw_A`'s two
  failures.

### C3. The prose's induction invariant is not the script's, and it is false of the design (L412)
- L412: "What rules it out is the relation between the three registers,
  `count == wr_ptr - rd_ptr`, which is exactly `CountPtrs_A`."
- `fifo-proof/fifo_proof.tcl` asserts `count[3:0] == wr_ptr - rd_ptr`.
  In `rtl/fifo_fixed.sv`, `count` is `[PTR_W:0]` (5 bits) and the pointers
  are `[PTR_W-1:0]` (4 bits). As written in the prose, the comparison is
  evaluated at 5 bits, and it is false whenever `wr_ptr < rd_ptr` and when
  the FIFO is full (count 16, pointers equal). So it is not "exactly"
  `CountPtrs_A`, and as printed it is not an invariant of the design.
- Fix: "`count[3:0] == wr_ptr - rd_ptr`, the count modulo sixteen, which is
  exactly `CountPtrs_A`".

### C4. The text describes a comparison that the check script does not make (L361)
- L361: "the outputs printed in this chapter are regenerated on every check
  of the examples and compared with the copies in the book."
- `scripts/check-examples.sh` (lines 101-107) overwrites each `run.out`
  from `run.log` and compares nothing. The book splices `run.out` itself,
  so no separate copy exists to compare against. The fixer's
  byte-identical comparison (log, final check) was done by hand.
- Fix: "the outputs printed in this chapter are regenerated on every check
  of the examples, so a change in the tool's report changes the page". If
  repeatability is the point, add "two runs in a row print the same
  report", which is what the fixer measured.

### C5. The Further-reading line and `refs.bib` give the author different given names (L525)
- L525: "Mike Kantrowitz and Lisa M. Noack". `refs.bib`
  `kantrowitznoack1996done` (and the research note's entry): "Michael
  Kantrowitz". At most one of them matches the paper's byline. The
  attribution rule says to check the whole author field against the
  document itself.
- Fix: read the byline of the DAC 1996 paper (the fixer re-read the PDF)
  and use it in both places.

### C6. British spelling in a printed listing (L458)
- `examples/ch09-temporal-properties/axi-formal/axi.tcl` line 3: "No slave
  is modelled". The chapter splices this file at L458. House rule:

- Fix: "modeled". (`axi.tcl` is spliced only by this chapter.)

## Non-blocking findings

N3. L343 and L470. L343 says the arbitrary reset-cycle values are harmless
because "Properties under `disable iff (!rst_n)` are not judged in that
cycle". The two Tcl properties at L470 (`HeldNext_A`, `HeldPast_A` in
`axi.tcl`) have no `disable iff`. Yet `HeldNext_A` is proven, although the
`HeldPast_A` trace (cycle 0 ARVALID 1 ARREADY 0, cycle 1 ARVALID 0) would
refute it if an attempt started in cycle 0. The tool starts no check in
the reset cycle whatever the property says. Its `docs/fpv-shell.md` says
so: "with a reset the reset cycle counts, so checks start right after it".
`$past` still reads that cycle. Suggest: "The tool starts every check in
the cycle after reset, with or without `disable iff`, so the arbitrary
values are harmless, with one exception: `$past`, which reads the reset
cycle", and at L470 note that the two Tcl spellings carry no reset term.

N4. L354. "`informal shell` exits with status 0 when a property is
refuted, when one is left undetermined and when the table is empty" is a
claim about a tool. Its only support in the book is the comment in the
spliced `examples/mk/informal.tcl`, which is the book's own statement.
Round 1's code review measured it. Suggest a row in
@tbl-ch09-support-x, or a line in one run script, that prints the bare
exit status of a refuting script with no `finish`.

N5. L432: "the checks are the same, less `Sync_A`". The cocotb monitor also
has no `Drained_C` cover: three covers in `fifo-cocotb/run.out`, four in
the SystemVerilog checker. Add "and the `Drained_C` cover".

N6. L301 and L498: "Icarus runs immediate assertions and nothing else" /
"Icarus runs immediate assertions only". Deferred immediate assertions
(`assert #0`, `assert final`), which L50 calls immediate, do not build
on Icarus (@tbl-ch09-support). Say "simple immediate assertions".

N7. Fairness to InFormal. Its README at 5114330 says constructs it cannot
model "are rejected with a message, never guessed", and lists liveness
under "Not there yet". Its `docs/fpv-shell.md` says `$isunknown` "is an
error". The chapter measures silent drops (immediate assertions, local
variables, a module with `$isunknown`) and a liveness row that runs (the
fpv-shell document describes liveness-to-safety for `s_eventually`, so
that row is consistent with the tool's detailed documentation). One
sentence at L299 saying that the silent drops depart from the tool's
stated design would show the reader a pre-release defect, not a design
choice. Whether to report it upstream is the author's call (round 1 N8).

N8. L54: "@sec-ch09-formal shows a checker written that way producing an
empty report". That section states it in a Pitfall and points at a table
row; it prints no report. "reports" or "measures" would be accurate.

N9. L82: "their plain counterparts are weak". Plain `eventually` exists
only with a bounded range, so the unbounded `s_eventually` has no plain
counterpart. A clause, "(the weak `eventually` takes only a bounded
range)", would close the gap.

N10. L133: `$rose(b)`/`$fell(b)` "test a one-bit signal". On a vector they
test the least significant bit (round 1 N2, still open). The matrix row
("on one bit and on a vector") makes the question natural.

N11. Exercises. Exercise 8 asks for the sample number before running.
That depends on Python's random sequence and is not predictable from the
text (round 1 N16); ask for the check only. Exercise 10 asks "which row

and the answer depends on which false expression the reader picks. Either
say that the expected answer is "none, unless you add a cover", or ask the
reader to add the cover of 16 entries and report its verdict.

N12. Whole statements typed into prose: L52 (the chapter's assertion

and L473. They are short, and inline fragments are the book's practice,

N13. L454. "for every offer there is a run in which VALID rises with READY
still low" quantifies oddly, since an offer lives inside a run. Clearer:
"from every state in which the master has something to send, some

within n ticks whatever READY does") is an ordinary assertion. One clause
would stop a reader from over-generalizing.

N14. Length: 14,370 words, up from about 13,500 in round 1. The `$past`

N16. L167: "The rule is a regular expression, in sequence notation
