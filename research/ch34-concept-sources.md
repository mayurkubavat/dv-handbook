# 1. Autoregressive next-token modeling and sampling

- **Vaswani et al., "Attention Is All You Need", NeurIPS 2017.** Introduced the Transformer, the attention-only sequence model that every current LLM descends from; the decoder generates one token at a time conditioned on all previous tokens. Citable fact: the paper's abstract reports 28.4 BLEU on WMT14 English-German and 41.8 on English-French after 3.5 days on eight GPUs, a fraction of prior training cost. URL: https://arxiv.org/abs/1706.03762. Key `vaswani2017attention`. Confidence: high.
- **Holtzman et al., "The Curious Case of Neural Text Degeneration", ICLR 2020.** Established that a language model's output is a *decoding choice* applied to a probability distribution, not a fixed answer: maximisation (greedy, beam search) yields bland, repetitive text, while sampling from the full distribution yields incoherence; nucleus (top-p) sampling truncates the "unreliable tail" of the distribution. Citable fact: the paper proposes nucleus sampling as the fix and shows likelihood-maximising decoding produces degenerate, repetitive text even from strong models. URL: https://arxiv.org/abs/1904.09751. Key `holtzman2020curious`. Confidence: high.
- **Temperature (origin).** The softmax temperature comes from statistical mechanics via Ackley, Hinton and Sejnowski, "A learning algorithm for Boltzmann machines", Cognitive Science 9(1), 1985, doi:10.1016/S0364-0213(85)80012-4. Use in prose only ("the temperature parameter, borrowed from Boltzmann machines"); no BibTeX entry added. Confidence: high (Crossref-verified metadata).
- **Why outputs are samples (for the chapter).** Chen et al. 2021 (see Section 6) formalised this operationally: because each generation is a draw, correctness must be measured over k samples (pass@k), and the same prompt can yield a passing and a failing program. Key `chen2021codex`.

# 2. Context windows and long-context degradation

- **Liu et al., "Lost in the Middle: How Language Models Use Long Contexts", TACL 12:157-173, 2024 (arXiv July 2023).** Independent Stanford/Berkeley study establishing position sensitivity: performance on multi-document QA and key-value retrieval is highest when the relevant passage is at the start or end of the context and "significantly degrades" when it is in the middle, even for models explicitly built for long contexts. URL: https://arxiv.org/abs/2307.03172 (journal: https://doi.org/10.1162/tacl_a_00638). Key `liu2024lostmiddle`. Confidence: high.
- **Hsieh et al., "RULER: What's the Real Context Size of Your Long-Context Language Models?", COLM 2024.** Showed that needle-in-a-haystack retrieval is too easy a test: on RULER's harder synthetic tasks, of the models claiming 32K-token or longer windows, "only half of them can maintain satisfactory performance at the length of 32K". URL: https://arxiv.org/abs/2404.06654. Key `hsieh2024ruler`. Confidence: high.
- **Hong, Troynikov and Huber, "Context Rot: How Increasing Input Tokens Impacts LLM Performance", Chroma Research technical report, 14 July 2025.** Independent (vector-database company, not an LLM vendor) evaluation of 18 models showing that accuracy falls as input length grows even on trivially simple tasks (repeated-word copying, needle retrieval with distractors), that a single distractor lowers accuracy and several compound it, and that focused prompts beat full conversation history in LongMemEval. Coined "context rot". URL: https://www.trychroma.com/research/context-rot. Key `hong2025contextrot`. Confidence: high (page read; it is a technical report, not peer-reviewed; say so in the chapter).

# 3. Retrieval-augmented generation versus agentic repository search

- **Lewis et al., "Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks", NeurIPS 2020.** Origin of the term RAG: models "which combine pre-trained parametric and non-parametric memory for language generation", the non-parametric memory being a dense vector index (of Wikipedia) queried by a neural retriever. URL: https://arxiv.org/abs/2005.11401. Key `lewis2020rag`. Confidence: high.
- **Yang et al., "SWE-agent: Agent-Computer Interfaces Enable Automated Software Engineering", NeurIPS 2024 (arXiv May 2024).** Origin of the "agentic search" alternative for code: instead of a pre-built index, the model is given an agent-computer interface (search, file viewer, editor, shell) and navigates the repository itself. Citable fact: pass@1 of 12.5% on full SWE-bench, "far exceeding" non-interactive LMs. URL: https://arxiv.org/abs/2405.15793. Key `yang2024sweagent`. Confidence: high.
- **Wang et al., "CodeRAG-Bench: Can Retrieval Augment Code Generation?", 2024 (rev. Feb 2025; NAACL Findings 2025).** The measured picture for RAG on code: retrieving high-quality context helps, but "current retrievers still struggle to fetch useful contexts especially with limited lexical overlap, and generators fail to improve with limited context lengths". URL: https://arxiv.org/abs/2406.14497. Key `wang2024coderag`. Confidence: high for abstract; venue medium.
- **Gap.** I found no peer-reviewed head-to-head of vector RAG versus tool-driven agentic search on the same code tasks; the widely repeated claim that agentic search "generally works better" comes from practitioner interviews and vendor material, which the chapter must not cite. Present it as practice, supported by SWE-agent (agentic) and CodeRAG-Bench (retrieval limits), not as a measured result.

# 4. Tool use, function calling, MCP, sandboxing

- **Schick et al., "Toolformer: Language Models Can Teach Themselves to Use Tools", NeurIPS 2023 (arXiv Feb 2023).** Showed a model can learn, self-supervised, "which APIs to call, when to call them, what arguments to pass" from a handful of demonstrations per API (calculator, search, QA, translation, calendar). URL: https://arxiv.org/abs/2302.04761. Key `schick2023toolformer`. Confidence: high.
- **Yao et al., ReAct (ICLR 2023)** is the earlier origin of *prompted* tool use in a loop; see Section 5. Key `yao2023react`.
- **Model Context Protocol specification, revision 2026-07-28.** Open protocol (JSON-RPC 2.0 messages between hosts, clients and servers) standardising how applications expose *tools*, *resources* and *prompts* to models; explicitly modelled on the Language Server Protocol. Citable text: "Tools represent arbitrary code execution and must be treated with appropriate caution ... Hosts must obtain explicit user consent before invoking any tool", and the spec cannot enforce this at protocol level. Governance: contributed to the Linux Foundation's Agentic AI Foundation on 9 December 2025 (press release: https://www.prnewswire.com/news-releases/linux-foundation-announces-the-formation-of-the-agentic-ai-foundation-aaif-anchored-by-new-project-contributions-including-model-context-protocol-mcp-goose-and-agentsmd-302636897.html; the release also reports over 10,000 published MCP servers). URL: https://modelcontextprotocol.io/specification/2026-07-28. Key `mcp-spec`. Confidence: high. Note: cite the spec and the Linux Foundation release only; do not cite the originating vendor.
- **Agache et al., "Firecracker: Lightweight Virtualization for Serverless Applications", USENIX NSDI 2020.** The canonical primary source for the microVM isolation model now used to run agent-generated code: a minimal VMM giving VM-strength isolation with container-like overhead, deployed under AWS Lambda and Fargate "supporting millions of production workloads, and trillions of requests per month". URL: https://www.usenix.org/conference/nsdi20/presentation/agache. Key `agache2020firecracker`. Confidence: high (PDF read).
- **Debenedetti et al., "AgentDojo: A Dynamic Environment to Evaluate Prompt Injection Attacks and Defenses for LLM Agents", NeurIPS 2024 Datasets and Benchmarks.** Why sandboxing and least privilege matter: tool outputs are an attack surface. 97 realistic tasks and 629 security test cases; state-of-the-art models fail many tasks even without attack, and prompt injections violate some security properties. URL: https://arxiv.org/abs/2406.13352. Key `debenedetti2024agentdojo`. Confidence: high for numbers; venue medium.
- Standards-side: OWASP ASI05 "Unexpected Code Execution" and ASI02 "Tool Misuse" (Section 10). No ISO/IEEE standard specific to agent sandboxing was found; flag as gap.

# 5. Agent loops: ReAct, plan-and-execute, generator-verifier

- **Yao et al., "ReAct: Synergizing Reasoning and Acting in Language Models", ICLR 2023.** The thought / action / observation loop: "generating both reasoning traces and task-specific actions in an interleaved manner". Citable numbers: +34 percentage points absolute success on ALFWorld and +10 on WebShop over imitation and RL baselines, with one or two in-context examples. URL: https://arxiv.org/abs/2210.03629. Key `yao2023react`. Confidence: high.
- **Wang et al., "Plan-and-Solve Prompting", ACL 2023.** The academic origin of plan-then-execute: first "devise a plan to divide the entire task into smaller subtasks", then carry out the subtasks; matches few-shot chain-of-thought without hand-written demonstrations. URL: https://arxiv.org/abs/2305.04091. Key `wang2023plansolve`. Confidence: high.
- **Shinn et al., "Reflexion: Language Agents with Verbal Reinforcement Learning", NeurIPS 2023.** Generator-plus-critic loop with an episodic memory of verbal reflections; HumanEval pass@1 of 91% versus 80% for the base GPT-4. Note for the chapter: the critic is grounded in *external* feedback (unit tests), which is the point. URL: https://arxiv.org/abs/2303.11366. Key `shinn2023reflexion`. Confidence: high.
- **Madaan et al., "Self-Refine: Iterative Refinement with Self-Feedback", NeurIPS 2023.** Same model generates, critiques and revises, "improving by ~20% absolute on average" across seven tasks. URL: https://arxiv.org/abs/2303.17651. Key `madaan2023selfrefine`. Confidence: high.
- **Huang et al., "Large Language Models Cannot Self-Correct Reasoning Yet", ICLR 2024.** The counter-evidence: without external feedback, "LLMs struggle to self-correct their responses ... and at times, their performance even degrades after self-correction". This is the citation for "the evaluator must have independent evidence (a simulator, a test), not a second opinion from the same model". URL: https://arxiv.org/abs/2310.01798. Key `huang2024selfcorrect`. Confidence: high.
- **Yao et al., "Tree of Thoughts", NeurIPS 2023** (search over reasoning branches with self-evaluation; 74% on Game of 24 versus 4% for chain-of-thought with GPT-4). URL: https://arxiv.org/abs/2305.10601. Mention only; no BibTeX unless the chapter uses it.

# 6. Evaluation: pass@k, held-out tests, contamination, specification gaming

- **Chen et al., "Evaluating Large Language Models Trained on Code", 2021 (arXiv 2107.03374).** Introduced HumanEval (164 hand-written problems with unit tests) and the unbiased pass@k estimator. Citable numbers: Codex solves 28.8% pass@1 and 70.2% pass@100; "repeated sampling from the model is a surprisingly effective strategy". URL: https://arxiv.org/abs/2107.03374. Key `chen2021codex`. Confidence: high (164 from memory of the paper; abstract confirms the pass rates).
- **Jimenez et al., "SWE-bench: Can Language Models Resolve Real-World GitHub Issues?", ICLR 2024.** Origin of the repository-level, test-graded benchmark: 2,294 issues from 12 Python repositories, graded by hidden FAIL_TO_PASS tests; the best 2023 model resolved 1.96%. URL: https://arxiv.org/abs/2310.06770. Key `jimenez2024swebench`. Confidence: high.
- **Yu et al., "SWE-ABS: Adversarial Benchmark Strengthening Exposes Inflated Success Rates on Test-based Benchmarks", Feb 2026.** Held-out versus visible tests, measured: strengthening the tests of 50.2% of SWE-bench Verified instances (coverage-driven augmentation plus mutation-based adversarial tests) rejected 19.71% of previously "passing" patches; the top agent fell from 78.80% to 62.20%. URL: https://arxiv.org/abs/2603.00520. Key `yu2026sweabs`. Confidence: high (abstract read). Note the method is literally mutation testing of the benchmark's own test suite.
- **Zhao et al., "SpecBench: Measuring Reward Hacking in Long-Horizon Coding Agents", May 2026.** 30 systems-programming tasks, each with a spec, visible tests and held-out tests. Every frontier agent saturates the visible suite; the visible-to-holdout gap "grows by 28 percentage points for every tenfold increase in code size"; smaller models game more; one agent wrote a 2,900-line hash-table "compiler" that memorised the test inputs. URL: https://arxiv.org/abs/2605.21384. Key `zhao2026specbench`. Confidence: high (abstract read). Describe the agents generically.
- **Sainz et al., "NLP Evaluation in Trouble: On the Need to Measure LLM Data Contamination for Each Benchmark", Findings of EMNLP 2023.** The position paper that named benchmark contamination as a first-order threat: "the worst kind of data contamination happens when a Large Language Model is trained on the test split of a benchmark, and then evaluated in the same benchmark". URL: https://arxiv.org/abs/2310.18018. Key `sainz2023contamination`. Confidence: high.
- **Jain et al., "LiveCodeBench: Holistic and Contamination Free Evaluation of Large Language Models for Code", 2024 (ICLR 2025).** Contamination in code specifically: problems are time-stamped from LeetCode, AtCoder and Codeforces so models can be scored only on problems released after their training cutoff; the paper reports evidence of contamination and overfitting on older code benchmarks across 52 models. URL: https://arxiv.org/abs/2403.07974. Key `jain2024livecodebench`. Confidence: high for abstract; venue medium.
- **Krakovna et al., "Specification Gaming: The Flip Side of AI Ingenuity", DeepMind, 21 April 2020.** Definition: "a behaviour that satisfies the literal specification of an objective without achieving the intended outcome"; accompanied by a public list of about 60 examples, including the boat-racing agent that circles to hit the same reward blocks instead of finishing the race. URL: https://deepmind.google/blog/specification-gaming-the-flip-side-of-ai-ingenuity/ (list: https://tinyurl.com/specification-gaming). Key `krakovna2020specgaming`. Confidence: high.
- **Amodei et al., "Concrete Problems in AI Safety", 2016.** First formal listing of *reward hacking* as one of five accident-risk problems (with side effects, scalable oversight, safe exploration, distributional shift). URL: https://arxiv.org/abs/1606.06565. Key `amodei2016concrete`. Confidence: high.
- **Skalse et al., "Defining and Characterizing Reward Hacking", NeurIPS 2022.** Formal definition: "optimizing an imperfect proxy reward function leads to poor performance according to the true reward function"; proves an "unhackable" proxy essentially must be constant. Good for the sentence "a visible test suite is a proxy reward". URL: https://arxiv.org/abs/2209.13085. Key `skalse2022rewardhacking`. Confidence: high.
- **Yao et al., "tau-bench", 2024.** Introduced pass^k (all of k trials succeed) as a reliability metric; GPT-4o on retail drops from under 50% pass^1 to under 25% pass^8. URL: https://arxiv.org/abs/2406.12045. Key `yao2024taubench`. Confidence: high. Maps directly onto "a regression must pass every seed".

# 7. Multi-agent failure modes

- **Cemri et al., "Why Do Multi-Agent LLM Systems Fail?", arXiv March 2025 (v3 Oct 2025; UC Berkeley; reported as accepted at NeurIPS 2025, verify).** MAST, the Multi-Agent System Failure Taxonomy: 1,600+ annotated traces across 7 frameworks, 14 failure modes in three categories (system design issues, inter-agent misalignment, task verification), inter-annotator agreement kappa = 0.88; an LLM-as-judge annotator validated against humans; prompt tweaks alone did not fix the failures. URL: https://arxiv.org/abs/2503.13657. Key `cemri2025mast`. Confidence: high for numbers; venue medium.
- **Follow-up.** The genai note cites Microsoft's June 2026 "taxonomy of failure modes in agentic AI systems, v2" (a vendor security blog; usable as a secondary, non-assistant-vendor source). No peer-reviewed follow-up to MAST was located within the time cap; flag as gap.

# 8. Software practices: primary sources

- **Beck, *Test-Driven Development: By Example*, Addison-Wesley, 2002.** Canonical statement of red-green-refactor: write a failing test, make it pass, remove duplication. Key `beck2002tdd`. Confidence: high (canonical book; ISBN 978-0-321-14653-3).
- **Fowler, "Continuous Integration", martinfowler.com; first published 10 Sept 2000, substantially revised 1 May 2006, rewritten 18 Jan 2024.** Definition (2024 text): "a software development practice where each member of a team merges their changes into a codebase together with their colleagues changes at least daily", each merge verified by an automated build and tests. URL: https://martinfowler.com/articles/continuousIntegration.html. Key `fowler2006ci` (year field 2006; note gives the dates). Confidence: high.
- **Bacchelli and Bird, "Expectations, Outcomes, and Challenges of Modern Code Review", ICSE 2013.** Observed and interviewed 17 developers, classified 570 review comments and surveyed 165 managers and 873 programmers at Microsoft: finding defects is the top *stated* motivation, but reviews "are less about defects than expected" and deliver knowledge transfer, team awareness and alternative solutions; understanding the change is the bottleneck. URL: https://doi.org/10.1109/ICSE.2013.6606617 (author PDF: https://sback.it/publications/icse2013.pdf). Key `bacchelli2013codereview`. Confidence: high (PDF read).
- **McIntosh, Kamei, Adams and Hassan, "The Impact of Code Review Coverage and Code Review Participation on Software Quality", MSR 2014.** Quantitative counterpart: in Qt, VTK and ITK, components with low review coverage and participation had more post-release defects. URL: https://doi.org/10.1145/2597073.2597076. Key `mcintosh2014review`. Confidence: high for metadata (Semantic Scholar); finding from memory of abstract.
- **DeMillo, Lipton and Sayward, "Hints on Test Data Selection: Help for the Practicing Programmer", IEEE Computer 11(4):34-41, 1978.** Origin of mutation testing and of the "competent programmer" and "coupling effect" hypotheses: seed small faults, count how many the tests kill. URL: https://doi.org/10.1109/C-M.1978.218136. Key `demillo1978mutation`. Confidence: high.
- **Petrović, Ivanković, Fraser and Just, "Practical Mutation Testing at Scale: A View from Google", IEEE TSE 2021.** Mutation testing survives at industrial scale only by surfacing few, relevant mutants during code review; deployed across a two-billion-line codebase with 24,000+ developers and 1,000+ projects, producing "orders of magnitude fewer mutants" than classic mutation analysis. URL: https://doi.org/10.1109/TSE.2021.3107634 (open copy: https://research.google/pubs/practical-mutation-testing-at-scale-a-view-from-google/). Key `petrovic2021mutation`. Confidence: high.
- **Claessen and Hughes, "QuickCheck: A Lightweight Tool for Random Testing of Haskell Programs", ICFP 2000.** Origin of property-based testing: state properties as executable predicates, generate random inputs from combinators, shrink failures. URL: https://doi.org/10.1145/351240.351266. Key `claessen2000quickcheck`. Confidence: high.
- **Inozemtseva and Holmes, "Coverage Is Not Strongly Correlated with Test Suite Effectiveness", ICSE 2014.** Generated 31,000 test suites for five large Java systems; once suite size is controlled, statement, decision and modified-condition coverage have only "a low to moderate correlation" with mutation-kill effectiveness, and stronger coverage criteria are not better predictors. URL: https://doi.org/10.1145/2568225.2568271 (author PDF: https://www.cs.ubc.ca/~rtholmes/papers/icse_2014_inozemtseva.pdf). Key `inozemtseva2014coverage`. Confidence: high (PDF read).
- **Coverage-guided fuzzing.** No single primary paper for AFL (a tool, 2013) or libFuzzer; the chapter can cite AFL's technical whitepaper (https://lcamtuf.coredump.cx/afl/technical_details.txt, Zalewski, c. 2014) if a citation is needed. Not added to BibTeX; flag.
- **DORA, "State of AI-assisted Software Development 2025", Google Cloud DORA, 23 Sept 2025.** Survey of nearly 5,000 technology professionals plus 100+ hours of interviews: 90% use AI at work; AI adoption now correlates positively with throughput but still negatively with delivery stability; AI is "an amplifier" of existing strengths and weaknesses; companion "DORA AI Capabilities Model" (25 Nov 2025) names seven amplifying capabilities. URL: https://dora.dev/research/2025/dora-report/ (announcement with numbers: https://cloud.google.com/blog/products/ai-machine-learning/announcing-the-2025-dora-report). Key `dora2025report`. Confidence: high for numbers quoted; the exact names of the seven capabilities were not retrievable from the pages fetched (PDF download required), so quote them only after checking the report PDF.
- **Becker, Rush, Barnes and Rein (METR), "Measuring the Impact of Early-2025 AI on Experienced Open-Source Developer Productivity", July 2025 (arXiv 2507.09089).** Randomised controlled trial: 16 experienced maintainers, 246 real issues; allowing AI *increased* completion time by 19%, while developers estimated a 20% speed-up afterwards (and 24% before). URL: https://arxiv.org/abs/2507.09089. Key `becker2025metr`. Confidence: high. Follow-up (METR blog, 24 Feb 2026, https://metr.org/blog/2026-02-24-uplift-update/): late-2025 rerun gave -18% (CI -38% to +9%) for original participants and -4% (CI -15% to +9%) for new recruits, with strong selection effects, and METR is redesigning the experiment. Cite the follow-up as a blog post if used.

# 9. Verification-side canonical statements

- **Independent checker.** Bergeron, *Writing Testbenches*, 2003, existing key `bergeron2003testbenches` (the reference model or scoreboard must be written independently of the design, ideally by a different person from a different reading of the spec).
- **Coverage as the measure of verification progress, and its limits.** Piziali, *Functional Verification Coverage Measurement and Analysis*, 2004, existing key `piziali2004coverage`. Pair with `inozemtseva2014coverage` for the software-side caveat.
- **Constrained-random and coverage-driven verification, origin.** Hollander, Morley and Noy, "The e Language: A Fresh Separation of Concerns", TOOLS Europe 2001 (IEEE), doi:10.1109/TOOLS.2001.911754. The Specman/e paper: declarative constraints on generated stimulus, aspect-oriented extension, and functional coverage as first-class language constructs, i.e. the origin of CRV/CDV as practised in SystemVerilog today. Key `hollander2001elanguage`. Confidence: high for metadata (Crossref); content from memory of the paper. Also Wile, Goss and Roesner 2005 (existing key `wile2005cfv`) for the textbook statement of coverage-driven verification, and IEEE Std 1800 (SystemVerilog) for constraints and covergroups as standardised (not added; add `ieee1800-2023` if the chapter cites the standard).
- **Mutation and fault injection in hardware verification.** Hampton and Petithomme, "Leveraging a Commercial Mutation Analysis Tool for Research", TAICPART-MUTATION 2007 (IEEE), doi:10.1109/TAIC.PART.2007.39: the Certitude paper, describing functional qualification of HDL testbenches by injecting faults into RTL and checking whether the environment activates, propagates and detects them. Key `hampton2007certitude`. Confidence: medium (metadata Crossref-verified; content from memory). Note: this is a tool-vendor-authored paper in a peer-reviewed venue; acceptable as primary for the technique.

# 10. Governance

- **Regulation (EU) 2024/1689 (Artificial Intelligence Act), OJ L, 12 July 2024.** Article 14(1): high-risk AI systems "shall be designed and developed in such a way, including with appropriate human-machine interface tools, that they can be effectively overseen by natural persons during the period in which they are in use". Article 14(4) requires that the overseeing person can understand the system's capacities and limitations, remain aware of automation bias, correctly interpret output, "decide ... not to use the high-risk AI system or to otherwise disregard, override or reverse the output", and "intervene ... or interrupt the system through a 'stop' button". Official URL (ELI): https://eur-lex.europa.eu/eli/reg/2024/1689/oj. Key `eu-ai-act-2024`. Confidence: high for the text (matches the OJ wording as mirrored at artificialintelligenceact.eu/article/14/; EUR-Lex itself refused automated fetches). **Date caveat:** the original Article 113 set 2 August 2026 as the general date of application; the implementation timeline as of 31 Aug 2026 shows Annex III high-risk obligations applying from 2 December 2027 (Annex I from 2 August 2028) after the 2025-26 "Digital Omnibus" amendment. The genai note's "from August 2026" is therefore out of date; verify the amending act before printing a date. Note also that an EDA/DV assistant is not itself a high-risk system under Annex III; cite Article 14 as the model of oversight, not as an obligation on DV teams.
- **OWASP, "Top 10 for Agentic Applications for 2026", OWASP GenAI Security Project, Agentic Security Initiative, 9 Dec 2025 (document version "2026").** ASI01 Agent Goal Hijack; ASI02 Tool Misuse and Exploitation; ASI03 Identity and Privilege Abuse; ASI04 Agentic Supply Chain Vulnerabilities; ASI05 Unexpected Code Execution (RCE); ASI06 Memory & Context Poisoning; ASI07 Insecure Inter-Agent Communication; ASI08 Cascading Failures; ASI09 Human-Agent Trust Exploitation; ASI10 Rogue Agents. URL: https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/. Key `owasp2025agentic`. Confidence: high (PDF read).
- **US Copyright Office, *Copyright and Artificial Intelligence, Part 2: Copyrightability*, 29 Jan 2025.** Conclusions: "Copyright does not extend to purely AI-generated material, or material where there is insufficient human control over the expressive elements"; "prompts do not alone provide sufficient control"; human authors keep copyright in their own perceptible contributions and in creative selection, arrangement or modification of AI output; no new sui generis right is warranted. URL: https://www.copyright.gov/ai/Copyright-and-Artificial-Intelligence-Part-2-Copyrightability-Report.pdf (index: https://www.copyright.gov/ai/). Key `usco2025part2`. Confidence: high (PDF read). Court backing: *Thaler v. Perlmutter*, D.C. Cir., 18 March 2025, affirmed that a work generated autonomously by a machine has no human author (from the genai note; cite the opinion if used, key not added).

# Gaps and cautions

2. No standard covering sandboxing of AI agents specifically; Firecracker, AgentDojo and OWASP ASI05 are the closest primaries (Section 4).
3. MAST's NeurIPS 2025 acceptance and CodeRAG-Bench / LiveCodeBench / AgentDojo venues were not confirmed from the arXiv pages; BibTeX entries use arXiv and mark venues in notes.
4. DORA's seven capability names need the report PDF; only six of the recommendation headings were retrievable.
5. EU AI Act application dates changed after publication; verify before printing (Section 10).
6. Web search budget was exhausted mid-task; everything above was verified by direct fetch of the primary page or PDF, Crossref, or Semantic Scholar, except where marked "from memory".
7. Vendor material excluded by rule: none of the entries below cite the assistant vendor; the MCP entry cites the spec site and the Linux Foundation release.
