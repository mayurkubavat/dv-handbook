# Tooling landscape survey: hardware side

Scope: open (and a few labelled vendor) tools across RTL parsing, simulation, coverage, waveforms, formal, MCP/agent wrappers, debug data sources, spec tooling, build/CI. Each row records what an agent could do with the tool through a tool interface (CLI, Python API, LSP, library). URLs were checked with curl on 2026-09-07 unless marked "unverified".

Maturity scale: **production** (widely used, multi-year, releases), **stable** (usable, active, smaller community), **experimental** (young, single-maintainer, or research), **dormant** (no meaningful activity for 2+ years).

## 1. Parsers, ASTs and language servers

The dominant split is between (a) full-elaboration front-ends that see the design the way a simulator does (slang, Surelog/UHDM, Verilator, Yosys-slang) and (b) syntax-only parsers that are fast, tolerant of incomplete code and easy to embed (Verible, tree-sitter, sv-parser). An agent tool layer wants both: syntax-level for editing and navigation, elaboration-level for "what does the compiler actually see".

## 8. Gaps (no open tool found)

1. **CDC / RDC analysis.** No open clock- or reset-domain-crossing checker exists. Yosys `check` and Verilator lint are structural only. Commercial only (Questa CDC, SpyGlass, Jasper CDC).
2. **UCIS binary databases.** pyucis reads/writes UCIS XML and its own formats, but no open tool reads vendor UCDB/VDB binaries. Verilator `.dat` and cocotb-coverage XML/YAML are the only open coverage stores, and they are not UCIS.
3. **Emulation / FPGA prototyping of verification environments.** Nothing open beyond FPGA synthesis flows; no open transactor-based emulation.
4. **Full UVM on an open simulator.** Verilator runs UVM 2020-3.2 with limitations tracked in an open issue (#1538, updated Aug 2026); Icarus does not support classes broadly. pyuvm sidesteps this by moving UVM to Python.
5. **Regression database.** No open, reusable results database or schema; JUnit XML is the lowest common denominator. pyEDAA.Reports is an early attempt.
6. **Failure clustering / automatic bisection for HDL.** Only `git bisect run` with a user-supplied oracle; PinDown is commercial. No open log-signature clustering tool.
7. **SARIF from linters.** Only Verilator emits SARIF. Verible and svlint emit text; a catalogue could specify a small SARIF wrapper.
8. **Open SVA-capable formal beyond immediate assertions.** sby handles SVA via Yosys's limited `read_verilog -formal`; concurrent SVA needs the slang front-end or EBMC, whose SVA subsets are documented but incomplete.
9. **Rename/refactor over LSP.** verible-verilog-ls does not implement rename; no open SV LSP does.
10. **AgentDV.** No repository or paper by this name could be located through the arXiv API in this session; the reference should be re-verified before citing.
11. **Standard Markdown spec convention.** None; each open project rolls its own.
12. **Open FSDB reader.** Only through Synopsys libraries (TraceWeave) or conversion to FST (wave-mcp). No clean-room reader.

URL status codes were collected with `curl -sSL -A "Mozilla/5.0"` on 2026-09-07; GitHub metadata (license, stars, last push, archived flag) via the GitHub REST API the same day. Web search was unavailable for the second half of this session, so the MCP inventory is from GitHub repository search only; servers hosted elsewhere (GitLab, Gitee, vendor portals) may be missing.
