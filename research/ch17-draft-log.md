## 1. Decisions made while building the examples

- **Drivers are Python, not shell.** The outline names `run_tools.sh`
  and `run_model.sh`. The build system has no shell recipe
  (`examples/mk/` holds sv, cocotb, systemc, python, informal, and the
  informal recipe runs a Tcl script through `informal shell`), and
  `examples/mk/` is outside what this draft may edit. The three
  tool-driven examples therefore use `EXAMPLE_LANG := python` with a
  driver `run_tools.py` / `run_model.py` that calls the tools, filters
  the timing fields, asserts the expected sizes and prints
  `skipped: ...` when a program is missing (the precedent is
  `examples/ch09-temporal-properties/support-matrix/matrix.py`).
- **`selftest.py` has its own directory** (`solver-selftest/`), not
  `cdcl/`. It needs `z3`; a Python module cannot be named in
  `REQUIRES`, so the script prints `skipped: ` when the import fails.
  Had it stayed in `cdcl/`, the `run.out` of `cdcl/` would differ
  between a machine with z3 and one without.
- **Which Python (RN P1).** `examples/mk/python.mk` runs `python3`. On
  the drafting machine the first `python3` on the documented PATH has
  no `z3`, so the three z3 examples skip there; their `run.out` files
  were written by running the checker with the venv's directory first
  on the PATH. `python.mk` was not edited.
- **The Tseitin builder has a direct `or_`** (three clauses), not the
  De Morgan form of the research scratch file. The builder's full
  adder is then the hand-written file clause for clause. Every count
  was re-measured with this builder (section 3).
- **Random 3-SAT uses only `random.Random(seed).random()`**, the one
  method Python's documentation guarantees to reproduce across
  versions (RN P15 left `sample` unchecked). Counts re-measured.

Deviations from the outline's example list, and why:

- `aig/` is new. The outline had the 9-to-7 reduction only through
  ABC or InFormal (RN P10), neither of which the book's CI has. A
  twenty-line structural hash in Python shows the same reduction
  everywhere and lets the chapter define the term by a listing.
  `fa.aag` is checked in there; `tseitin-tools` regenerates it with
  Yosys and fails if it differs (the Yosys comment line with the
  compiler version is cut off).
- `production/` is new, to meet "production-solver numbers go in
  captioned tables generated by a script whose output is committed".
  Solvers: z3 5.4.1 (`z3 -st`, `:sat-conflicts`) and CaDiCaL 3.0.1
  (the binary under `/opt`, put on the PATH for the run only). The RN
  tables used CaDiCaL 1.9.5 and MiniSat through `python-sat`, which
  the chapter may not use, so **the chapter's production numbers
  differ from the RN's and from the outline's** (for example 10 holes:
  3,134,556 conflicts with CaDiCaL 3.0.1, not 2.2 million; 8-bit
  multiplier: 39,521, not 36 thousand; 32-bit adder: 800, not 883).
  MiniSat is not shown at all.
- The FIFO wrapper does not `` `include `` the first chapter's file:
  `informal lower` has no include-path option, so both files are
  passed on the command line.
- `fifo-unroll-z3` prints one line for the unsatisfiable bounds, not
  one per bound.
- `tseitin/encode.py` answers the two questions by enumerating the
  256 assignments, not with a solver: no solver exists yet at that
  point of the chapter. The propagation trace is in `dpll/`.
- `truth.py` and `encode.py` read the gates from `full_adder.sv`
  (`common/netlist.py`), so the table and the clauses come from the
  SystemVerilog and not from a transcription of it.
