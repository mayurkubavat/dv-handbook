## 2. Teaching engines and Python examples (built, run)

- `common/ts.py` (library), `kind/kind.py`, `ic3/ic3.py`: ported from
  `research/ch18-measurements/teach/` with the logic unchanged and
  three additions: a `.names` sidecar per model, `holds_next` as a
  named third query in IC3 (the prototype reused `pred` with a
  flag), and report callbacks that pass states, so the run scripts
  print by register name. Query counts are the research note's: 160
  (153 search, 7 certificate) at two entries, 1,531 at four, 92 on
  `counter.aag`, 1,462 on `fifo_bmc.aag`; k = 7 and 16 queries for
  simple-path induction; base case satisfiable at k = 16 on the
  bugged FIFO with 33 queries.
- One wrapper, `common/fifo_ptrs.sv`, with three macros replaces the
  research note's one wrapper per model. The four models it produces
  are byte-identical to the research ones (`cmp`), and a fifth,
  `fifo_ptrs2_h.aag` (two entries, helper assumed), was added so the
  helper section stays at two entries; the outline listed only the
  four-entry one.
- Latch names: the reachable set alone does not fix them (swapping
  `wr_ptr` and `rd_ptr` maps the six states to themselves), so
  `reach/run_reach.py` checks the names against a step: from the
  empty state the only move is to `wr_ptr=1 rd_ptr=0 count=1`. At
  four entries the order was established the same way (two writes,
  then a write with a read) before the `.names` file was written.
- `ic3-fuzz/fuzz.py`: 300 random systems (2 to 6 latches, seed 18)
  and the 86 single-edge mutants of `fifo_ptrs2.aag`, three engines
  each, about 13 s. Checked that it can fail: with `meets_init`
  replaced by a constant False it reported 48 disagreements and
  exited 1; with a broken `differ` it reported 42. The research
  fuzz (2,913 systems, up to 8 latches) is not rerun by the example.

Things a reviewer should attack here:
1. `ic3.py` asserts that an obligation above frame 0 holds no reset
   state. The argument that this cannot fire (a reset state with a
   path to bad shorter than the frontier would have been found at an
   earlier frontier) is in the chapter in one sentence; try to
   construct a model that trips it (constraints that fail only in
   the bad step are the place to look).
2. `kind.py` proves at step k only after base cases 0 to k; the
   simple-path constraint compares latches only, never inputs.
3. `explicit` stops at the first bad state, so `reach` is partial
   for unsafe systems; the fuzz uses it only for safe ones.

   cover 2x2, the lemma picture and the engine flow chart were
   dropped; the cover summary block, the decoded invariant and
   `tbl-ch18-engines` carry that content as text and table.
2. `tbl-seconds.md` and its example `engine-seconds` are additions:
   the STATUS decision allows seconds only in a dated generated
   table, so there is one. It is regenerated on every run and so is
   the one checked-in file of the chapter that differs between runs.
3. The engine table and the scaling grid have a `ric3-ic3` column;
   there is no commercial-tool column anywhere (pointer to
   `tbl-ch09-formal-tools` by label).
4. `informal-kind` PROVED the liveness property under fairness in a
   one-property session, against the note's expectation. The table
   reports it and the prose does not say that only IC3 handles
   liveness.
5. `fifo-64`: the cover with `$past` from the outline was covered at
   depth 1 (reset-cycle value), so the drain cover is
   `full ##64 empty`, depth 129.
6. `lasso` has a second block (a bounded property beside the liveness
   one prints the lasso at depth 7, not 4); the chapter uses it for a
   pitfall.
7. `bmc-depth` has one more row than outlined (a false property 1024
   steps away) so that the two `undetermined` rows can be set side by
   side; the stepped engine reported depth 66 for a shortest of 65,
   and the script asserts only "not below 65".
8. Exercise 10 of the outline had a wrong answer ("stall held at
   least four cycles"). On this design two cycles of stall in state 2
   put the grant in the fifth cycle. The exercise now asks for the
   pattern and the prose gives the two-cycle one.
9. The shell-command table is made from a real session, line by line
   under `catch`, not from `informal shell --check`: check mode does
   not elaborate, so it reports RTL property names and engine names
   as unknown, which would have put artifacts in the table.
10. No solutions were written: there is no solutions appendix in the
    book yet. The outline's answers stand, with item 8 corrected.
11. A tool quirk left visible in spliced output: a disabled property
    row keeps the engine name of an earlier `prove` (`scaling`,
    `fifo-64`). The chapter splices the summary blocks, not those
    rows.

## 6. What a reviewer should attack

1. The frame invariants in the Definition of *frame* are stated for
   `ic3.py` (frontier checked for bad states directly, delta-encoded
   levels). Check them against Bradley section 4 and decide whether
   the attribution sentence is tight enough.
2. The definition of k-induction counts transitions (`k` good states,
   then a bad one; base case: fewer than `k` steps). `kind.py` asks
   one base depth more than that definition needs; the prose says so.

   chapter's own.
4. Every tool-internal statement tagged `[@informal-tool]`: confirm
   against the pinned documents (`docs/engines.md`,

   its 2024 edition": the results page supports mandatory in 2024; it
   does not say 2024 was the first year.
6. `tbl-seconds.md` changes on every run by design; decide whether it
   should be checked in or built.
7. The reading of the cyclic contradiction in `over-constraint`

8. Word count is under the budget (about 12,200 by `wc -w`, markup
